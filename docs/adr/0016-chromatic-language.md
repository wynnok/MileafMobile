# 语义色相与图标秩序：把单强调色换成「一动作色 + 六数据身份色」

- 日期 2026-11-19，状态 **accepted**。
- 用户当日指令（原文要点）：参考 `days-matter/days-matter-android` 的 UI/UX 设计理念优化行笺；只允许迁移「理念层」，禁止迁移「元素层」（页面结构、控件摆放、图标造型、配色数值、文案）；范围全量重构；**多彩配色，必须改变现在寡淡的配色，总体年轻化、活泼化、明亮化**；避免高饱和撞色/渐变滥用/霓虹感，浅深双模正文 ≥4.5:1；**按钮尽量配图标**，同一图标家族；统一 4/8pt 栅格；液态玻璃「合理」使用而非满屏；动效统一；**底部 Tab Bar 不改**；方案必须可拆到多个 Agent / 多个会话实施。
- 调研输入为只读审计两份（证据带 文件:行号 与逐像素实测）：`.dsh-tmp/research/reference-language.md`（参考 App 536 行）、`.dsh-tmp/research/current-system.md`（行笺现状）。
- 配套：[色彩与图标秩序规格](../specs/chromatic-language.md)（条款 CL01–CL48）、[Tickets 与多会话提示词](../specs/chromatic-language-tickets.md)（MC00–MC12）、[实施记录](../implementation/chromatic-language.md)。

## 背景

行笺的外观经过四代收敛：ADR 0006（电光蓝单强调色 + 去暖中性）、ADR 0011/0014（排版与 Apple 质感精修）、ADR 0015（从参考 App 迁移理念，并**加固**了「单强调色纪律」与「彩色面积 ≤20%」）。

上一轮 ADR 0015 的结论是「两者在理念层高度同构，不做推翻式重构」。本轮用户对同一参考 App 提出了**相反方向的判据**：当前界面「寡淡」，要求多彩、年轻、活泼、明亮。两者并不矛盾——ADR 0015 对齐的是**纪律**（彩色要有预算、状态要诚实、材质要三分），本轮要改的是**色彩数量**（1 个色相不够表达行笺的六类数据）。

审计给出两条关键事实：

1. 参考 App 的「不花」不是因为上色少，而是因为**面积与彩度成反比**：能看出颜色的像素只占 2–5%，鲜明彩度 ≤2%，而占屏 27% 的大面板把颜色压成 24–26% α 的洗色。行笺当前的「寡淡」正好相反：彩色面积与参考 App 相当（只有图表和极少数强调），但**全部集中在一个色相上**，于是既没有参考 App 的信息量，也没有它的辨识度。
2. 参考 App 的色相是**分寄存器**的：动作色只有 1 个，内容身份色 8 个但被关进 ≤46dp 的小件，中性色 15 个锁在同一色相（H=286°）。行笺可以照搬这个结构，把「内容身份色」从「条目类别」换成「数据域」——这对数据看板是更强的语义（里程永远是同一个色，跨页面下钻不用重新解码）。

因此本增量**不推翻** ADR 0015 的任何纪律，而是把「单强调色」升级为「一动作色 + 六数据身份色」，并把彩色预算从 20% 收紧到 5%/2% 的双预算——彩色变多的同时，花的风险反而下降。

## 提议决定

1. **D1 色相寄存器（取代 ADR 0006 的单强调色纪律）**：① 动作色仍是唯一的 azure（按钮、链接、选中、焦点环、开关）；② 新增 6 个**数据身份色相**，绑定数据域（journey/energy/efficiency/cost/climate/dwell），跨页面稳定；③ 状态色（warning/error）不入枚举；④ 参考 App 的「设置页七彩索引色」**不迁移**（设置/连接/地图保持中性）。
2. **D2 三级强度 + 明度锚定**：solid（图形，浅色 ≥3.55:1）/ strong（文字与实心，浅色 ≥5.90:1）/ soft·tint（16%/8% wash）；深色只有一档（对 #12161C ≥7.42:1）。六色相统一锚在 azure500/600/300 的实测对比度上，色相在 OKLCH 上取锚定 L 下 90–95% 可用彩度。azure 保留品牌现值，不参与解算。
3. **D3 彩色预算收紧**：非图表彩色面积 ≤5%（OKLab C>0.04）、高彩 ≤2%（C>0.12）；占屏 ≥10% 的面只允许 tint（≤8% alpha）；单页首屏可见数据色相 ≤3。取代 MG01 的 ≤20% 单口径。
4. **D4 图标：家族不变，只扩 4 个字形**（leaf / thermometer / speed / share），不引入第二套图标库。按用户指令给按钮补图标，但遵守参考 App 的纪律——**图标只复述按钮词义，不引入新概念**；动作图标取按钮前景色，身份图标取所属域色；同一动作在不同层级不得换图标。
5. **D5 栅格：不改刻度，改执行**。4 基准与 {4,8,12,16,20,24,32} 冻结；把「块 32 / 卡内 16 / 卡间 12 / 控件 8 / 基线 2–4」写成层级表，并新增裸数字守卫。半径不新增 token，只把归属写成表。
6. **D6 材质：玻璃只加两处**。浮层菜单与地图浮控改玻璃（与底栏同参数：22σ / 1.5 / 同一套叠色与受光边）；**弹层明确不叠玻璃**（背后已有 scrim，玻璃读不出层次，只剩性能开销）；内容层禁令继续。底栏冻结不改。
7. **D7 动效：三档时长 + 只加一条白名单**。新增 `settle` 240ms 管容器尺寸变化；「色相改变」复用既有 120ms 交叉淡化（M09 / PD13）。不引入弹簧（沿 D2 的旧裁定的同级理由：行笺的按压已由 pressScale + 120ms 承担）。禁止为上色本身做动画。

## 未采纳的备选

| 备选 | 否决理由 |
| --- | --- |
| 只提高现有 azure 的用量/彩度（不上多色） | 无法表达六类数据的身份；跨页面下钻时用户仍要读文字才知道在看什么 |
| 每个页面一个主色（page-tinted） | 「颜色=页面位置」与「颜色=数据身份」冲突，同一指标在两个页面会变色 |
| 参考 App 式的「条目类别色」 | 行笺的条目类别（行程/充电）就是数据域，但条目本身的颜色没信息量——颜色应跟随指标，不跟随列表行 |
| 墨色 Hero 主卡 + 分类洗色 | 沿 ADR 0015 D4 不迁移独立墨色材质；焦点卡改用 8% 语义 tint |
| 弹层也做玻璃 | 背后已 scrim 压暗，玻璃无层次收益；Android 低端机模糊开销明显 |
| 为按钮统一引用 Material Icons 补图标 | 会形成第二套图标家族（线宽/圆角/视觉重量都不一致），违反 CL10 |

## 后果

**正面**
- 跨页面语义稳定：里程、充电、费用、效率、环境、停放六个域各有固定色相，下钻专题时不需要重新解码。
- 「寡淡」被结构性解决，而不是靠加装饰：彩色来自数据本身（图表、指标图标、彩色读数），因此彩色越多、信息密度越高，而不是越花。
- 彩色预算从 20% 收紧到 5%/2%，并新增「大面只能 tint」——本轮之后**更难**出现满屏彩色。
- 对比度可核查：六色相 × 三级强度 × 四种底（canvas/surface/soft/canvas 合成）全部进守卫测试。

**负面 / 风险**
- **浅色下 amber 只能是金棕**（`#AA8215`）：明亮琥珀在 ≥3.55:1 的白底约束下物理上不存在。cost 域的「活泼」改由 wash 底 + strong 文字承担。已在规格 §10 记为 CL-偏差。
- 深色只有一档强度（solid=strong），语义上少一个层级——深色底上分两档会得到两个近似浅色。
- 彩色面积估算依赖逐页登记（CL06 是估算口径，不是像素自动统计）。逐像素统计的方法已在审计里跑通，但纳入 CI 需要一条渲染+计像素的守卫，成本高于本轮收益，留作候选。
- 六个色相在六条业务线上并行落地，任何一条线漏接都会造成「同一指标两个颜色」——因此 Tickets 按页分包，并在收尾波次做跨页一致性核对（MC12）。

**与既有决定的关系**：取代 ADR 0006 的单强调色纪律与 MG01 的 20% 口径；ADR 0015 其余 MG02/MG04/MG07/MG09 全部继续有效（MG02 补「状态不用数据色」，MG04 扩充 4 个字形，MG07 守卫扩到页面文件）。

**外部 gate**：真机材质与性能（#11/#16/#17）不因本增量关闭；本轮只做代码与自动化，不推送。
