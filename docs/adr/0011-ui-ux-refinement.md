# 以统一排版和任务层级推进整体 UI/UX 精修

- 日期为2026-11-12，状态为accepted。用户已确认设计文档更新范围及GitHub发布。
- 实施基线为main的2f8755c。代表页面视觉待验，产品实施待开始。
- 正式依据见[整体规格](../specs/ui-ux-refinement.md)、[实施任务](../specs/ui-ux-refinement-tickets.md)和[交付手册](../specs/ui-ux-refinement-delivery.md)。

## 背景与取舍

现有视觉系统已具备token分层和稳定的数据阅读行为。最新渲染呈现出小字号配大字距、主数字权重过强、记录和专题入口偏晚的问题。跨页面共享排版、图表和状态组件意味着此次调整有较高的迁移与回归成本，需要记录全局取舍及旧条款的适用范围。[现状审计](../product/ui-ux-refinement-audit.md)

决定以克制、精致、有秩序为设计方向。采用48/36/24主数角色、16正文、13标签、12辅助文字及普通文字零字距，通过任务优先级、对齐和有限表面组织页面。深底车况锚点用于概览，记录和专题入口按规格前置。光晕、导航模糊、整页入场及图表生长由即时完整内容和短时操作反馈替代。图轴、大字、触控与局部状态使用统一可验证规则。

保留电光蓝及中性底色、Inter与平台中文回退、四Tab、AC/DC构成环、电池弧和现有数据能力。单次费用补录、身份隔离、地图隐私及阅读恢复按既有业务契约验收。具体规则与逐页顺序集中在新规格R01–R10、S01–S08、P01–P16。

## 考虑过的选项与影响

逐页零散修补可减少单次改动，却会延续不同字阶、表面和操作节奏。全面更换品牌与布局语言会扩大识别和回归成本。此次选择沿既有品牌统一排版和任务层级，接受共享组件与全页面渲染复验的成本。

U01先在正式组件中形成代表候选并记录token差异，U02将确认后的改动收敛到共享系统。视觉参考由用户评审，行为通过App与可控HTTP验证，真实字体、地图、键盘、读屏和性能分别承载外部验收。
