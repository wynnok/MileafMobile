# 缺失充电费用补录：双入口、单表单与有限写入

- 日期：2026-11-04
- 状态：**accepted，2026-11-04 用户确认 ADR 并要求继续 Spec**。设计决定已接受，不表示代码已实施。
- 关系：继承 [ADR 0003「夜航」](0003-visual-direction-a.md) 的版式与 [ADR 0006「外观 v2」](0006-appearance-and-accent.md) 的配色、默认跟随系统；仅为缺失充电费用增加有限写入例外。既有视觉决定中“业务数据完全只读”的表述在此范围内修订，其他边界保留。

TeslaMate 的费用缺失会让车主无法完整回顾补能支出。采用列表与详情双入口、共用一个底部表单，让车主按本次单价补齐费用；延续现有数据阅读节奏，以明确的金额预览和提交结果承载这次有限写入。

## 已确认的决定

1. **双入口**：列表缺失费用旁增加入口，直接打开表单；详情费用位置也保留入口。列表整行继续进入详情，两个点击目标独立。
2. **沿用当前接口**：Server 0.4.0 及以上显示符合条件的入口；提交返回 403 时保留输入，提示“站点尚未开启费用补录，请联系管理员”。不通过写请求探测能力，不要求本次增加后端能力字段。
3. **未知币种允许补录**：提示按 TeslaMate 原账本币种填写，不默认人民币；本机币种偏好仅用于显示，不能证明账本实际币种。

| 后端已实现补录，但 `/meta` 未声明开关是否开启 | 只读参考 [charging_cost.py](../../MileafServer/src/mileaf/charging_cost.py)、[meta.py](../../MileafServer/src/mileaf/meta.py)；版本支持不等于站点已启用写入 |

契约来源为后端 [OpenAPI 0.4.0](../../MileafServer/docs/api/openapi-0.4.0.json) 和 [有限写入 ADR](../../MileafServer/docs/adr/0004-limited-charging-cost-writes.md)。后端会话记录的本地提交为 `63ad86a`，未推送，真实数据库集成验证待完成；不能据此声称用户部署已经可用。

- `PATCH /v1/charging-sessions/{session_id}/cost`，沿用现有 Bearer 鉴权，JSON 请求仅含 `unit_price`，客户端按十进制字符串发送，如 `{"unit_price":"1.250000"}`。
- 单价范围 0–999999，最多 6 位小数、12 位总数字。0 是明确免费，空输入是未填写。
- 仅允许已结束、`cost == null`、计费电量有效的记录；已有费用（含 0）不能覆盖。不保存单价，不设置地点价格或默认价格。
- 计费电量为 `energy_added_kwh` 与 `energy_used_kwh` 的较大可用值，必须大于 0 且小于 1,000,000 kWh；两者分别记录，不相加。
- 服务端将计费电量乘单价，费用四舍五入为两位小数；返回 `session_id` 以及十进制字符串 `unit_price`、`billing_energy_kwh`、`cost`。
- 403 为未开启，404 为记录不存在，409 为已有费用或不符合计费条件，400/422 为参数问题，503 可表示数据库授权不可用或超时。服务端原子更新避免并发覆盖；重复提交可能返回 409。

## 已接受的设计决定

### D1 入口采用低强调文字动作，费用语义保持准确

列表费用行使用“费用 —”与 `补录费用` 文字动作；详情在费用读数附近使用同名动作。动作采用 `accentStrong`，不放实心蓝按钮、不添加警告徽章，不让多条缺失记录形成一串醒目的彩色卡片。触控区域至少 44×44，视觉文字仍沿用当前正文层级；窄屏或大字时动作换行，不挤压费用读数。

只有已知版本支持、费用缺失、已结束且电量满足条件时才显示动作。未知/旧版本不显示；已有费用含 0 不显示。页面仍区分缺失、免费和进行中，不把“没有入口”解释成免费。更深层的数据库列权限无法由版本判断，按已确认的 403/503 反馈处理。

从任一入口打开后，先读取最新详情并验证记录 ID、车辆 ID、会话及站点身份，再允许输入和提交；加载或读取失败时在原弹层中显示状态与重试。这样列表摘要缺少车辆归属字段、或费用已由另一客户端补齐时，也不会直接拿旧摘要提交。

### D2 单一底部表单，层级为“本次充电 → 单价 → 预估费用 → 确认补录”

表单标题为“补录费用”。顶部用地点与本次充电时间确认操作对象；主体只有一个可编辑字段“充电单价”，其余均为只读。展示计费电量和实时预估总费用，让车主在提交前看见计算结果。

阅读顺序：

1. 本次充电的地点与时间，避免把当前车辆或另一条记录当成操作对象。
2. 单价输入与币种/kWh 单位；未知币种明确显示“账本币种 / kWh”并提示“请按 TeslaMate 原账本币种填写”。已配置币种时同样说明币种标签来自本机偏好。
3. “预估费用”主数与计费电量；解释“按两类电量的较大可用值计费”，不把当前单价称为平均单价，也不默认取“充入电池”数值。
4. 按钮前正文说明“仅补录本次充电。保存后无法在 App 中修改；单价不会设为默认值。”
5. 一个主按钮“确认补录”；免费单价 0 时明确写“将记录为免费充电”，不把空白输入转为 0。

提交前信息在同一表单内完整可见，不叠加第二个确认弹窗。预估费用明确为参考值，最终费用以服务端返回为准；不保存草稿或记忆上次单价，避免产生“已设置默认电价”的错觉。关闭表单后丢弃本次输入。

### D3 视觉继承外观 v2，表单只增加一个金额重点

继续使用现有 primitive → semantic → component 分层；**不新增色板、字号阶梯、阴影等级或圆角档位**。列表和详情保留原锚点，弹层以预估金额为唯一较大数字，不在表单内再嵌一个深色 hero。

| 元素 | 继承方式与取舍 |
| --- | --- |
| 弹层材质 | `MileafSheetFrame` + `bottomSheetTheme`：surface、顶部 20 圆角、现有遮罩、36×4 把手；不另加渐变、描边卡片或悬浮阴影 |
| 排版 | 标题沿用 `type.title`；单价输入沿用 `type.title`；预估金额使用 `type.metricMd`；说明与错误用 `type.body`，补充身份用现有次级文字样式；关键风险说明不使用 micro 小字 |
| 内边距 | 沿用 `MileafLayout.pageInset` 的 20/24；内容按 8/12/16/20/28 现有档位组织，不以散落的裸值调整页面 |
| 输入 | 复用 `InputDecorationTheme` 的 12 圆角、16×12 内边距、focusRing 与 error 语义；单价没有默认值，十进制键盘仅辅助输入，粘贴仍需完整校验 |
| 操作 | 入口用 ghost 层级；提交复用 `MileafButton` 主按钮、10 圆角、至少 44 高、loading 保留文案；用字形和文案表达状态，颜色不单独承担含义 |
| 动效 | 沿用现有弹层路由与 `MileafDurations`，不增加成功庆祝、数字翻滚或光效；遵循减少动态效果偏好 |

使用逻辑像素，跟随系统浅深模式与字体缩放；表单受现有 `sheetMax` 约束，键盘出现后内容可滚动且提交动作可达，200% 下文本与输入区域可增长。具体间距图、状态图、断点值与像素验收矩阵在下一份 Spec 锁定，本 ADR 不充当渲染验收证据。

### D4 单次显式提交，异常不丢输入、不伪报成功

提交前再检查当前会话、站点、车辆和本次详情状态。请求发送期间禁用重复提交和表单编辑，阻止普通关闭/拖拽造成误以为取消；会话到期或切换站点/车辆时应退出旧操作上下文。HTTP 请求发送后无法通过关闭 UI 撤销，旧响应不得更新新车辆页面。

| 结果 | 用户体验 |
| --- | --- |
| 200 且返回格式及记录身份正确 | 显示服务端最终费用，关闭表单，简短提示“费用已补录”；刷新发起页面及受影响数据 |
| 403 | 保留输入，提示已确认的“站点尚未开启费用补录，请联系管理员”；不循环自动提交 |
| 400/422 | 保留输入，在单价附近提示校验问题；不直接显示后端英文或响应体 |
| 404 | 提示“该充电记录已不可用”，停止补录并允许关闭、刷新列表 |
| 409 | 重新获取详情；已有费用则展示最新费用并结束编辑，不声称本次请求成功；仍无法计费则说明条件不满足，不提供覆盖操作 |
| 401/会话失效 | 复用现有登录失效处理，移除旧会话下的表单与输入 |
| 超时、连接中断、5xx、200 响应无法解析 | 保留输入并说明结果未确认，先提供“查询最新结果”；禁止自动重发 PATCH，不能直接判定“保存失败” |

未知结果的查询若失败，继续保持待确认。读到已有费用只表示该记录现在有费用；接口不存单价、没有写入来源，不能反推由本次输入产生。读到费用仍缺失后，可由用户主动重新提交；多实例缓存 TTL 可能造成短暂旧读，服务端原子条件仍负责防止覆盖。

### D5 刷新真实数据，维持站点与车辆隔离

成功后使当前授权范围内相关业务快照失效，并通知已挂载页面刷新：详情、充电列表/费用汇总/趋势/地点摘要、概览及统计中受费用影响的数据。失效须涵盖在途 GET，避免旧响应回写；仅清缓存并不足以更新页面已经持有的结果。

若写入已经确认、随后刷新失败，仍应报告费用补录成功，同时说明汇总暂未更新，保留原快照及手动刷新入口。不能把服务端写入成功回退成失败，也不能凭本地估算改写整个统计图表。保持当前列表筛选与滚动上下文；“费用未知”筛选下，补齐后的记录随刷新自然移出结果。

新增小范围费用补录模块（拟落点 `lib/src/charging_cost.dart`）统一表单、校验、写请求和结果；两入口复用该模块。`SessionController` 增加受控 PATCH 支持并保留现有 GET 默认行为，继续使用 `MileafApi` 的超时、HTTP 信任、禁止重定向策略以及现有会话失效处理。无需新增全局状态框架或改造全部 API。

## 考虑过的替代方案

- **仅详情入口**：最少视觉增量，但连续补录需反复进入详情；用户已选择列表也直接打开表单。
- **列表内直接输入单价**：会把补能回顾变成编辑表格，键盘、行高及滚动冲突显著；使用按需弹层保留阅读节奏。
- **先新增后端写入能力声明**：可提前隐藏未启用入口，但阻塞当前已实现接口接入；用户已选择现有契约及明确的 403 反馈。
- **强制配置币种、默认人民币或记忆上次单价**：显示偏好无法验证真实账本，后两者还可能导致误录；用户已允许未知币种并明确提醒原账本口径。
- **允许修改已有费用、批量补齐或设置默认电价**：超出唯一写接口的约束，需要另行设计与后端能力，不纳入本次。
