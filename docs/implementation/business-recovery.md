# 业务请求恢复与并发缓存

所有业务 GET 继续复用唯一 HTTP 客户端和授权代次缓存。429 的 `Retry-After` 支持非负秒数和 HTTP-date；等待期限仅在当前内存会话保留，期限内不发新的业务网络请求，有效缓存仍可读取。没有有效 header 时不臆造等待时间；没有后台重试，期限过后仍由用户手动恢复。退出、换站或会话失效清除该状态；同会话跨日或换时区只清除查询快照，仍遵守等待期限。

同一查询存在并发请求时，以最近发起者为准；迟到响应无权写缓存、限流期限或触发无缓存体的 304 补请求。日历清缓存也使旧请求失去缓存写权限。页面自身仍隔离车辆、会话和页面请求代次。

App/HTTP 回归验证：秒数及 HTTP-date 429 保留 68% 电量快照；期限内点击刷新不新增请求，时间推进不自动重试，期限后手动恢复。前后台产生同查询并发时，后发 21% 先返回、先发 68% 后返回，导航离开再返回仍为 21%，且不产生额外网络读取。

这些是受控响应自动化证据，不代替双端真实网络、站点和设备验收。
