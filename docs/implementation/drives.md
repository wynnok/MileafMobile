# Ticket #9：行程筛选与游标分页

## 当前行为

行程入口独立 DrivesPage 通过当前会话的 BusinessCache 读取 DrivePage：列表按照响应顺序展示时间、display_name（缺失/空白回退未知地点）、距离、时长和净电耗；ended_at=null 明示进行中，未知数值与真实零分开。点击记录调用 onRecord(id)，交给后续详情票接入；本票不伪装已有详情、地图或曲线。

默认近30个本地日历日，用户可输入含首尾日期的自定义区间；以 CalendarContext 的 IANA 日历零点转换成 UTC 半开范围，历史结束取次日零点、今日截当前时刻，不套用统计730日限制。午夜尚无可查询时段或切时区后选定日期落在未来时明确提示且不发送非法范围。前台换日/IANA时保留自定义日历日期后重算，默认窗口重新计算。

limit=20，cursor原样回传不解码。按ID去重且保留服务端顺序，同开始时间不被误去重。用户向下滚动接近底部或点击加载更多读取下一页；在途翻页被抑制。翻页失败保留列表和局部重试，重复非空游标提示异常而不假装到底，避免自动循环。筛选、刷新与换车重置分页；刷新失败保留原快照。每次读取同时校验页面存活、请求序号、会话对象和车辆归属；参数变化递增序号。ETag、304、no-store和缺体恢复沿用既有完整查询键缓存。

已确认的测试边界是完整App操作+可控HTTP。首先用真实fixture测试观察行程tab无数据的红灯，再实现DTO与真实列表绿灯；后续验证翻页失败恢复/去重、304刷新清掉后续页、进行中和null/0、跨DST及早于730日的筛选、前台时区/日期变化、切车迟到、360宽200%字体、非法数组兼容错误及刷新失败快照。此工作树完整行为测试59项通过，分析通过后提交。
