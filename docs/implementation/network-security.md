# T02 安全网络候选实现（GitHub #3）

## 已实现的行为

- 所有站点请求通过同一 `MileafApi` 请求入口；无自动重定向（含同源跳转），无自动重试，无 HTTPS 失败降级。健康检查采用该入口；认证切片必须继承它，不另建绕过策略的客户端。
- HTTPS 使用 Dart `HttpClient` 的默认信任与主机名检查，5 秒建立连接时限、15 秒包含响应头/体的总时限及中止机制。未设置忽略证书回调，未修改系统证书信任。
- HTTP 默认连健康检查也阻止。用户看到明文口令/token/车辆数据风险和确切站点身份后，主动勾选可信私网/VPN。App 不推断或证明 VPN 安全。
- 授权身份包含规范化协议、主机、有效端口与反代路径前缀；尾部斜杠与重复 API 前缀按连接规则统一。其他身份不继承授权。勾选可撤销，普通偏好仅保存本站点授权，不保存凭据；使用锁定的官方 shared_preferences 2.5.6 Async API。读授权失败时阻止联网，不将存储错误误称为已授权。
- iOS 声明局域网用途；网络失败提示系统设置中检查局域网权限、返回后手动重试，或使用仍可访问的 HTTPS 站点。不扫描设备、不请求 GPS。
- 不添加 `NSAllowsArbitraryLoads`、全局 Android 明文放行或测试 CA。Dart-owned sockets 与原生栈策略不同，不能依赖 manifest/ATS 替代 App 站点授权。参见 [Flutter 官方说明](https://docs.flutter.dev/release/breaking-changes/network-policy-ios-android)；该页面是历史变更记录，当前版本仍需真机验证。

## 自动化与构建证据

2026-10-22：通过约定的完整 App + 可控 HTTP 主边界，测试精确站点授权、未授权无请求、授权恢复/撤销、跳转拒绝、局域网错误后恢复、证书错误提示和既有健康/超时/可访问性行为。偏好存储采用可替换的系统边界；App 重建恢复测试证明授权行为，**不等于设备磁盘跨进程持久化已验收**。

工具链仍按 T01 固定版本；构建只用项目 wrapper。Flutter 的 iOS 构建以及 Android 的 Flutter 子任务可能改写 `local.properties` 到既有全局 SDK 设置；每次入口重写项目 SDK 和顺序构建仍不能阻止 Flutter 子进程再次改写该文件，现有 wrapper 的隔离方案尚未解决；停止进一步 native 构建试错，待根因级隔离方案确认。曾因并发覆盖导致 Android CMake 定位失败，未向主机安装 CMake；曾顺序重跑 Android release 成功（155 tasks，2m12s），iOS release 无签名构建成功（16.5MB）；这些仅证明候选编译成功，不证明工具链隔离完整，也不是已安装或设备网络验收。shared_preferences Android 插件需要 platform35，已仅在项目 SDK 内补齐，主工程仍 compile/target36、最低24。

最终源码已有 16 个 App 行为测试、格式检查及静态分析通过。最后一次 Android 增量构建按协调要求中止，不以它作为验收证据；项目 local.properties 已恢复为项目 SDK。
