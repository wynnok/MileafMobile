# 行程详情「对照电量」与「驾驶与环境」重排实施记录

2026-11-16 在 `main` 工作区完成（基线 `7b1ca30`，本地提交，未推送）。条款依据 [焕新规格](../specs/apple-design-renewal.md) R11（共用起始线、一处一个分组方式、平台命中尺寸）、R12（`body` 17 与 `label` 14 的角色分工、单位随基线 4）、R16 M06（折叠箭头 160ms `easeOutCubic`，减动效 0）与 [ADR 0012](../adr/0012-apple-design-renewal.md)。没有新增颜色、字号、圆角或时长 token。

## 1 问题

用户指出两处（截图红框）：

1. **`对照电量`**：①不与其他元素对齐——它当时是 `Align(centerLeft)` 里的 `TextButton`，Material 的行内边距把 17 号标签推进去 16，与上方 `速度数据说明`／`采样数据说明` 的 0 起算线错开；②可读性差——纯蓝文字动作夹在两条灰色说明与两枚蓝色「前/后一个采样」之间，既像链接又像脚注，读者看不出它是「给这张图再加一条曲线」的开关。
2. **`驾驶与环境`**：五条 `Text` 各写一句「字段名 + 空格 + 值 + 单位」，17/25、同色同重、无分隔、无对齐。字段名恰好都是四字，值却从不同 x 起笔；整块读起来是一段正文而不是一组事实，扫读时找不到列。

## 3 版式

### 3.1 对照电量：从「蓝色文本按钮」变成「图表动作行」

```
速度过程   点按图形读值
[过程图]
16:05 · 速度读数 60 km/h
km/h                        前一个采样  后一个采样
──────────────────────────────────────────────  1px line
对照电量                                        ⌄   17/500 text
与速度过程同屏                                  12 textMuted
（展开）电量过程   点按图形读值 → 图 → 读数 → 电量数据说明
```

- **对齐**：折叠行的标签与说明都从内容左沿起算，因此与 `速度数据说明`、`采样数据说明`、`速度过程`、`驾驶与环境` 首列落在同一条竖线上；测试直接比较这几个 `Text` 的 `left`。
- **可读性**：标签从「蓝色动作」改成正文色的 17/500——它不是链接，是本区块的第二个动作；下面加一行 12 号说明，在读之前就说清「同屏对照什么」，按下之前不必猜。灰蓝两色不再抢同一层的注意力。文案仍是「动词 + 对象」（R12），没有为了与章节标题同构而改成名词短语。
- **层级**：1px 顶线把它与「图表 + 数据说明」分开，形成「图 → 说明 → 追加动作」三段，而不是三条同重的灰字里夹一条蓝字。
- **动效**：箭头 160ms `easeOutCubic` 从朝下转到朝上；内容用 `AnimatedSize` 以同一时长在**原位**长出来（不跳页、不弹层）；减动效时两者都是 0ms，内容仍即时可达。R16 M06 写的是「内容自然重排」、旧文「禁止自写高度 Tween」：这里不手写 Tween，用的是框架的 `AnimatedSize`（高度按实际布局插值），与 R16 的「操作驱动、可打断」一致；这一条与旧文措辞的差异在此登记。

### 3.2 驾驶与环境：从「一段正文」变成「一张表」

```
驾驶与环境
平均速度                              10 km/h
──────────────────────────────────
最高速度                              90 km/h
──────────────────────────────────
车外均温                             15.0  °C
──────────────────────────────────
车内均温                             21.0  °C
──────────────────────────────────
最大功率                              120  kW
```

| 角色 | 取值 | 理由 |
| --- | --- | --- |
| 字段名 | `label` 14/20 500，`textMuted` | R12 把「字段名」定为 `label`；它不再和值挤在同一句里 |
| 值 | `body` 17/25 500，`text` | 事实的内容，比字段名大一档、实一档，是全表唯一的重点 |
| 单位 | `label` 14 `textFaint`，定宽列内靠右 | R12「单位沿基线间隔 4」；定宽列让数字右边缘成一条竖线 |
| 分隔 | 行间 1px `line`，首行无顶线、末行不封口 | R11「记录用行与细分隔」；不封口 = 一组行，不是卡片 |

**为什么值靠右。** 同一屏上方的电量区间已经用「出发 76% / 到达 68%」占住了左右两条边；事实表的值列靠右后与 `到达 68%` 共用同一条右线，字段名与标题共用同一条左线，两个元素因此不必加任何外框就属于同一套网格。这不是装饰，是这一块「秩序感」的来源。

**为什么单位要定宽列。** 直接把「值 + 单位」当一段右对齐，`10 km/h` 与 `120 kW` 的数字右边缘会随单位宽度左右浮动 10px，五行扫下来像一条毛边。单位列宽取本表最长单位的实测宽度后，数字落在一条竖线上，单位右边缘仍与页面右线齐平，两个方向都不毛。

**大字**：`largeText`（`scale(14) ≥ 21`）时改为字段名在上、值在下，单位随值同行，不缩字号、不横向溢出；行分隔照旧，读起来仍是同一张表。这一档放弃「值靠右的两条竖线」，换成可读性——150% 就已经切换，见 `after-facts-*-360-150`。

**动作行与脚注行是两档，不是两套规则。** 表末的 `更多行程指标` 原来与字段名同色同号，紧贴最后一行，读成「第六行事实」；它和 `对照电量` 一样是会改变内容的结构动作，因此同档处理：17/500 正文色 + 12 号说明 + 1px 顶线（顺带给表封口）。三条 `*数据说明` 是脚注，保持 17/400 `textMuted`、无分隔线。

## 4 语义与状态

- 折叠行读成一个按钮：`Semantics(button: true, expanded: …)`，标签为「对照电量」，说明作为 `hint`，点击只产生一个节点（`InkWell.excludeFromSemantics`）。
- 事实表每行 `Semantics(container: true, excludeSemantics: true, label: '字段名 值 单位')`，读成「平均速度 10 km/h」「车内均温 21.0 °C」；缺失读成「平均速度 —」，不带单位、不读成零。
- 收起时子内容不构建：屏幕阅读器不会读到未展开的第二张图，首帧也没有隐藏的重图表成本。
- **展开态挂在页面上**（`batteryPaired`），不放在组件 State 里：该行在切到「电量」指标时会被 `if (metric != 1)` 卸载，状态一旦随组件销毁，切回速度就会静默收起第二张图。组件同时支持受控（`expanded`）与自持两种用法，本页用受控。
- 焦点环沿用 `MileafFocusRing`（2px `focusRing`）。外层 `Focus` 只作焦点环锚点（`canRequestFocus: false`），Tab 停靠点仍只有 `InkWell` 一个；键盘 Tab 到本行后回车即可展开，测试同时断言了焦点锚点不可取焦、焦点环为 `focusRing`、回车改变内容。

### 登记的两处偏离

| 条款 | 偏离 | 理由 |
| --- | --- | --- |
| R13「关键状态具有文字」 | 展开/收起只由箭头方向与内容出现表达，没有第二个状态词 | 本页原有四条折叠行（换皮前是 `ExpansionTile`）一直如此；只给其中一条加状态词会让同页出现两种折叠语言。状态另有 `Semantics(expanded:)` 供读屏 |
| R11「行内 4/8/12」 | 标签与说明之间用 `inline2`（2） | `MileafDataRow`、`MetricBlock` 的 title→meta 间隙同为 2；同一页若用 4 会让两行说明比同站其他行松 |

## 5 对照度

浅色：字段名 `textMuted` 在 canvas 上 **5.38:1**，值 `text` **17.1:1**，单位 `textFaint` **4.65:1**。深色：**7.87 / 17.87 / 5.59:1**。行分隔线是装饰线（1.23:1），不承担控件边界，行与行的区分同时由 12 上下内边距与字号差承担；这也与 `MileafDataRow`、`MetricGrid` 的既有分隔线一致。没有新造色值。

## 6 设计迭代（保留判断过程）

1. **先试「做成开关」**。在行右端画一枚 40×24 的开关，状态最直白；但全 App 没有开关语言，为一行引入新控件，与「不冲突、和谐」冲突。改用本页已有的折叠语言（箭头 + 就地展开），并让它比脚注行更实一档来区分层级。
2. **再试「做成次级按钮」**。48 高的描边按钮在图表下方会变成第二块实心面，压过图本身；否决。
3. **试过把入口移到图表上方**（`headerTrailing`）。图表头部已有标题与副标题，320 宽再加一枚控件会换行，且折叠展开的内容会被挤到头部下方，读起来像换了一张图。留在图下、以 1px 顶线切分。
4. **试过用 2×2 事实卡**（复用 `StatisticsTopicFacts`）。五条事实在 2 列里会空一格，为了凑偶还要合并「车外/车内」，等于用版式改造数据；改为整表 5 行。
5. **第一版值没有单位列**：`10 km/h` 与 `120 kW` 的数字右边缘差 10px（见 `before-facts-*` 与首轮 `after`）。加定宽单位列后数字成一条竖线；单位起初在列内左对齐，结果表格右边缘又出现毛边，最终改为列内右对齐，两个方向同时对齐。
6. **箭头起初在整行垂直居中**，两行标签时落到两行之间；改为按标签首行行高（含 `TextScaler`）居中。
7. **试过把 `对照电量` 改名 `电量对照`**（与章节标题同为名词短语），审查指出这违反 R12「界面文案采用动词与对象」，且全页只有它一处是动词短语动作；改回 `对照电量`，层级由字重、颜色与顶线承担，不靠改名。
8. **动作行与脚注行起初混在一个层级**：第一版只让 `对照电量` 变实，表末的 `更多行程指标` 仍是灰字 17，紧贴事实表读成第六行。改成两条动作行同档（`emphasis` + `topLine` + `meta`），三条数据说明保持脚注档。
9. **展开态一度放进了组件 State**：切到「电量」指标时该行被卸载，切回速度会静默收起第二张图；改为页面持有 `batteryPaired`，组件同时支持受控用法。
