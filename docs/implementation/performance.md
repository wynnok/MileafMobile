# Ticket #16：性能采集准备与未测状态

当前只有本地候选端点和复现协议。没有 Android/iPhone 实测样本，没有 p50/p95 或达标结论；Ticket #16 保持外部验收待验。App/HTTP 行为测试不是计时证据，现有后端 ASGI 性能测试也不是 App 端到端证据。本轮没有运行设备、改变设备执行保护、启动全局 Docker/OrbStack，或写真实数据库。

## 本地标记及精度边界

使用既有项目工具链构建 profile（协议也允许 release），仅在本地测量构建添加 `--dart-define=MILEAF_PERFORMANCE_TRACE=true`。常规构建默认关闭。定义只启用应用标记，不自动开启 VM Timeline stream；采集前验证实际 trace 中存在对应事件。当前冻结 Dart SDK 的 Timeline.instantSync 在 Timeline/Dart stream 未启用时不会发出事件；release 中不能假定 DevTools/VM 时间线可用，缺标记必须按采集失败处理，或另行验证 OS 级端点，不用零代替。

Android 的项目构建命令形态为 `tool/flutterw build apk --profile --dart-define=MILEAF_PERFORMANCE_TRACE=true`；iOS 为 `tool/flutterw build ios --profile --no-codesign --dart-define=MILEAF_PERFORMANCE_TRACE=true`。依旧需要已有项目 SDK、外层沙箱与构建前探针；这里没有执行这些命令。签名/安装/设备执行仍遵循另行验证的流程，不使用裸 flutter 或跳过入口的方式绕过当前 run/install/drive 保护。

事件仅含固定名称 `mileaf.<enum name>` 与可选进程内递增 trial 序号，不接受 URL、车辆/记录 ID、口令、token、坐标、响应体或自由文本，不上传、不加遥测 SDK、不写日志文件或网络服务。

| 事件 | 事实与用途 | 不得据此声称 |
| --- | --- | --- |
| dartEntry | Dart main 入口诊断分段 | OS 进程启动；冷启动总耗时 |
| overviewFrameworkReady | 本进程首次当前会话 summary 成功且交互加载结束后，对应 framework post-frame 候选 | raster 完成、屏幕 present 或冷启动验收通过 |
| resume / warmOverviewFrameworkReady | 已读过概览后前台恢复；已有当前概览快照的 framework 帧候选。刷新独立继续，不等待 HTTP | 仅以恢复回调或缓存命中当作实际可见首帧 |
| driveClick | 用户从列表/概览点击行程的处理入口，生成 trial | 原始触摸硬件时间 |
| driveMetricsAvailable / driveSeriesAvailable | 当前车辆正确资源分别成功解码；默认请求字段与 200 点参数未改变 | 两个 HTTP 时间的和等于端到端时间 |
| driveFrameworkReady | 同一 trial 明细与默认速度序列均成功、无局部错误后，当前路由的 framework 帧候选 | 底图首图；lazy/offscreen 曲线已显示；raster/present 已完成 |
| overviewFailed / driveFailed | 当前有效请求失败；可辨识一次 trial 内的失败经历 | 静默剔除失败后重新计数 |
| mapRequest / mapFirstTileDecoded / mapFailed | 地图每次加载的开始、首张真实瓦片成功解码候选与失败 hook | 单张解码即完整视口可见；失败透明底片等于首图 |

post-frame 回调位于 framework 帧尾，不是 GPU/OS 呈现完成。正式样本必须将候选事件关联到其 Flutter frame、raster 完成及 OS 实际 present；DevTools 用于定位，Android 使用已有系统 trace（如 Perfetto），iOS 使用已有 Instruments/系统呈现证据。两端都先证明所用工具能够捕获所需起终点、采用同一时钟或有可验证时钟映射，再采样。不能直接相减未经对齐的 OS 时间与 Dart Timeline 时间戳。无法对齐的样本标为采集失败，不换用 Dart main 缩短冷启动。

行程详情默认曲线可能位于纵向滚动区域。数据已可供构建不保证曲线已在当前视口绘制；必须以录屏/帧证据核查主要指标和默认曲线的实际可读状态。若固定验收视口无法在初始交互帧呈现目标，就记录该限制及真实可达路径，不能将本候选标记包装成满足预算。测量过程需要额外用户滚动或修复操作时不能混入“点击到默认可读”成功样本。

地图 hook 单独配对：地图实例接受展示后 start(mapRequest)，每加载代次首次真正 HTTP 成功并 decode 完成时 mark(mapFirstTileDecoded, trial: ...)，失败 mark(mapFailed, trial: ...)；透明降级图片绝不发成功事件。该边界由地图切片接入；实际首图仍取对应瓦片在正确视口呈现的证据。地图未获同意、瓦片错误、网络失败均不算成功首图。底图失败时指标/默认曲线继续可读，恢复行为另验。

## 数据准备门槛

只读核验当前后端 `tests/fixtures/performance.py` 与夹具说明：种子27、专用车下 **20,000行程、200,000位置点、5,000充电会话**，包含一个20,000源点行程。它不能满足本 Spec 的50,000/500,000目标。当前移动端固定 HTTP 样本中的24点序列也只是契约回归，不是200点性能数据。

后续在项目内独立工作目录与独立临时 PostgreSQL 环境准备扩大合成集，不修改 MileafServer/、teslamate/ 只读参考或真实用户库。固定源提交与schema，复制现有确定性生成思路到隔离数据准备任务，扩大行程/位置点数且保持行程和起终点外键有效；保留一个足够密集的固定详情资源以验证默认200点降采样，以及足以20条游标多页的充电。必须记录生成输入、资源别名、数据摘要与数据库只读计数核验后才开测；数据生成与容器启动不计入用户操作时间。

本轮未生成扩大数据集或启动容器；当前环境没有满足该规模的已验证运行站点。扩大生成器与服务启动是待具备隔离环境后的前置工作，不能靠更改报告中的计数获得通过。若临时数据需要销毁，先按相应授权流程清理，不能指向既有数据库。

## 每次测量

1. 两端分别为下列四类指标准备至少30次独立试次。先做不计入正式批次的工具校准，冻结后不再改变设备/资源/缓存定义。每次试次从开始便登记，超时、崩溃、登录失效、读取错误、采集缺失和需要人工修复都保留为失败，不自动重跑覆盖原记录。
2. **已登录冷启动**：保持有效安全存储凭据，确认目标进程不存在；系统 trace 开始后从 OS 实际进程创建开始，到当前车辆概览关键内容可读可交互的首个实际呈现帧结束。包含安全存储、vehicles 和必要 summary；不含人输入/首次权限弹窗。缺少进程创建起点或实际呈现终点时不计算有效 duration。预算 p95≤2000ms。
3. **同会话热恢复**：先确认当前车概览已可读、同进程同会话内存仍在，固定后台间隔（例如10秒，批次前声明）后恢复前台。起点是 OS 前台恢复，终点是已有概览首次可读可交互实际呈现帧，刷新异步进行；不等刷新HTTP、不把进程被杀、换日/时区变化或会话过期混入此定义。预算 p95≤800ms。恢复遇到这些情况仍登记试次失败或独立条件组，不冒充热成功。
4. **行程详情**：每次从固定同车同资源的实际点击开始，捕获明细和默认200点速度曲线均可读的实际呈现帧。默认按无该详情内存缓存的条件测量，已授权返回/重新登录准备工作在试次开始前完成；若要测热详情须另组。底图独立，不等地图来结束详情计时；网络或曲线失败也不以只有明细当成功。预算 p95≤1500ms。
5. **底图首图**：固定地图资源、可见区域与缓存条件，以该实例开始展示底图到至少首张正确瓦片在正确视口实际呈现计时；同时记录成功率、失败降级是否保留指标/曲线/地点文字。单张decode事件仅为候选关联点。中国大陆验收网络与两端供应商可用性仍按地图票验证；没有首图预算承诺，但必须报告耗时分布与成功率。
6. 同一试次只配对同一进程/同一trial的事件，不把一次失败的开始与下一次成功的终点相减。超时阈值在开测前统一声明（例如30秒），不根据结果调整。若 Timeline 丢事件或trace断档，保留为采集失败；不要拿 HTTP elapsed、Dart入口或视频手工估计替代未捕获端点。

## 报告与判定

使用公开的 nearest-rank 定义：将每个指标/平台批次的全部 N 个试次按耗时排序，失败视为未完成（+∞），p50取第ceil(0.50×N)项、p95取第ceil(0.95×N)项。该秩落在失败项时写“未完成”，不写数值。可另列成功样本的条件分位数帮助定位，但它不能替代全部试次分位数或掩盖失败。

报告必须保留 N、成功数、失败数/类型、p50、p95、成功率、条件、原始试次证据指针和起终点定义。至少30独立试次是每指标每平台的门槛，不是两端合并30；缺条件、缺采样或尚有未解释失败时结论为待验，不单凭成功子集p95称通过。原始 trace/录屏仅留项目本地 `.cache/performance/` 等忽略目录，公开报告只用合成资源别名；确认没有凭据、完整响应、坐标或真实站点URL后再共享。不要提交DevTools可能额外采集的业务日志。
