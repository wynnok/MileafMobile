post-frame 回调位于 framework 帧尾，不是 GPU/OS 呈现完成。正式样本必须将候选事件关联到其 Flutter frame、raster 完成及 OS 实际 present；DevTools 用于定位，Android 使用已有系统 trace（如 Perfetto），iOS 使用已有 Instruments/系统呈现证据。两端都先证明所用工具能够捕获所需起终点、采用同一时钟或有可验证时钟映射，再采样。不能直接相减未经对齐的 OS 时间与 Dart Timeline 时间戳。无法对齐的样本标为采集失败，不换用 Dart main 缩短冷启动。

行程详情现将主要指标与默认曲线放在次要字段和地图之前。App/HTTP 回归确认 360×800、正常字体下主要指标与完整默认图形位于初始视口，200% 字体下全字段与图表可纵向阅读。该几何检查不是设备呈现或性能证据；数据已可供构建不保证目标设备的曲线已在当前视口绘制，仍必须以录屏/帧证据核查主要指标和默认曲线的实际可读状态。若固定验收视口无法在初始交互帧呈现目标，就记录该限制及真实可达路径，不能将本候选标记包装成满足预算。测量过程需要额外用户滚动或修复操作时不能混入“点击到默认可读”成功样本。

地图 hook 单独配对：地图实例接受展示后 start(mapRequest)，每加载代次首次真正 HTTP 成功并 decode 完成时 mark(mapFirstTileDecoded, trial: ...)，失败 mark(mapFailed, trial: ...)；透明降级图片绝不发成功事件。现已接入 CandidateMap 的加载代次和成功 decode 专用回调，每代仅首个成功瓦片发一次事件；实际首图仍取对应瓦片在正确视口呈现的证据。地图未获同意、瓦片错误、网络失败均不算成功首图。底图失败时指标/默认曲线继续可读，恢复行为另验。

## 每次测量

1. 两端分别为下列四类指标准备至少30次独立试次。先做不计入正式批次的工具校准，冻结后不再改变设备/资源/缓存定义。每次试次从开始便登记，超时、崩溃、登录失效、读取错误、采集缺失和需要人工修复都保留为失败，不自动重跑覆盖原记录。
2. **已登录冷启动**：保持有效安全存储凭据，确认目标进程不存在；系统 trace 开始后从 OS 实际进程创建开始，到当前车辆概览关键内容与主趋势实际可读可交互的首个实际呈现帧结束。包含安全存储、vehicles、summary和本月stats主图；不含人输入/首次权限弹窗。缺少进程创建起点或实际呈现终点时不计算有效 duration。预算 p95≤2000ms。
3. **同会话热恢复**：先确认当前车概览已可读、同进程同会话内存仍在，固定后台间隔（例如10秒，批次前声明）后恢复前台。起点是 OS 前台恢复，终点是已有概览首次可读可交互实际呈现帧，刷新异步进行；不等刷新HTTP、不把进程被杀、换日/时区变化或会话过期混入此定义。预算 p95≤800ms。恢复遇到这些情况仍登记试次失败或独立条件组，不冒充热成功。
4. **行程详情**：每次从固定同车同资源的实际点击开始，捕获明细和默认200点速度曲线均可读的实际呈现帧。默认按无该详情内存缓存的条件测量，已授权返回/重新登录准备工作在试次开始前完成；若要测热详情须另组。底图独立，不等地图来结束详情计时；网络或曲线失败也不以只有明细当成功。预算 p95≤1500ms。
5. **底图首图**：固定地图资源、可见区域与缓存条件，以该实例开始展示底图到至少首张正确瓦片在正确视口实际呈现计时；同时记录成功率、失败降级是否保留指标/曲线/地点文字。单张decode事件仅为候选关联点。中国大陆验收网络与两端供应商可用性仍按地图票验证；没有首图预算承诺，但必须报告耗时分布与成功率。
6. 同一试次只配对同一进程/同一trial的事件，不把一次失败的开始与下一次成功的终点相减。超时阈值在开测前统一声明（例如30秒），不根据结果调整。若 Timeline 丢事件或trace断档，保留为采集失败；不要拿 HTTP elapsed、Dart入口或视频手工估计替代未捕获端点。

## 报告与判定

使用公开的 nearest-rank 定义：将每个指标/平台批次的全部 N 个试次按耗时排序，失败视为未完成（+∞），p50取第ceil(0.50×N)项、p95取第ceil(0.95×N)项。该秩落在失败项时写“未完成”，不写数值。可另列成功样本的条件分位数帮助定位，但它不能替代全部试次分位数或掩盖失败。

报告必须保留 N、成功数、失败数/类型、p50、p95、成功率、条件、原始试次证据指针和起终点定义。至少30独立试次是每指标每平台的门槛，不是两端合并30；缺条件、缺采样或尚有未解释失败时结论为待验，不单凭成功子集p95称通过。原始 trace/录屏仅留项目本地 `.cache/performance/` 等忽略目录，公开报告只用合成资源别名；确认没有凭据、完整响应、坐标或真实站点URL后再共享。采集时不要开启带请求头/响应体的网络日志；不要提交DevTools可能额外采集的业务日志。
