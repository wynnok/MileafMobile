# 行笺视觉重构方案：一页一主角

> 2026-10-30 决策更新：用户已选择 **C「数据拼贴」** 作为主视觉方向。本文的 A「仪表舱」推荐保留为评审历史；当前决定见 [ADR 0001](../adr/0001-visual-direction-c.md)。

日期：2026-10-30。来源：用户反馈“页面太素、内容平铺、没有重心、不讨好眼球”。本文是产品与视觉提案，不是已实施规格；正式 Flutter 页面、测试和构建均未改动。评审原型见[设计室](../prototypes/visual-refresh/README.md)。

## 先说结论

问题不是“数据不够多”，而是**每一页都在用同一种音量说话**：车况、月度里程、净电耗、费用、AC/DC、最近记录、口径说明都被放进大小接近的白底圆角卡里。用户第一眼找不到主角，第二眼找不到结论，第三眼被技术说明挡住。

建议把产品从“记录查看器”改成**车主的数据手册**，并只做三条规则：

1. **一页一个主角**：每页最多一个最大数字、一个深色/大面积视觉锚点、一张主图。
2. **结论先行，证据随后，明细最后**：先给结果和变化，再给趋势与比较，最后才是记录、采样和口径。
3. **用层级制造节奏**：深色主屏 → 纸面主图 → 浅色辅助信息 → 细线记录；不再让所有内容都长成同一张卡。

推荐方向 **A「仪表舱」**，吸收 B「行笺志」的字体气质与 C「数据拼贴」的块面节奏。保持「湖畔」绿白/深绿基调，不换品牌。

## 为什么现在显得平

对照当前正式渲染（`docs/implementation/owner-experience-renders/`）和源码，能看到六个具体原因：

| 问题 | 当前表现 | 后果 |
| --- | --- | --- |
| 没有视觉主角 | 概览的车况卡、四张指标卡、主图、记录卡尺寸接近；统计页先出现五个等权 tab | 眼睛没有落点，滚动像读清单 |
| 所有内容都是卡 | 白底、1px 边框、18px 圆角贯穿全页 | 卡片失去“分组”意义，页面变成平铺网格 |
| 字号层级太少 | 标签 10–12px、数字 24–28px；趋势图与说明文字争空间 | 数字不够大，解释不够轻，读起来累 |
| 技术元数据抢主线 | “归期时区”“按结束时间归期”“服务端采样 14 点”“非实时”出现在首屏正文 | 用户先读工程说明，后看自己的车 |
| 结论藏在文字里 | “比参照低 8 Wh/km”是一行小字，图表没有参照线/标注 | 图表是装饰，不是证据 |
| 页面职责重叠 | 概览同时承担车况、月度统计、驾驶消耗、补能账本、最近记录、专题入口 | 首页过长，统计页又重复一遍，四 Tab 分工被稀释 |

## 产品层级：5 秒、30 秒、5 分钟

| 时间 | 用户问题 | 页面回答 | 视觉手段 |
| --- | --- | --- | --- |
| 5 秒 | 车现在怎么样？ | 电量、额定续航、状态、是否在充电、最近采样 | 深色车况主屏 + 超大续航数字 + 电池弧/车侧影 |
| 30 秒 | 这个月过得怎样？ | 里程主数、与上月同期的变化、净电耗/补能/已知费用 | 大数字 + 一个变化 chip + 三列辅助读数 + 一张主图 |
| 5 分钟 | 钱花在哪、哪次出行值得看？ | 日趋势、AC/DC、地点、最近行程/充电、专题 | 可点读主图、章节卡、记录时间线、详情 |

四 Tab 的分工重新锁定：

- **概览**：现在 + 本月简报。只保留一个主图和一个洞察，不再堆第二套统计。
- **行程**：找一段路 + 看一段路。期间摘要压缩为一条“路书”，记录卡提前出现。
- **充电**：补能账本。先看钱和覆盖，再看节奏、方式和地点，最后才是全部记录。
- **统计**：解释变化与结构。先给结论与主图，再用“节奏/能耗/补能/长期”四个章节下钻，不把五个等权 tab 放在最前面。

## 页面蓝图：每页只回答一个问题

| 页面 | 首屏主角 | 第二层证据 | 第三层背景 | 下钻 |
| --- | --- | --- | --- | --- |
| 概览 | 深色车况：68% / 320 km / 充电中 / 今日 60 km | 本月 1,198.6 km + 同期变化 + 三列辅助数 + 每日里程主图 | 一条洞察（如净电耗较上月同期低 8 Wh/km） | 最近行程/充电卡、四个专题入口 |
| 行程 | 期间里程 1,280.6 km（30 天）+ 52 趟 | 一条压缩的出行节奏图（不是大卡） | 日期分组时间线；最新一条加大 + 路线缩略图 | 单次行程：地图 → 结果 → 速度/电量 |
| 充电 | 已知费用 ¥186.4 + 8/9 次覆盖 | 充入 234.7 kWh、9 次、5h10；每日补能主图 | AC/DC/未知构成；地点账目 | 单次充电：SOC 区间 → 功率曲线 → 费用/能量 |
| 统计 | 本月里程 + 与上月同期的变化 | 本期/参照主图（柱/线同尺度） | 2×2 章节卡：节奏、能耗、补能、长期 | 章节专题页：一个主图 + 一组证据数字 |
| 详情 | 地图/曲线/电池弧 | 本次结果与参照 | 环境、原始采样、口径 | 返回列表，不跨记录拼全量 |

### 概览：从“车况 + 统计报表”改成“现在 + 这个月”

首屏顺序固定为：

1. 顶部只保留品牌、车辆切换、一个更多菜单；刷新交给下拉。
2. **深色车况主屏**：状态、电量、额定续航、充电功率、今日里程/次数。采样时间降为右上角小字；完整数据时间进“数据说明”。
3. **本月主数**：只让里程成为最大数字；旁边一个“较上月同期 +8.2%”的变化 chip。净电耗、充入电量、已知费用变成三列辅助读数。
4. **一张主图**：每日里程/净电耗可切；图上有一条平均线、当前点标注和可点读，不再只是绿色柱子。
5. **一条洞察**：只放一条可核对的描述，附带“查看依据”；没有可靠参照时宁可留白。
6. **最近两条**：最近行程与最近充电做成横向卡片，带路线缩略图/SOC 条，直接可下钻。
7. **继续读懂**：节奏、能耗、续航/停放三个细行入口；不再用三张同权大卡。

删掉：独立的“驾驶消耗”大卡、“补能账本”大卡、重复的“今日/本月”数字、首屏的归期时区与长口径。它们已经由主数、主图、统计专题承接。

### 行程：记录入口必须早出现

- 期间摘要压成一块：`1,280.6 km` + `52 趟 · 197.4 kWh · 154 Wh/km`，用一条路线纹理做底，不再占两屏。
- 出行节奏变成 80–100px 高的紧凑条带，可点日；它是“找哪天”的工具，不是第二张统计图。
- 记录列表从首屏下半部开始，日期作为分组；每条以“起点 → 终点”为主标题，距离为主数，时长/电耗/能量为一行辅助。
- 最新或最长的一条可以加一张路线缩略图，形成唯一重点；其余记录保持安静。
- 详情：全幅地图作为第一视觉，底部压一张结果 sheet；先看“开了多远、用了多少、到达还剩多少”，再看速度曲线、环境、原始明细。

### 充电：先看账，再看过程

- 深色“补能账本”主屏：已知费用是大数字；覆盖用 `8 / 9 次有记录` + 进度条，不让用户误以为是总用车成本。
- 辅助三列：充入 234.7 kWh、9 次、记录时长 5h10。
- 主图：每日补能/费用/均价可切；费用缺失断开，不补零。
- 构成：一条 AC/DC/未知的水平分段条，标签与绝对值同时出现；DC 占比明确“仅已知分类”。
- 地点：像钱包账单一样列“家 / 湖畔超充 / 公司 / 未定位”，显示次数、能量、已知费用、覆盖。地点不排名、不叫“最划算”。
- 最近记录：一张 SOC 区间卡（18→82%）+ 费用/时长；全部记录仍在页头可达。
- 详情：SOC 18→82% 是主视觉，随后功率曲线；能量、费用、温度、相数分层次，不把技术采样放在第一段。

### 统计：先给一句结论，再给四个章节

- 顶部只留周期选择和“本月”说明；五个 tab 不再占据首屏。
- 主屏是一句结论 + 一个大数字 + 一个参照 chip：例如“本月开了 1,198.6 km，比上月同期多 8.2%”。不评价“开得多就是好”。
- 主图用本期柱/线与参照虚线同尺度呈现；没有可靠参照时只画本期，并说明原因。
- 下方 2×2 章节卡：
  - **节奏**：迷你日历热图 + 活跃日/单程中位；
  - **能耗**：温度或距离分组的迷你条形 + 净电耗；
  - **补能**：AC/DC 迷你分段条 + 已知费用；
  - **长期**：6 个月额定续航观测 sparkline。
- 点章节进入独立专题页：一个大数字、一张主图、一页证据；不再在同一页继续堆十个等权指标。

## 哪些数据上移，哪些下移

| 处理 | 数据 | 理由 |
| --- | --- | --- |
| 首屏最大 | 额定续航、电量、状态、今日里程；本月里程 | 每天打开先看车，再理解这段时间 |
| 一级辅助 | 净电耗（估算）、充入电量、已知费用、费用覆盖 | 它们共同解释“用了多少、花了多少” |
| 需要参照 | 本月 vs 上月同期、本次行程 vs 个人 30 日、本期 vs 参照 | 孤立数字没有意义；比较必须同口径 |
| 二级 | AC/DC/未知、地点账目、记录时长、活跃日、单程分位 | 有明确问题再展开 |
| 折叠/详情 | 最高速度、最大功率、内外均温、相数、电压电流、固件、完整时区/采样口径 | 有价值，但不该和主结果争抢首屏 |

## 视觉系统：湖畔，但更深、更有节奏

### 颜色

- **浅色**：暖雾纸底 `#E9EFE6` / 纸白 `#FBF9F3` / 深墨绿 `#0B2A20` / 湖绿 `#2F7D58` / 薄荷 `#D9F0DF` / 琥珀 `#C58A4A`。
- **深色**：深林 `#08140F` / 墨绿 `#12251C` / 浅苔 `#8FD6B0` / 亮薄荷 `#D6F7DE`。
- 主系列用湖绿；参照用琥珀虚线/空心描边；比较不靠红绿判断好坏。
- 页面底色与卡面必须有明度差；深色主屏只出现在每页一个位置。

### 字体与数字

- 中文用系统黑体；**数字用大字号、紧字距、等宽数字**（`font-variant-numeric: tabular-nums`）。
- 每页最多 4 个字号层级：44–56（主角）、28–32（主数）、16–18（标题）、10–12（标签/说明）。
- 详情页可使用衬线数字/标题作为“行笺”气质（B 方向），但正文仍用黑体保证可读。
- 单位、口径、时间比数字小两级；不要用同字号解释和读数。

### 表面与节奏

- 三种表面：**深色主屏**（车况/账本/统计结论）、**纸面图版**（主图、章节）、**浅色辅助**（三列读数、洞察、记录）。
- 卡片不再统一 18px 圆角：主屏 28px，图版 20px，辅助条 14px，记录行不用卡。
- 用留白和细线分隔，不靠“再加一张卡”分隔。
- 页面内至少有一次“满幅—内缩—满幅”的节奏变化；不要让所有块同宽同高。

### 图表

- 主图必须有：单位、时间范围、当前点、平均/参照线、可点读；柱图从 0 起。
- 当前值用实色，背景值用浅色/描边；参照用琥珀虚线，不只靠颜色区分。
- 图内允许一句短标注，但长口径进“数据说明”层。
- 图表尺寸服务于“看懂一个变化”，不追求同时塞进所有指标。

## 三个方向

| 方向 | 第一眼 | 结构 | 适合 | 风险 |
| --- | --- | --- | --- | --- |
| **A 仪表舱** | 深色车况 + 超大续航 + 本月主数 | 竖向叙事：主屏 → 月份 → 主图 → 洞察 → 最近 → 专题 | 日常打开、快速确认；最容易在 Flutter 落地 | 深色块用得过多会重新变重 |
| **B 行笺志** | 纸面、衬线、超大标题、时间线 | 编辑式流：标题 → 图版 → 手账记录 → 账单；几乎不用卡 | 品牌气质最强，适合“回顾”和“长期” | 信息密度低，开发更定制，中文衬线字体需评估 |
| **C 数据拼贴** | 大小不一的色块 + 一张巨大的里程 tile | Bento：主 tile + 辅助 tile + 满幅图 + 最近 tile | 年轻、视觉冲击强，适合作为章节页/专题页 | 容易变成“更多卡片”，需要严格控制主角数量 |

**推荐 A 作为主结构，吸收 B 的排版自信与 C 的章节块面。** 理由：

- A 直接回应用户“第一眼不知道看哪”的问题：深色主屏把车况变成唯一锚点，其他内容自然退后。
- 它保留现有信息与流程：不需要新 API，不需要重做导航，只需要重排组件和视觉。
- 落地成本可控：Flutter 的 Container/Stack/CustomPainter 已足够；不需要引入新的图表库或字体依赖。
- B 的纸面与衬线适合作为“统计专题/详情”的次级语言；C 的拼贴适合统计章节卡，不建议整页 Bento 化。

## 评审原型

[设计室](../prototypes/visual-refresh/README.md)提供三套方向、四个主 Tab 和两类详情，全部为固定合成数据：

- `?variant=A|B|C` 切换方向；
- 概览/行程/充电/统计底部切换；点最近记录进入详情；
- 浅/深色、100%/200% 字号可切；A 概览另可切正常/部分缺失/空数据，B/C 为固定正常样例以比较结构；
- 固定合成样例：2026-10-26 18:40，68% / 320 km，本月 1,198.6 km、46 趟、净电耗 158 Wh/km、充入 234.7 kWh、9 次、已知费用 186.4 CNY（8/9 次有记录）。
- 合成数据只用于版式评审；正式 App 的总计与比率仍取服务端返回值，不从前端桶或分页重算。

## 如果确认，怎么实施

建议分三个切片，不一次性重写全部页面：

1. **设计系统 + 概览**：颜色/字号/表面/图表规则，概览主屏、月份主数、主图、最近卡；保留四 Tab、会话、车牌、加载/错误/空态。先出浅深色与 200% 实际 Flutter 渲染。
2. **行程 + 充电**：压缩期间摘要、记录时间线、充电账本/地点/SOC 卡；详情页做地图/曲线主视觉。保持现有 API、分页、日期筛选、失败重试边界。
3. **统计**：结论 + 主图 + 2×2 章节；专题页沿用同一图表语言。若确认“章节卡替代五个 tab”，同步 Spec #1 与 #14/#15/#18–#21 的导航验收，不重复建票。

每步都按现有 App + 可控 HTTP 边界 TDD；最后做完整回归、浅深色/大字号实际渲染、双端隔离构建和双轴审查。真实站点/Grafana 对账、真机手势/读屏、地图外部验收仍保持待验，不因原型或构建通过而关闭。

## 需要确认

1. 选 **A 仪表舱**、B 行笺志、C 数据拼贴，还是“以 A 为主，吸收 B/C 的某些块”？
2. 统计页是否接受“结论 + 主图 + 2×2 章节卡 → 独立专题页”替代当前“五个等权 tab 先出现”？这会让首屏更像产品，但需要同步 Spec。
3. 详情页是否把“地图/电池弧/功率曲线”作为第一视觉？地图在真实底图/坐标验收前仍用占位或合规方案，不把合成路线当正式能力。
4. 是否接受把时区、完整采样口径、车辆资料收进“数据说明/更多”层；主路径只留“非实时、估算、已知费用、覆盖不足”这类会影响判断的短提示？
