## 核心目标与成功定义

用户重申的目标是：在 App 中体验良好、美观地、尽可能充分地展示 TeslaMate 的相关数据，参考 Grafana 的相关指标，但不追求逐项一致，也不把桌面 Grafana 整体搬到移动端。

行笺是以图表、地图和关键数字组织信息的移动数据应用。用户应能直观看到变化、比较区间内各时间桶、理解能耗和充电过程，再下钻到记录。图表是主要阅读内容，关键数字用于概括，列表用于找记录，文字用于标签、解释和辅助功能。接入和设置页面按表单设计，记录列表按可扫读卡片设计，不要求每个字段都画图。

“尽可能”通过指标覆盖清单落实：对具有用户价值的指标逐项记录入口、数据来源、展示方式和缺口，而不是只展示当前页面已经接好的字段。当前 API 支撑的下表 V01–V08 是首版必需内容；暂不支持的指标进入 G01–G08 能力缺口，不能悄悄丢弃，也不能在本移动端仓库伪造或补算。缺口不等于永久排除，扩大首版范围或修改后端需另行明确交付范围。

## 指标、页面与展示方式

以下是最低展示要求，不限定具体图表库或像素稿。相同单位的可比数据共用尺度；不同单位采用切换或上下对齐的小图，避免默认双纵轴造成误读。图形必须表达实际数据关系，装饰性图标和逐行进度条不能代替趋势图。

| 编号 / 用户问题 | 页面与必需指标 | 主要展示 | 来源与限制 |
| --- | --- | --- | --- |
| V01 最近车况和这段时间用车如何？ | 概览：状态、电量、续航及口径、今日里程/次数/估算消耗；本月/近7天里程、估算净电耗/能量、充入电量/次数、已知费用/均价、AC/DC绝对值及已知分类占比；净电耗基期比较、最近记录和车辆资料 | 紧凑车况→四个主数→可切每日里程/电耗/能量/补能/费用主图→比较依据→驾驶消耗与补能账本→最近记录；默认首屏露出主数和实际绘图区 | summary + 当前driving/charging日桶stats + 基期driving stats；各资源独立加载/重试/快照区间，比较不阻塞主图。总计和比率取服务端；无电量历史，不伪造停车损耗/费用覆盖率 |
| V02 哪次行程值得查看？ | 行程列表：时间、起终点、距离、时长、净电耗、进行中状态 | 日期分组的紧凑记录卡片，地点和关键数字有清晰层级；点击进入地图和曲线 | drives；列表不是统计数据源，不从已加载分页计算区间总计/趋势，不逐条预取详情序列 |
| V03 这次行程经过哪里、过程怎样？ | 行程详情：轨迹、速度/电量/海拔；距离、时长、净电耗、能量、平均/最高速度、最大功率、内外均温、起终点电量、地点和时间 | 简短摘要后为轨迹地图与时间曲线；默认速度，电量/海拔在同区块切换，起终点电量作区间比较；次级数值放明细 | drive detail + fields=speed,battery,elevation 的 series；温度只有均值，不画温度历史；地图单独加载 |
| V04 哪次充电、补了多少电？ | 充电列表：时间、地点、起止电量、充入能量、费用、时长、AC/DC/未知和进行中 | 记录卡片用同一 0–100% 尺度展示起止电量区间，并保留起止精确数字；能量和费用易扫读 | charging-sessions；缺失起/止值不补 0/100%，不把电量区间画成过程曲线 |
| V05 这次充电过程和结果怎样？ | 充电详情：功率/电量曲线，起止电量、两类能量、费用、时长、分类、温度均值及已有相数信息 | 默认功率曲线，可切到电量；能量并列卡片/条形使用各自名称和相同单位，起止电量可视化 | charging detail + fields=power,soc 的 series；不把两类能量解释为两个可相加部分，不推导损耗率或费用组成 |
| V06 这段时间开了多少、消耗怎样变化？ | 驾驶统计：行程数、里程、能量、净/毛电耗、最高速度，含 totals 和 buckets | 默认里程时间柱图；行程数、能量、最高速度可切换查看对应桶图；净/毛电耗在独立同单位折线图中比较；总计卡片配合读数明细 | kind=driving；直接使用 bucket 数值和 totals，不能平均桶比率；负净能耗/电耗按返回值保留，图轴支持负值 |
| V07 这段时间充了多少、花费怎样变化？ | 充电统计：会话数、充入能量、已知费用、已知费用均价，含 totals 和 buckets | 默认能量时间柱图；可切换会话数；费用和均价分别有时间图及单位，不混轴；总计卡片注明已知费用口径 | kind=charging；费用/均价 null 断开或留空，不画为免费充电；币种沿用站点设置 |
| V08 AC/DC 补能如何分布？ | 充电统计：AC/DC 能量、DC 已知分类能量占比，含区间和时间桶 | AC/DC 同尺度分组条形和随时间比较，DC 占比配精确读数；标明只含已知分类 | stats 的 ac_energy_kwh、dc_energy_kwh、dc_energy_share；不用归一到全部能量的饼图，不把未知归入 AC，不推导 unknown_energy |

概览本月趋势使用与统计相同的 IANA 时区、区间和桶规则，截止当前时刻；独立于 summary 加载、失败及重试。切车/换时区时两个区块都隔离旧结果。数据完整时，默认字号的概览首屏须露出关键结果和实际趋势绘图区；详情简短摘要后进入地图/曲线，统计在简短总计后进入主图，不能先滚过长段说明和逐项字段表才能看到图。

主图可以通过指标切换减少纵向堆叠，但每个必需指标必须有可发现的入口；不得把“可展开文字读数”当成已经交付对应图表。列表和详情不为装饰增加逐记录请求。预算内的数据覆盖和交互质量优先于图表数量。

## Grafana 参考覆盖与能力缺口

参考来自只读 TeslaMate checkout `6bf3d55e4242cf9c55d1dd334b18e35c9ff59d9f` 的 `grafana/dashboards/**/*.json`，只静态核对面板标题；不是对实际站点、SQL 指标口径或运行可用性的验收。当前数据能力以冻结 [OpenAPI](../contracts/openapi-v1.json) 和[来源](../contracts/openapi-v1-source.json)为准。开发版面板中出现某项能力，不代表已测 TeslaMate 版本或现有 API 一定支持。

| 编号 / 参考主题 | 首版承接 / 缺口 | 处理与原因 |
| --- | --- | --- |
| G01 Overview、Drives、Charges、Drive/Charge Details | V01–V05；部分字段缺口 | 已有状态/续航/功率、列表、地图和曲线纳入必做；电压、胎压、能量回收等无冻结 API 支撑的项留作后端能力评估，不伪造 |
| G02 Mileage、Drive Stats、Efficiency、Statistics | V01、V06；部分聚合缺口 | 里程/次数/能量/净毛电耗/最高速度必做；行程中位数、速度直方图、目的地排行、温度与效率关联、里程预测需要额外聚合或模型，列为后续候选 |
| G03 Charging Stats | V07–V08；部分统计缺口 | 能量/费用/均价/分类必做；充电热图可作为已有日桶的后续呈现候选；地点排行、AC/DC 时长或单独均价、跨会话 DC 曲线无对应统计契约，待能力评估 |
| G04 Charge Level、Projected Range、Battery Health | 当前电量/续航及单次过程已覆盖；长期历史、容量/衰减未覆盖 | 后续高价值候选；当前 API 不提供跨记录 SOC/续航历史、容量及健康模型，首版不承诺独立专题，不从少量摘要或分页记录估算 |
| G05 Vampire Drain、States、Timeline | 当前状态快照已覆盖；停放损耗、状态时长分布和时间线未覆盖 | 缺少相应历史及聚合 API，保留候选；不能从最近状态开始时间推导长期分布 |
| G06 Temperatures、Updates | 详情温度均值和当前固件已覆盖；历史未覆盖 | 温度历史/分布、固件历史和更新间隔作为后续候选；不把均值画成时间序列 |
| G07 Visited、Locations、Trip | 单次轨迹、地点与日期筛选已覆盖；访问地图/排行、跨记录旅程组合未覆盖 | 需要额外空间/跨记录契约；不拼当前分页冒充完整历史，也不扩展围栏编辑或导航 |
| G08 Database Information、Dutch tax report | 首版不纳入 | 数据库运维和专项税务报表不属于当前移动用车阅读任务；用户提出具体场景后重新评估 |

这些缺口的下一步是记录用户问题、核实口径和后端输入、评估移动呈现，再单独确定优先级与交付范围；本次不替外部仓库承诺实现。后续出现新的高价值数据时补入本清单，不以“Grafana 没有同名面板”或“旧七屏没写”直接拒绝。

## 可视化与交互要求

- 图表标题说明指标和当前区间，坐标轴/刻度显示时间与单位；柱图有可解释的零基线，折线范围清晰，百分比尺度明确。不同长度的日历桶如实标注，不暗示等长时段；正负数、极值、常量和密集点可读。
- 点按或拖动可读取日期/时间、指标名、精确值与单位；提供不依赖精细手势的选点方式和辅助功能语义。切指标保留当前车和区间，图例与颜色含义保持一致；不要求跨图联动、双轴或复杂缩放工具。
- 序列按真实时间定位；统计桶按日历顺序和桶边界展示。0、null、无记录、单点、全缺失、进行中分别呈现；不补点补零、不插值制造采样、不画未来日子，不以全零假图代替加载态。
- 地图展示已采样路线，不是导航；详情数据、序列、底图，以及概览趋势分区加载和重试。正常数据展示与失败降级分别验收，不能把文字降级当成长期默认交付。
- 配色、字体、间距和圆角形成统一视觉；图表有足够绘图区和留白，标签不遮挡读数。浅深色均可区分图形/网格/选中态，系列不只靠颜色区分；字体放大时允许纵向重排，保留图和等价读数。
- 常规页面只显示必要标签、短口径和采样/快照提示；计算定义、字段名和长说明放帮助或展开层。缺失、已知分类和费用不完整等会影响判断的信息在相关图旁保留短提示，不能藏掉。

## 当前事实与本轮边界

现有代码具备数据读取闭环、基础详情曲线及逐桶条形展示，但概览文字化、统计缺少上述完整指标图表，尚无满足本基线的页面视觉验收。此前代码测试与构建证据继续有效，其覆盖范围不扩大为本基线通过。

本轮交付为文档澄清及相应正式 Spec/工单同步，不实现 UI、不改 API、不改外部链接仓库、不访问生产数据库。后续依据本基线完成原型、实现、自动化和双端真实体验验收；既有“代码/自动化先行，外部待验不关闭工单”的授权继续适用。
