## 产品判断

现有概览不是没有数据，而是信息围绕“最近电量、续航、开了多少公里”展开。同一页里今日/月度里程重复，驾驶能量已经返回却没有展示；充电和效率分散在其他入口。大车况卡和采样说明占用首屏，用户还看不出自己这一段时间用车有什么特点。

建议把首页定位为**可以回到记录核对的用车简报**：先给结果和变化，再让用户看过程与证据。车况仍重要，但不再决定整个首页的空间分配。首页要让普通车主理解数据，深入分析继续交给统计与详情。

这是一项待验证的产品假设：日常反复打开首页的用户，首先关心最近车况、驾驶消耗与补能花费，其次才是电压、最高功率、固件等技术细节。依据是现有产品范围与数据结构，不是已完成用户访谈的结论。

### 首页应该回答的五个问题

| 用户问题 | 首页的答案 | 怎样进一步查证 |
| --- | --- | --- |
| 最近车况怎样？ | 最近采样状态、电量、明确口径的续航；充电时有值才显示最近功率 | 车辆资料与数据时间；不能把旧采样当实时 |
| 这段时间开了多少？ | 今日里程/次数/估算消耗；本月或近7天里程、次数和每日趋势 | 统计及按日期查询记录 |
| 驾驶消耗怎样？ | 估算驾驶能量、净电耗及同口径基期读数 | 逐日趋势、单次行程、口径帮助 |
| 补了多少电、已知花费多少？ | 充入电池能量、次数、已知费用/均价、AC/DC绝对能量 | 充电统计、单次充电过程和费用记录 |
| 哪些变化值得看？ | 一条有依据的区间差异或近期活动；数据不足时不强行生成结论 | 给出区间、基期、样本限制和对应入口 |

“有解释”不意味着自动写一段评价。先做可复核的描述：例如“估算净电耗由166变为158 Wh/km”；不要没有证据就说“天气变暖让你更省电”。

## 建议增加哪些指标

优先级是本次建议，尚未构成实施承诺。这里区分**数据能力**与**页面是否已经实现**。

| 顺序 | 数据/指标 | 用户价值与呈现 | 当前能力与边界 |
| --- | --- | --- | --- |
| 1 | 今日/本月驾驶消耗 kWh | 把“开了多少”与“消耗多少”放在一起；今日作为紧凑副读数，期间能量可切图 | `summary.period.today/month.energy_kwh` 已返回；当前页面未展示 |
| 1 | 期间净电耗、每日变化 | 看驾驶消耗强度；首页主指标，点按切换趋势 | 概览已经请求的 driving stats 有 totals/buckets；须标“估算” |
| 1 | 充入电量与充电次数 | 看补能频率和规模；主指标＋次数副读数 | 增加同区间 charging stats 请求即可；不是新增后端接口 |
| 1 | 已知充电费用、已知费用均价 | 花费有能量背景；费用为主数，均价在补能区 | charging stats 已支持；不能称为完整用车成本，不含停车、保险等 |
| 1 | AC/DC能量及已知分类DC占比 | 理解补能结构；同尺度绝对值条形，标明统计范围 | charging stats 已支持；AC不等于家充、DC不等于外充 |
| 1 | 同期里程/净电耗/补能差异 | 给孤立大数字一个参照；首页最多突出一条，其他在统计中查 | stats可另查基期。需确定区间对齐、0/null、未完成区间规则；不额外发明“健康分” |
| 2 | 跨记录24小时/7天电量历史＋行程/充电事件 | 把驾驶、补能、停放串起来，回答“电量什么时候变了” | TeslaMate原始记录可提供输入；当前Mileaf API缺少跨记录序列，需后端扩展 |
| 2 | 最近一次完整停放的SOC变化与时长 | 回答“没开车时发生了什么”；用起止值、时间与采样条件表达 | 需完整停放边界及质量规则；先做采样变化，再评估能量估计，不直接标精确损耗 |
| 2 | 费用记录完整度 | 用户知道账本缺多少；费用旁短提示，点开缺失记录 | 无已知费用会话数/对应能量覆盖字段，需统计契约扩展；不能从分页估算 |
| 3 | 多周满充投影续航趋势、参考线与覆盖 | 长期观察比单次续航或“健康97%”更有价值；首页留摘要入口 | 无历史聚合和模型契约；需范围/SOC条件、模型版本、有效样本及校准规则 |
| 3 | 温度与效率关系、常用地点、用车节奏 | 有证据时帮助理解差异；主要进专题，首页按需露出 | 详情有温度均值和地点；相关分组/空间聚合需新能力，不能把均值画成温度历史 |

毛电耗继续保留可发现入口，但放在驾驶消耗的解释层，而不是与净电耗并列作为两个“驾驶效率评分”。最高速度、峰值功率、电压/电流/相数、胎压、固件有各自价值，更适合详情或车辆资料，不建议为增加数量而都升为首页主卡。

## 推荐的信息架构与原型

### A 用车简报：推荐

**紧凑车况与今日副读数 → 期间四个主数 → 完整主趋势 → 一条有参照的变化 → 驾驶消耗/补能账本 → 最近记录。**

- 首屏：状态、68%电量、320km额定续航保留；车况卡缩小。今日里程/次数/消耗作为短副读数。四个主数为期间里程、估算净电耗、充入电量、已知充电费用。默认里程趋势在360×800内有实际绘图区。
- 四张主数卡是图表入口，切换里程、净电耗、补能、费用；驾驶能量从消耗卡进入同一主图，避免再叠一排同权卡。
- 第二屏：驾驶能量与净电耗、毛电耗说明；充电次数、已知均价、AC/DC能量与占比。后面是最近行程/充电，直接进入详情。
- 更完整的愿景：电量/事件共同时间线、最近完整停放变化、长期续航入口。原型评审工具可切换到愿景，相关模块明确标待建能力。

取舍：需要向下滚动，但用户不必进入多个菜单才能形成完整认识。重数据用户在同一首页能看全主要结果；日常用户在首屏可停止阅读。

### B 沿途手账：生活事件优先

**今天的里程与消耗 → 用车节奏图 → 最近行程/补能时间叙事 → 期间电耗与费用 → 补能账本。**

优点是能把数据和“我最近做了什么”联系起来，适合回忆旅途。代价是期间成本与效率靠后。当前能力模式只展示最近记录，不声称已有完整状态时间线；愿景模式才加入跨记录电量历史。

### C 能量账本：消耗与花费优先

**紧凑车况 → 已知费用与能量读数 → 净电耗趋势 → 补能结构 → 驾驶里程/能量 → 最近记录。**

适合对电耗与费用关注度较高的人。驾驶消耗与充入电量分开表达，不画暗示守恒的能量流。代价是出行回顾不如A直观，因此建议作为A吸收的信息设计，而非默认首页。

三个方案使用同一份样例与同一套视觉，比较的是信息优先级；不需要同时发布三个首页，也不在本次加入自定义仪表盘、拖拽布局或首页配置系统。

## 哪一部分真正可能比 Grafana 更好

1. **把同一个人的驾驶与补能放在共同语境中。** 里程、电耗、补能和费用之间能互相解释，而不是要求用户自己在多个面板里拼接。未来用电量时间线连接事件，是最值得优先扩展的能力。
2. **先告诉用户一条值得看什么，再给证据。** 按数据质量选择一个相关变化；点击后给基期、趋势与记录。没有足够样本时保持沉默。初期用确定性规则即可，不需要引入大模型生成总结。
3. **按使用状态调整重点，而不是永远相同的卡片顺序。** 完整停放可突出停放变化，正在充电可原位展示最近功率，长途之后可突出本次行程。当前接口缺少目标/ETA，不展示“还需20分钟充满”或“还够开三天”。动态排序规则应在独立交互评审后实施，本原型未实现自动排序。
4. **让“数据不完整”也容易理解。** 用户看见的是“已知费用”“最近采样”“费用8/9次已记录”等结果上下文。覆盖数字需要真实字段；技术定义放帮助层，避免首页变成解释文档。

## 比较与计算必须先说清

- 当前月例：10月1日00:00至26日18:40，对比9月1日00:00至26日18:40；同车、同Asia/Shanghai。不是未满月对上月整月。近7天例为10月20日00:00至26日18:40，对比13日00:00至19日18:40。月份没有对应日、夏令时等情况需在实施时明确策略；不静默按毫秒平移。
- totals与各桶比率直接使用服务端返回值；不从分页加总、不平均桶电耗。UI可对两个已确认同口径的结果展示差值。基期0/null不输出百分比；完成程度不同不直接出好坏结论。
- 当前净能量基于续航差×车辆效率估算。服务端缺少有效能量样本覆盖率，部分样本缺失可能导致能量/里程覆盖不对称。可以显示估算读数和描述性差异，不宣称精确计量、显著改善或驾驶水平评价。
- 当前毛电耗＝按结束时间归期的完成充电充入电池能量÷按开始时间归期的完成行程里程。它不是网侧电耗；补能错期会影响短区间值；净毛差额不是停车耗电。
- 已知费用均价的分母只含费用已知会话的充入能量；免费会话参加，未知费用排除。费用币种沿用用户明确的本地配置；样例显式选CNY，不给真实站点默认币种。
- AC/DC占比分母仅AC+DC，未知分类仍在充入总量中；现接口没有unknown_energy，不能通过相减把它包装成正式返回指标。
- 状态、电量与充电功率未必同一采样时刻。`state.since`不是停放开始。长期休眠或旧采样不直接触发“异常耗电”警报。
