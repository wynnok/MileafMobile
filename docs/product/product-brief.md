# 行笺移动端：产品范围

日期：2026-10-22。状态：需求准备，非正式 spec。

## 已确认的定位

行笺（Mileaf）是一款 Flutter 实现的 Android / iOS App。
目标是解决 TeslaMate 的 Grafana 面板在 PC 上易读、在手机上难用的问题，
将已有数据转化为适合手机浏览、比较和下钻的结果展示。

目标用户是已有 TeslaMate 与 Mileaf Server 的车主；安装后端和建立网络访问路径
是使用前提，不在 App 内重新建设数据采集、数据库或 Grafana。

数据链路为 TeslaMate → Mileaf Server（FastAPI）→ Mileaf Mobile。
客户端不直接连接 PostgreSQL、Grafana 或 Tesla API。

## 已确认的首版范围

一个站点、多辆车辆；站点指一个 Mileaf Server 所服务的一套 TeslaMate 部署。
保留七类核心屏幕，并补齐可用所需的连接与登录入口。

| 能力 | 用户获得的结果 |
| --- | --- |
| 连接与登录 | 输入自托管服务地址及站点访问口令，建立可恢复的会话 |
| 车辆切换 | 从站点车辆中选择一辆，所有业务页面随之切换 |
| 首页概览 | 查看最新记录的状态、电量、续航、今日及本月里程、最近行程与充电、固件 |
| 行程列表 | 按时间浏览、筛选和逐页加载行程，快速看到地点、距离、时长、净电耗 |
| 行程详情 | 查看起终点、轨迹、速度/电量/海拔曲线及相关指标 |
| 充电列表 | 浏览地点、电量区间、能量、费用、时长和 AC/DC 类型 |
| 充电详情 | 查看充入能量、电网侧能量、费用、温度和功率/电量曲线 |
| 统计 | 按周/月/年或自定义区间查看驾驶与充电结果 |

“当前状态”指 TeslaMate 最近记录的快照，不承诺车辆此刻的真实状态。
认证中的 setup/login 属于接入流程，不改变业务数据只读的定位。

## 首版不做

- 车辆控制、Tesla 账号或凭据接入。
- 秒级刷新、实时流、后台持续追踪。
- 修改、删除、补录行程或充电数据，管理围栏。
- 多车对比、多站点同时管理、多用户、共享及社交。
- Grafana 嵌入或面板编辑。
- 电池健康、吸血鬼耗电、独立时间线、固件历史、温度专题。
- 云端托管数据、推送、商业授权和支付流程。

后两组沿用后端首版边界；如需扩展，应先调整范围，不隐含在已有页面中。

## 体验原则（待确认建议）

1. 先给结论，再给明细：概览一屏可读，曲线和次级指标放在下钻页面。
2. 用卡片、列表和单指标图表重组信息，不复刻桌面仪表盘布局。
3. 低饱和配色、清晰数字层级；行笺的记录感优先，避免汽车控制台式的操作暗示。
4. 数字始终带单位和口径；未知显示“暂无数据”，真实的 0 正常显示。
5. 位置数据时间、状态区间起始时间、请求成功时间分别表达，不混成一个“实时更新”。
6. 正常、加载、空数据、部分缺失、过期快照、网络失败均是正式体验的一部分。

## 验收目标（待确认，尚未测量）

- 能在两端完成连接 → 登录 → 切车 → 概览 → 列表 → 详情 → 统计的完整路径。
- 无需横向滚动即可阅读主要结果；系统字体放大后关键数字、单位和操作仍可见。
- 同车同区间按已核实口径与 Grafana 对账，允许差异必须有解释，不能靠客户端重算凑数。
- 参考后端范围文档：已登录冷启动到概览关键数据可用目标 ≤ 2s、热启动 ≤ 800ms、
  行程详情关键数据可用 ≤ 1.5s。测量起止、参考设备、网络、数据规模与底图是否计入，
  必须在 spec 中锁定；现阶段不能宣称达标。
