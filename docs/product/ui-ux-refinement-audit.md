# 行笺 UI/UX 全面优化：现状审计

日期：2026-11-12。审计基线：`main` / `2f8755c`（0.1.2）。状态：方案依据，不是实施完成报告。

配套：[设计与交互规格](../specs/ui-ux-refinement.md)；[实施与验收手册](../specs/ui-ux-refinement-delivery.md)。

## 1. 结论与方法

当前系统已有统一色板、字体、图表、语义与阅读恢复机制。主要问题是信息主次接近、展示密度与任务不匹配、小字号和大字距、图表读值上下文不足，以及少数降级状态占据过大空间。本轮应调整层级和组件规则，保留数据能力与已验证行为。

使用 Hallmark v2 的 app-screen 审计方法；不是营销网站改版，不套用网页 hero、80-word、随机主题或 CSS scaffold。审计阅读源码和既有正式 Flutter 图像，没有启动真实站点、设备或数据库，没有重跑历史测试。文档中的性能、读屏、键盘与真实地图结论仍待实测。

开始时工作树仅有两项用户修改：`docs/tutorial/amap-key-application.md`、`docs/tutorial/amap-key-settings.md`。本轮不修改它们。前一轮对话中未提交的阅读改动现已在 `2f8755c`，不能继续把它们当成待实现缺口。

## 5. 需要保护的既有设计成果

- 单站点、多车、四Tab；设置路径和已有全部指标/证据入口。
- 图表点按/横向拖动/键盘/读屏调整能力，真实零与缺失区别。
- 费用已知覆盖、净/毛/配对口径、充电结束时间归期与时区。
- 只读业务边界和费用补录唯一例外；真实地图与性能外部验收。
- 浅深主题、跟随系统、大字分支；不能以“克制”为由取消必要说明或降低可访问性。
