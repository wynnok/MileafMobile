# 行笺整体产品复核：从记录查看器到车主的数据手册

日期：2026-10-29。来源：本轮用户要求整体复核并实施优化。保留已选「湖畔」视觉和四个主Tab。本文区分目标设计、当前交付与接口缺口；不把建议当作已有能力。

## 结论与产品承诺

车主可能愿意付费的原因，应是打开后迅速看懂自己的车、记录可信、历史可追溯、手机上阅读轻松，而不是卡片数量。商业价值仍需用户验证，不能以此证明付费意愿。

主线是 **现在怎样 → 最近怎样使用 → 能量与钱去了哪里 → 长期发生什么变化 → 查看原始记录**。保持四个Tab，避免电池、地图、温度、固件各占一个低频主入口。所有信息按「一个主结果、一张证据图、一组背景指标、一个下钻」组织。增加数据深度，同时减少同屏竞争。

本次实际读取：Mobile起点`8467391`四Tab、行程/充电详情、统计全部专题、共享图表与App/HTTP测试；冻结0.1/0.2/0.3契约；Server源码`86bf311`；TeslaMate源码`6bf3d55`的Grafana所有dashboard标题及相关SQL、Ecto记录模型。只做源码核对，未读真实站点或数据库。

TeslaMate[官方图册](https://docs.teslamate.org/docs/screenshots/)表明其覆盖电量、效率、续航、状态、地点等多个专题；[官方FAQ](https://docs.teslamate.org/docs/faq/)明确行程电耗是估算。移动端需要承接分析深度，不能照抄桌面面板或把估算包装成仪表实测。

## 车主问题与优先级

| 用户任务 | 主读数与证据 | 为什么重要 | 必须避免 |
| --- | --- | --- | --- |
| 看车况 | 最近SOC、额定/理想续航、状态、采样时间；充电时功率 | 最频繁的确认任务 | 把旧采样当实时、把额定续航当实际可达距离 |
| 看使用强度 | 里程、驾驶记录时长、趟数、活跃日、单程P50/P90；日历与时间图 | 用自己的生活解释数据 | 默认最高速度、仅列累计总数 |
| 看行驶消耗 | 同批有效里程配对估算电耗、估算能量、覆盖；同进度参照与条件分组 | 分清开得多与单位里程消耗高 | 桶比率平均、净毛差当停车损耗、温度因果判断 |

| 回顾与核查 | 路线、地点、时间、过程曲线、来源记录 | 有记忆价值，也能验证汇总结论 | 从已加载分页拼全量统计、按抽样推精确恢复能量 |

## 各Tab的内容契约与阅读顺序

### 概览：现在与近况

首屏：顶部车辆选择 → 紧凑车况（SOC、带口径续航、状态、采样）→ 本月/近7天简报（里程、估算电耗、补入电池、已知费用）→ 实际日趋势。选中指标的卡片与图形联动，只有一个主图焦点。

第二屏：读懂这辆车的直接入口（用车节奏、能耗条件、续航与停放）→ 数值比较与依据 → 驾驶/补能背景 → 最近行程/充电 → 车辆资料。专题问题使用可点击卡片，读者不必知道统计术语；点击才请求专题，不预取全部历史。

本轮已按独立能力声明在概览原位接入0.3配对电耗/趋势/质量比较和驾驶时长、0.2费用覆盖/有效入电均价；保留旧净电耗明细及旧站点回退，扩展字段缺失时不冒充成功。未来优先补充24小时/7日SOC变化和事件带。全量专题汇总不能继续复制到概览形成第二个统计Tab。

### 行程：回顾出行与查找记录

首屏：明确日期 → 期间里程一个主数字，趟数/估算能量/电耗为背景 → 紧凑日节奏 → 日期分组记录。不要用大型趋势把记录入口推到多屏后；趋势点日后显示该日完整服务端匹配。

记录卡：时间为眉题，起终点为主标题，里程/时长为一级，估算电耗/能量为二级；额外围栏/地址保持可查。详情：起终点和时间 → 路线地图 → 核心里程/时长/能量 → SOC区间与电耗历史参照 → 速度/电量/海拔过程 → 驾驶环境和原始明细。温度、最高速度、最大功率不与路线争抢焦点。

下一阶段：在此承接常去地点及访问地图，支持由地点下钻全量记录；多段旅程需先定义跨日、停留和充电事件归属，不自动把行程拼成一次旅行。

### 充电：补能账本与过程回顾

首屏：近30日/7日与自定义 → 已知费用一个主数字和明确费用覆盖 → 入电/有效均价/记录时长 → 真实日趋势。无记录、金额未知与0元分别呈现。未知费用使用中性「未记录」，不显示红色负面评分。

第二屏：AC/DC/未知能量与记录时长 → 地点账目 → 最近充电 → 全部记录与筛选。地点比较应同时看到次数、能量、已知金额、覆盖，避免仅按总价判定某处贵。现有地点API已具备，不重建新端点。

详情：地点和补能结果 → 功率/SOC过程 → 电网侧/入电并列与各自均价 → 时间加权平均/峰值和20–80状态 → 电压电流温度等采样 → 明细。20–80未完整覆盖时不显示确定用时；两侧能量不相加，也不直接叫损耗。

下一阶段：星期×开始小时补能热图、起止SOC分布和时长分位数。跨会话DC性能比较需要SOC、温度、车型、采样覆盖约束，优先级低于账目完整与地点阅读。

### 统计：解释结构与长期变化

首页：全局期间选择 → 总览/节奏/能耗/补能/长期 → 期间里程主数字、配对净电耗与已知支出 → 可点读的当前/同进度参照主图 → 驾驶时长、有效行程和能量覆盖 → 用车日历 → 专题下钻。质量不足只展示原值。

节奏：活跃日、驾驶时长、每活跃日里程、单程P50/P90、记录平均速度；日历、短中长途结构、星期分布；组内完整证据。节奏必须直接可见，不能仅靠滚到首页底部发现。

能耗：配对净电耗及有效里程为主，温度和距离分组提供背景；单程里程中位数和样本数用于提示混杂因素。旧净/毛值保留可查但不代替同批指标。不能输出「最佳温度」「省电排名」。

补能：与充电Tab共享口径，但承担本周/月/年趋势与结构比较，而充电Tab负责记录和账目查找；两处复用数据定义，不让用户理解两套单价。

长期：6/12月额定续航观测与停放窗口观察。趋势必须看到有效日/样本与缺月；停放显示观测小时、有效/排除/开放窗口、SOC百分点、在线/睡眠/离线/未知。它不是全月损耗，正向/零变化保留。

连接/设置：仍是可靠的表单与状态反馈；站点、会话、币种、兼容版本独立说明，不用图表装饰，不新增主Tab。

## 视觉与交互规则

- 延续湖畔绿白/深绿；主结果使用最大字重/字号，单位与解释降一级，数字使用等宽数字特性。每个区块只突出一个主数字。比较用琥珀与线型/描边，不用红绿暗示开得多/花得少就是好。
- 两列指标遵循实际容器宽度，200%字号改为单列；金额及长单位允许换行，不靠缩小字体塞入。记录主标题是地点/路线，日期和技术口径退为辅助层。
- 主图默认使用最能回答当前问题的指标；里程/入电采用零基线柱图，过程采用真实时间曲线，分类同尺度条形，相关分组显示样本和精确读数。图形不只是装饰。
- 口径长说明放展开层，但「估算、已知费用、分类未知、样本不足、非实时」紧邻结果。图表支持点读与前后选点，不要求精准拖动；文字、图案和标签共同表达含义。
- 360×800、100%字号首屏看到主结果及实际绘图区；200%字号以完整阅读为优先，允许滚动。深色/空态/缺失/局部失败都必须渲染验证。
- 数据不齐不等于车辆异常。正常零值、字段缺失、无记录、旧快照、能力不支持各自呈现。每块独立重试；旧数据保留原查询区间。选择车辆/日期/时区后不得混入另一范围。

## 实施顺序与完成边界

本轮实施：概览配对电耗、覆盖及有效均价、问题型专题直达，保留车辆和所选期间；统计显式节奏入口及服务端已有驾驶时长/趟数/能量有效里程；主结果和次级指标的视觉层级；行程与充电/详情的层级优化；App/HTTP回归、正式Flutter渲染、静态分析和双端隔离构建。本轮不修改统计公式或后端。

下一批按依赖推进：OE01电量/事件历史 → OE02车况温度/胎压 → OE03地点回顾 → OE04补能习惯 → OE05行驶过程扩展 → OE06固件历史。它们是可实施的后端交接，详见[接口说明](owner-api-requirements.md)，尚未冻结或部署，不提前显示示例数据到产品。

范围仍归Spec #1及#8–#15/#18–#21/#17，不另建重复票、不关闭外部待验。新增后端能力需要后端仓库实现/契约冻结后再接入。本地单次实施不证明用户审美满意或商业价值通过，需用户评审实际图册。全部执行结果在[实施记录](../implementation/owner-experience.md)据实记录。
