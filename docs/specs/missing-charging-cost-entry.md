## 1. 产品行为与范围

车主在充电列表或详情点击“补录费用”，在同一底部表单输入本次充电单价，查看预估费用后点击“确认补录”。成功后显示服务端最终费用并更新受影响读数。

仅补录费用为 null 的已结束充电；已有费用含 0 均不能覆盖。单价仅用于本次计算，不持久保存，不建立地点价格、默认电价、批量补录或费用修改能力。未知币种允许输入，按原 TeslaMate 账本币种填写。此为既有只读定位的唯一业务写入例外。

## 3. 入口条件与点击行为

入口显示需同时满足：

1. 当前授权范围内 `/meta.version` 可识别为稳定版本且 ≥0.4.0；沿用三段数字版本格式，未知、读取失败且无当前有效能力快照、预发布或不兼容格式均保守隐藏。版本能力不跨站点/登录代次复用。
2. `cost == null`、`ended_at != null` 且 `is_active == false`。
3. 两类能量去掉 null 后取较大值；所有非 null 值必须有限，计费结果 >0 且 <1,000,000 kWh。异常格式保守隐藏并以服务端最终判断为准。

未启用写入开关仍可出现入口，这是已接受的接口限制；不发 PATCH 探测。旧版本仍正常展示只读费用，不能因能力检查失败阻断列表或详情。

| 位置 | 默认排版 | 大字/窄屏 |
| --- | --- | --- |
| 列表费用行 | “费用 —”后间隔 8，ghost“补录费用”；整体左对齐 | 内容自然换行；≥150% 时动作独占下一行并左对齐 |
| 详情结果区 | 保留电量/费用/时长顺序，费用与 ghost 动作为同一组，可参与原 Wrap | ≥150% 时沿用现有单列结果布局，动作位于费用之后 |

动作使用 `type.body`、w600、`accentStrong`；触控区域至少 44×44，按钮横内距沿用 `s20`，无图标、无徽章、无实心底。只有有入口的记录行随内容增高；其他记录高度和费用格式不变。点击动作只打开表单，点击行的其余区域继续进入详情。反复点击不得堆叠表单。

打开时冻结 `{站点身份, 登录代次, 车辆ID, 记录ID}`，强制读取详情并校验返回 `id`、`vehicle_id` 与当前身份。预检完成前不允许输入/提交；已补齐、进行中或电量无效则转只读状态，说明原因并提供“关闭”。预检失败在原弹层重试，不自动退回并跳转详情。

## 4. 表单结构与文案

从上至下只有一条阅读轴：

```text
                  把手
补录费用                         关闭
湖畔超级充电站
2026/11/04 10:20 · 充电 #42

充电单价
┌───────────────────────────────┐
│ 1.25               CNY / kWh  │
└───────────────────────────────┘
币种标签来自本机设置，请与 TeslaMate 原账本保持一致。

预估费用
¥27.50
计费电量 22 kWh
按两类电量的较大可用值计费，最终费用以服务端为准。

仅补录本次充电。保存后无法在 App 中修改；单价不会设为默认值。
[             确认补录           ]
```

此图仅示意顺序，尺寸以 §5 为准；不作为视觉截图或真实费用。地点缺失显示“未知地点”。时间使用当前日历时区，格式 `yyyy/MM/dd HH:mm`，与列表的日历语义一致；超长地点换行，不省略操作对象。

- 标题“补录费用”；字段可见标签“充电单价”，在输入框外，避免浮动后缩成小字；placeholder 为“请输入单价”，不是示例默认值。
- 已配置币种：单位使用代码，如 `CNY / kWh`、`USD / kWh`；提示“币种标签来自本机设置，请与 TeslaMate 原账本保持一致。”
- 未配置：单位“账本币种 / kWh”；提示“请按 TeslaMate 原账本币种填写；当前未配置币种标签。”预估数不添加 ¥，下方显示“币种未记录”。不强制导航去设置。
- 数值为空或无效：预估费用为“—”，保留计费电量，不补 0。
- 明确输入 0：预估为 `0.00`（带已配置的币种显示），附“将记录为免费充电”。正单价舍入为 `0.00` 时改用“费用按两位小数四舍五入”，不能说免费。
- 唯一主按钮“确认补录”；loading 文案保持，附加载指示。没有另一颗“保存单价”、币种选择器或第二次确认弹窗。
- 打开后不自动聚焦，先完整呈现对象和后果；点输入框才唤起键盘。键盘完成键仅收起键盘，不提交。

## 7. 输入、计费与显示规则

### 7.1 单价

- 接受非负十进制，范围0–999999，最多6位小数。规范化后去整数前导零、小数尾零，0 统一为 `"0"`；实际发送最多12位总数字。
- 允许首尾空白、`.5`（规范化 `0.5`）；不默默删除中间空白、逗号、货币符号或负号。禁止指数、NaN、Infinity、正负号及多个小数点。
- `1.` 为编辑中未完成值，暂不能提交；失焦显示“请补全小数部分”。空值首次呈现不报错，用户编辑后失焦显示“请输入本次充电单价”。
- 非数字：“请输入有效单价，使用小数点，不含币种或千位分隔符”；超范围：“单价须在 0–999999 之间”；超过6位小数：“单价最多支持 6 位小数”。不截断、不静默四舍五入用户输入。
- 编辑时不显示千位分组、不改写光标前内容；规范化仅用于校验/请求，不在每次按键重写文本。十进制键盘、关闭自动纠错和文本建议；粘贴走相同校验。
- 单价有效且预检通过才启用主按钮；本地校验无效时 PATCH 次数为0。

### 7.2 费用预估

使用十进制定点计算，不能以二进制 `double * double` 后格式化作为金额算法。预览从 GET 的两类能量计算；请求不发送电量或总价。输入单价乘计费电量，非负结果按 half-up 舍入到两位小数，与服务端 numeric round 口径一致。服务端可能读到更新后的电量，因此预估永远标注“最终费用以服务端为准”。

预估及本次成功确认金额固定显示两位小数、按当前分组规则分组；CNY 前缀 ¥，其他代码后缀，未知币种不附符号且保留说明。原页面仍调用现有 `amountValue`，可以去尾零，不扩大为全局格式迁移。计费电量按现有 `decimal` 规则最多两位小数显示。

| 充入/电网 kWh | 单价 | 计费 kWh | 预估费用数字 | 意义 |
| --- | --- | --- | --- | --- |
| 20 / 22 | 1.25 | 22 | 27.50 | 取较大值，不相加 |
| 20 / null | 1.25 | 20 | 25.00 | 使用唯一可用值 |
| 22 / 20 | 1.25 | 22 | 27.50 | 不能固定选择电网侧 |
| 1 / 1 | 0.005 | 1 | 0.01 | half-up，不用银行家舍入 |
| 22 / 22 | 0 | 22 | 0.00 | 明确免费 |
| 0.01 / null | 0.000001 | 0.01 | 0.00 | 正单价舍入为零，不标免费 |
| null / null、0 / 0 | 任意 | 无效 | — | 不允许补录 |

## 8. 请求与响应

预检：`GET /v1/charging-sessions/{id}`，使用 `force` 获取最新结果；提交前检查冻结身份仍与当前一致、详情仍符合条件。校验时保持原详情电量快照，最终条件由后端原子更新裁定。

```json
// PATCH /v1/charging-sessions/42/cost
{"unit_price":"1.25"}

// 200
{"session_id":42,"unit_price":"1.25","billing_energy_kwh":"22","cost":"27.50"}
```

鉴权与 Content-Type 沿用请求层，不通过 GET 缓存发送；不自动重试或跨重定向转发。请求必须只有 `unit_price`，不传币种、车辆或计算结果。响应严格验证必需字段、记录ID匹配、十进制字符串有限且非负、单价等于提交值、计费电量>0且<1,000,000。最终费用采用服务端值，不以预估不同判定失败；结构错误进入“结果待确认”。

版本解析和新增契约与现有读能力分开：不能因新增 PATCH 判定成功而自动把整个站点标为可写。日志、错误和测试输出不得包含真实 token、站点密码或原始服务响应。

## 9. 状态、关闭与恢复

| 状态 | 可见反馈 | 可执行操作 |
| --- | --- | --- |
| 预检加载 | “正在读取本次充电…” | 关闭；不显示可编辑字段/主提交 |
| 预检失败 | “暂时无法读取本次充电，请重试” | 重试读取、关闭；重试只发 GET |
| 编辑 | 对象、字段、预估、后果说明 | 输入、关闭、合法时确认补录 |
| 提交中 | 保留全部内容、主按钮 loading、“正在补录费用…” | 禁用编辑与提交、关闭、拖拽、遮罩和返回；不提供“取消写入” |
| 403 | “站点尚未开启费用补录，请联系管理员” | 保留输入；按钮禁用至重新读取记录成功或再次打开，提供“重新检查”GET和关闭 |
| 400/422 | “单价未被服务接受，请检查范围和小数位后重试” | 保留输入，修改后可再次确认；无原始英文错误 |
| 404 | “该充电记录已不可用” | 关闭并使列表刷新；没有提交 |
| 409，最新已有费用 | “该记录已有费用 {金额}” | 只读展示并关闭，触发刷新；不称本次成功 |
| 409，最新仍缺失但不符合条件 | “该记录当前无法补录费用，请刷新后查看” | 关闭、重新读取；没有覆盖按钮 |
| 409，最新仍缺失且条件看似有效 | “记录状态已变化，暂无法确认是否可补录” | 查询最新结果或关闭；不在该冲突状态立即重发 |
| 网络/超时/5xx/响应异常 | “补录结果尚未确认，请先查询最新结果” | 保留输入，主动作改为“查询最新结果”，关闭；不自动 PATCH |
| 查询失败 | “仍无法确认补录结果，请稍后查询” | 查询、关闭；保留输入和待确认状态 |
| 查询到已有费用 | “该记录已有费用 {金额}” | 展示实际金额、关闭、刷新；不推断来源或本次单价 |
| 查询到仍缺失且符合条件 | “最新读取仍无费用；查询可能有延迟，重新提交将由服务端校验。” | 保留输入，恢复显式“确认补录”；用户点击才再次 PATCH |
| 成功且响应有效 | “费用已补录 · {最终金额}” | 关闭表单并发出可读屏提示；无需额外确认点击 |
| 401、登出、站点/车辆切换 | 退出旧上下文，必要时沿用重新登录提示 | 清理旧输入，旧响应不能更新当前页面 |

成功用发起页面的提示显示服务端最终金额，不让用户必须在自动关闭前读完闪现的成功页。已确认成功后刷新失败，改用“费用已补录，部分汇总暂未更新，请刷新”，保留快照；不能回退到可重新提交。

普通编辑、预检、失败、待确认阶段允许关闭（按钮、遮罩、拖拽、返回），按 ADR 丢弃输入；关闭待确认表单不等于撤销写入。下次打开仍先预检。提交中仅阻止普通关闭，身份失效仍必须移除旧上下文；离开 App 后恢复也不能自动 PATCH，仍在途则保持提交状态，失去确定结果则进入查询状态。

## 10. 刷新与跨页一致性

明确写入成功，或查询/409 已读到费用时：失效当前会话有关快照、拒绝旧在途 GET 写回，并发出费用数据变更通知。通知不得清空当前车辆、重设日期、切换 Tab 或清除筛选；不借用“身份变更”导致详情退出。

- 发起列表保持搜索、类型/费用/地点筛选、日期、排序及已有加载范围，重新读取记录和相关汇总。尽量保持原滚动位置，内容减少时仅夹到合法范围；费用未知筛选下移除已补齐项。
- 发起详情刷新费用与相关读数，保留电池弧、地图和曲线可见快照，不因费用写入重建地图或强制重新下载曲线。
- 已挂载的概览、统计/充电专题及充电汇总、趋势、地点数据按各自上下文重新读取；未挂载页面下次进入不能用旧费用快照。多实例服务端缓存 TTL 的短暂延迟要通过刷新反馈处理，不能承诺即时全站一致。
- 刷新失败保留旧快照和原有重试入口，并说明费用数据尚未更新；不在本地给整个统计费用简单加预估值。

## 11. 可达性与正式渲染

读屏顺序与视觉阅读顺序一致；字段语义包含“充电单价”、单位和错误，入口标签包含地点/时间以区分多条记录。关闭工具提示“关闭费用补录”。加载、校验、待确认和成功用 live region 通知；键入每个字符不反复播报整张表单。

文字对比度≥4.5:1，图标≥3:1；颜色不单独表达错误、免费或成功。触控目标≥44×44，焦点描边不裁切。支持 100/150/200% 字号，所有主数、单位、后果说明、错误和主动作可经滚动完整访问。

实施时用正式 Flutter 渲染，沿用 [现有渲染辅助](../../test/support/render_png.dart) 和 [现有图册测试模式](../../test/a_charging_method_render_test.dart)，产出本功能小图册，不复制整套全 App 图册：

| 机位 | 状态 | 矩阵 |
| --- | --- | --- |
| 360×800 | 列表入口、详情入口、空输入、合法预估、明确免费、校验错误、403、待确认 | 浅/深 × 100/200% |
| 320×640 | 长地点、未知币种、最大合法单价、底部键盘遮挡 | 浅/深 × 100/200% |
| 390×844 | 标准预估、有输入的键盘状态 | 浅/深 × 100/200% |
| 768×1024 | 标准预估，最大宽520居中 | 浅/深 × 100/200% |

图册可按状态共享夹具，但不得用“missing”名称掩盖实际有费用的记录。每张断言对应状态文案/入口/金额再保存；滚动到底另截主动作机位，不能仅凭首屏无溢出宣称可达。输入设备与真实键盘、中文字体回退仍需真机复验。
