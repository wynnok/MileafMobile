## Problem Statement

2026-10-29 增量对齐：本期四Tab职责、概览配对电耗/费用覆盖、专题直达与阅读层级以[车主体验整体复核增量](#2026-10-29-车主体验整体复核增量)为最新基线；OE01–OE06仍为后端待实现需求交接，当前不扩展后端实施授权。既有外部待验及未关闭工单保持。

2026-10-25 展示方式澄清：本修订依据用户明确重申的核心诉求，替代原先“关键数字优先、曲线作为次要内容”的解释。当前 App 数据闭环和历史验证不等于本修订的可视化交付已完成。

TeslaMate 已记录车辆、行程、充电和历史统计，但其 Grafana 仪表盘主要适合 PC。车主在手机上需要反复缩放、切换面板和筛选条件，难以快速读懂近期用车结果，也难以判断空白、零值和旧数据的区别。

行笺（Mileaf）需要以 Flutter 为 Android 和 iOS 提供独立的移动阅读体验。数据来自用户自托管的 Mileaf Server；客户端不接入 Tesla 凭据、不控制车辆、不修改 TeslaMate 业务数据。界面中的车况是最近采样的结果，不是实时车辆状态。

## Solution

2026-10-26 用户已选择 A「湖畔」作为正式视觉方向：柔和绿白/深绿主题，近况图形和关键卡片 → 完整趋势 → 最近记录的阅读层级，数字与单位分层；比较系列采用琥珀色并结合线型/描边区分。下述范围与数据口径不变，后续不再停在等待选择原型。

交付一个站点、多车辆的完整首版：连接与登录、车辆切换、概览、行程列表与详情、充电列表与详情、统计，以及必要的展示设置。主导航为“概览、行程、充电、统计”四个入口；车辆从顶部切换，设置从概览进入，详情承接列表和最近记录的下钻。

以移动端为载体，美观、直观、体验良好地尽可能充分展示 TeslaMate 数据。参考 Grafana 的相关指标，但不要求逐项一致或迁移桌面布局。图表、地图与关键数字构成主要阅读内容，文字解释和明细辅助下钻；概览、详情、统计不能以字段清单或逐桶文字代替主要图形。用户应能完成“连接 → 登录 → 选车 → 阅读概览 → 下钻行程/充电 → 查看统计”的闭环，支持手机纵向阅读、系统浅深色和字体放大。

本 Spec 覆盖完整首版，已由 #2–#17 跟踪；本轮修订同步相关既有工单，不另起一套范围。技术验证可以是依赖，但不能悄悄删减图表、地图、双端接入或其他已纳入的能力。文档澄清不代表已经实现、通过视觉评审或获准上架。

## Implementation Decisions

以下是基于现有文档与用户授权本次综合形成的首版基线。既往用户明确确认的范围保持不变；此前未冻结的默认值在这里作保守收敛，不宣称用户逐项指定过这些细节。

### 1. 范围、术语与平台

- “站点”是一套 TeslaMate 及对应的 Mileaf Server；“行程”“充电会话”“位置点”“数据新鲜度”“净/毛电耗”沿用既有领域含义。只同时连接一个站点，但支持该站点的多辆车。
- Android/iOS 使用同一 Flutter 工程，手机纵向布局优先；平板保持可用布局，不承担专门的平板双栏设计，横屏不作为首版优化目标。
- 最低运行基线为 Android API 24、iOS 15；工程创建时锁定可满足此基线的 Flutter stable 与兼容依赖，记录确切版本和架构，不安装或切换全局运行时。若 SDK/地图依赖不能满足，先换兼容方案，不静默提高最低版本。
- 最低运行版本不等于商店构建 SDK/target 要求；本 Spec 不覆盖商店提交。平台基线参考 [Flutter 官方支持矩阵](https://docs.flutter.dev/reference/supported-platforms)，实施时复核对应锁定版本的支持范围。

### 2. 页面和视觉

- 四个底部入口：概览、行程、充电、统计；顶部切车；设置从概览进入；详情为下一级页面。切车时退出旧车详情，避免标题和内容归属不一致。
- 中文界面、跟随系统浅/深色；首版不增加手动主题、英文翻译和视觉皮肤。统一排版、留白、配色和图表语言，主要结果采用图表/地图加关键数字；列表使用易扫读记录卡片，接入/设置采用表单，不为每个字段强加图形。
- 配套实施基线为仓库 `docs/product/visualization-requirements.md` 的 V01–V08、A01–A06；本轮不推送代码，本 Spec 正文同时列明必需指标、图形和验收，避免依赖未发布文件才能实施。主图、指标入口、数据来源和状态分别验收，逐行文字/进度条不替代完整趋势图。
- 先给出概览、两类统计、两种详情和记录卡片的代表性可视原型/渲染稿，以有起伏、0/null 的固定合成数据记录具体视觉方案的用户评审，再批量实施页面。此要求针对具体视觉方案，不把用户已确认的核心方向重新视为开放题。
- 在 360×800 逻辑像素、100% 字号的代表数据下，概览首屏露出关键结果与实际趋势绘图区；统计简短总计后可见主图，详情简短摘要后进入地图/曲线。长口径/字段名放帮助或展开层，影响判断的缺失/已知分类/费用提示在图旁简短保留。
- 车辆名缺失按车型与 VIN 后四位回退，仍不足时以车辆 ID 区分。只能展示 API 已提供的后四位，不请求完整 VIN。
- 主结果在 360 逻辑像素宽度与 200% 字体缩放下可读，无整页横向滚动或关键操作遮挡；密集指标允许换行/纵向重排。图表提供文本摘要、读数和辅助功能语义，不能只靠颜色区分。

### 3. 服务地址、接入和请求边界

- 用户填写服务根地址，客户端只追加一次 API 版本前缀，保留反代路径前缀与端口；拒绝不支持的协议、内嵌账号口令、查询串和片段，避免拼接含义不明。尾部斜杠规范化，连接身份包含协议、主机、端口和路径前缀。
- 公网使用 HTTPS；保留后端既有的自托管私网/VPN HTTP 使用场景。HTTP 默认不允许发送口令或 token；用户必须对确切站点明确选择受信任网络接入，界面说明明文传输含义，授权不跨站点继承。VPN 建立及网络可信性由用户负责，App 不声称能验证隧道安全。
- HTTPS 按正常证书链与主机名校验；不提供忽略证书错误开关，不因 HTTPS 失败自动降级 HTTP。
- 策略在统一客户端层执行；发布构建必须验证实际 Dart/原生网络栈，不能仅凭系统配置推断有效。Flutter 官方说明原生与 Dart socket 的策略行为不同；见 [Flutter 网络策略说明](https://docs.flutter.dev/release/breaking-changes/network-policy-ios-android)、[Android 网络配置](https://developer.android.com/privacy-and-security/security-config)、[Apple 本地网络例外](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking)。
- 仅按需要配置平台网络例外和局域网权限说明；拒绝权限时解释受影响的接入并提供系统设置指引，不申请手机定位权限。平台适配必须覆盖发布构建，不能依赖 debug 放行。
- 健康检查成功后才继续接入；503 明确解释数据库/上游异常，不把所有错误都归为地址填错。建立连接超时 5 秒，单次 API 总时限 15 秒，失败可手动重试；首版不做无限重试或静默循环登录。
- 登录、初始化和带凭据请求不自动跟随跳转；提示用户填写实际服务地址，避免跨 origin 或路径边界泄露凭据。

### 4. 初始化、会话与替换连接

- 提供“登录已有站点”和用户主动进入的“首次设置站点口令”入口；没有匿名初始化状态接口，不能从登录 401 推断尚未初始化，也不先探测性调用 setup。
- 初始化口令最少 10 字符，并做二次输入核对；成功后用该次内存中的口令登录，随后清除口令。409 返回已有站点登录；初始化请求超时不自动重复提交，提示结果未确定，可尝试登录或主动重试初始化。
- 登录只使用站点访问口令；保存 token 与 expires_at 至平台安全存储，不保存明文口令，不引入注册、OAuth、refresh token 或客户端找回密码。
- 当前 token 有效期 30 天，站点重置或 token 数量淘汰也可能使其提前失效。启动可检查本地到期时间；业务接口返回 401 时，以服务端结果为准，使当前会话失效并清空其业务缓存，保留地址等非敏感设置后回登录。
- 新连接作为候选独立检测与登录，成功后原子替换；失败不覆盖旧连接。旧 token 永不用于候选站点；同站点重新登录也创建新的会话代次以隔离旧请求。
- 本地退出清除本机会话、内存业务数据与旧请求权限，保留可编辑的地址设置；说明没有撤销其他设备或服务端 token，当前后端无 logout/revoke。

### 5. API 契约和模块边界

- 只调用 Mileaf Server 的 API；除显式 setup/login 外业务全为 GET。对 TeslaMate 数据库、Grafana、Tesla API 均无直接连接。
- 保持一个统一的 HTTP/DTO/错误处理边界，向业务页面提供可替换的数据读取接口；站点会话与展示状态独立管理。地图只在外部服务边界隔离，不为每个 DTO 建一层服务或引入插件化架构。
- 实施开始固定后端版本并取得其 OpenAPI 作为 Dart 客户端生成源。先核对 nullable、可选字段、Bearer 定义、错误 envelope、304 与统计联合响应；生成结果通过契约用例后使用，补足生成器未表达的运行时分支，不假设生成即正确。
- 此仓库不承担后端新端点或 schema 变更。若运行契约与本 Spec 相矛盾，保留可复现证据并先解决依赖，不在 App 内重算或伪造服务端缺失字段。
- 以下 API 路径均相对 `/v1`，是协议路径而非源代码文件位置。

| 能力 | 已有接口 | 关键契约 |
| --- | --- | --- |
| 连接、认证 | GET /health；POST /auth/setup、/auth/login | health 不返回初始化状态；login 返回 token、expires_at |
| 元信息、车辆 | GET /meta、/vehicles | vehicles 顶层是数组；meta 提供 version、tested 等 |
| 概览 | GET /vehicles/{id}/summary?tz=… | state、battery、period、最近记录、firmware、freshness |
| 行程 | GET /vehicles/{id}/drives；GET /drives/{id}、/drives/{id}/series | 列表 items/next_cursor；详情与序列分开 |
| 充电 | GET /vehicles/{id}/charging-sessions；GET /charging-sessions/{id}、/charging-sessions/{id}/series | 两类能量、cost、is_dc、is_active；详情与序列分开 |
| 统计 | GET /vehicles/{id}/stats | kind=driving/charging 分开请求，返回 buckets/totals |

### 6. 概览和车辆切换

- 单车自动选择；多车恢复上次仍存在的选择，否则选择列表首项并明确选中状态；空数组显示无车辆，不发无效车辆请求。
- 概览主要展示状态快照、电量、续航及口径、最近位置采样时间；其次为今日/本月里程和行程数、最近行程/充电、里程表与固件。有充电状态且功率有值时展示该功率，仍标明来源是最近记录。
- V01 以比例电量图和关键卡片展示 summary，并独立读取当前本月 kind=driving、bucket=day 的 stats 绘制每日里程主图；沿用统计 IANA/UTC 日历规则，截止当前时刻。summary 和趋势各自加载/失败/重试，切车/换时区均隔离旧结果，不用今日/本月两个汇总值伪造趋势或电量历史。
- 概览最近记录不是最终值保证；按 API 的 null 呈现，不从有限摘要猜测完成状态。点击后在详情读取完整状态。
- 全部请求归属连接、会话代次、车辆与查询参数。切车立即更新归属并清除旧车占位内容；旧响应包括旧 401 均不能覆盖/注销新会话。选择车辆消失时重取车辆列表并给出提示。

### 7. 列表、日期和分页

- 行程列表展示开始时间、起终点、距离、时长、净电耗；充电列表展示地点、电量区间、充入能量、费用、时长和 AC/DC/未知。
- V02/V04 用日期分组记录卡片组织主次；充电起止电量图采用 0–100% 同尺度，缺失端点不补值。列表用于找记录，不预取每条详情曲线，不用已加载分页充当全区间统计。
- 两类列表默认最近 30 个本地日历日：今天及前 29 天，从首日零点到当前时刻。用户可选择含首尾日期的区间；历史结束日转换为次日零点，今天结束则截到当前时刻，不请求未来时间。
- 统一转换为带时区的 UTC 半开区间 `[from,to)`，保持 `from < to`；列表按 started_at 归期，顺序以服务端为准。列表不额外套用统计的 730 天上限。
- page size=20，cursor 不透明；滚动到底逐页加载，next_cursor=null 才是到底。并发翻页合并/抑制重复请求，按 ID 去重；刷新、筛选和切车重置分页。游标不是数据库快照，不承诺跨请求的快照一致性。
- 进行中行程依据 ended_at=null 标识；充电依据 is_active。保留未完成指标的 null，不虚构最终时长、电量、距离或能量。翻页失败保留已加载结果并局部重试。

### 8. 详情、序列和图表

- 行程明细包含起终点、距离、时长、净电耗、速度、温度与起终点电量；充电明细区分充入能量、电网侧能量、费用、分类、时长及已有的温度均值。不承诺费用构成、温度序列或分时电价。
- 详情指标、序列与底图独立加载；成功区域不被局部失败遮蔽，失败区域可重试；资源 404 解释已不可用并可返回列表。
- 行程 fields=speed,battery,elevation，充电 fields=power,soc；默认 200 点，首版不增加用户采样精度开关或自动拉取完整轨迹。两类序列实际点数为 0/1/多点均必须可用。
- 图表按真实时间轴展示，支持指标切换和点选读数，不以序号代替时间。保留 null 并断开对应连线，不补点、不补零、不将采样峰值等同原始峰值。
- V03/V05 曲线是主要内容：行程默认速度、充电默认功率，其他指标在同一区域可发现地切换；配时间刻度、纵轴单位、选中状态及点按/拖动读数，提供无需精细手势的辅助选点。不同单位分图/切换，不默认叠双轴；两类充电能量独立标注，不相加或推导损耗率。
- API 降采样可能改变点间时间距，不能以固定间隔阈值推断真实断采。对没有 gap 标记的有效点，连线仅为低强调的采样示意，明确说明不代表连续观测；不新增插值样本或声称识别了全部采集空洞。准确的全量断采识别不属于当前契约能力。
- 行程电量按 battery_level、速度按 speed_kmh、海拔按 elevation_m 解码；充电 power 单位 kW、soc 为百分比。未请求字段省略与已请求字段 null 必须分别兼容。

### 9. 地图交付条件与前置验证

- 首版包含带地名底图、起终点和采样轨迹，可缩放并自动适配有效点边界；无坐标显示空状态，单点显示标记，坐标缺失不跨缺失点虚构路径。不是导航、路由规划、实时定位或原始高精度轨迹。
- 技术验证以中国大陆手机网络可用为验收区域；不承诺全球网络的服务可用性。选择至少一种可在两端发布构建使用的底图方案，不要求终端用户注册开发者账号或填写地图 API key；如需要服务凭据，由发布方配置且不写入公开仓库。
- 不预先绑定未评估的供应商或假设公共瓦片可无限免费使用。后续先完成有限技术验证，产出一个明确选择及官方使用条款、配额/费用、署名要求、SDK 最低版本与两端可用性证据；不额外建设地图供应商切换 UI。
- 核实 TeslaMate 来源坐标参考系与底图要求后，只在地图边界做必要转换，保留源坐标；转换规则须有可追溯依据及固定校准点，两端结果一致，不能凭“看起来对齐”验收。
- 上述是必须先完成的研发依赖，不是等待用户选择供应商的产品开放题。与底图、坐标或平台版本相关的实现应依赖验证结论；依赖未通过不能被当作无条件可实施工单。不能以永久无底图示意图作为满足本 Spec 的替代交付。
- 底图失败时保留已有指标、曲线及起终点文字，提供重试；实际运行降级不等于取消底图能力。不向底图服务发送站点 token；告知底图服务可能接收 IP 和可见区域请求，不集成行为遥测。

### 10. 统计口径与时间分桶

- 驾驶/充电作为同一统计入口的两种视图，默认本月；支持本周、本月、本年、自定义。当前日历周期都截到当前时刻，历史区间使用完整日历边界，不把未来日子画成已观测的 0。
- 本周周一开始；周/月视图 bucket=day，年视图 bucket=month；自定义跨度不超过 31 个本地日历日用 day，32–180 日用 week，其余用 month。首版不增加逐年对比或跨 730 天合并查询。
- 对 stats 分别传 kind=driving/charging、bucket、from/to、IANA tz；按 UTC 时差验证单次跨度大于 0 且不超过 730×24 小时，非法时不发送请求并提示缩小区间。
- 已完成行程按 started_at 统计，已完成充电按 ended_at 统计；进行中不计入。提供可见口径说明，解释充电列表与统计在区间边界上的差异。
- 总计直接使用 totals，趋势使用 buckets；不平均桶净电耗、毛电耗、单价或占比。若两种统计请求之一失败，保留另一种成功结果。
- V06–V08 要求完整时间轴主图及指标入口，不能用逐桶展开文字和横向进度条替代：驾驶默认里程柱图，可切行程数/能量/最高速度，独立比较净毛电耗折线；充电默认能量柱图，可切会话数，费用/均价分别有图，AC/DC 用同尺度分组及时间比较。图旁可读 totals，点击桶读取真实值；图表不需跨图联动或复杂分析工具。
- 桶按本地日历顺序及边界呈现，标题、时间刻度、单位、图例、尺度可读；柱图零基线、负值/常量/极值和密集点均可解释，净能耗/净电耗负值不截为 0。缺失比率断开，不把费用 null 画成免费；空状态和加载态不展示假零图。
- AC、DC 能量与后端 dc_energy_share 按原口径展示；unknown 不能归入 AC。首版使用独立数值/条形比较，不把 AC+DC 强行归一为全部能量的饼图，也不自行新增“未知能量”推导指标。说明 DC 占比的分母是已知分类能量。

### 11. 单位、续航、费用和空值

- 首版统一公制：km、km/h、kWh、kW、°C、Wh/km、分钟。暂不增加英制切换，不能依据 source_unit_of_length 对返回值再次换算。展示层舍入：距离 1 位小数，速度/电耗整数，能量/功率和费用最多 2 位小数，温度 1 位小数；舍入不参与再聚合。
- battery.range_kind=rated 标注“额定续航”，ideal 标注“理想续航（ideal）”；只显示实际返回的一个值，不将 ideal 改称 estimated 或伪造同时存在的两种续航。
- 行程 consumption_wh_km 是净电耗；统计明确区分 net/gross。energy_added_kwh 和 energy_used_kwh 不互换；概览最近充电 energy_kwh 使用充入电池口径。
- 费用币种默认“未配置”：显示数值并明确币种未知，不显示人民币符号。设置允许用户选择站点币种代码作为展示标签；不换汇、不按系统地区推断、不改变原数值，并说明后端没有币种信息，用户需确保站点数据使用同一币种。
- 真实 0 正常展示；null 显示“—”并提供缺失说明，不替代成 0；空列表为无记录。后端空桶计数/可加量中的 0 直接展示，比率 null 保留未知。费用部分缺失时不宣称总费用覆盖所有会话，均价说明只统计费用已知记录。
- 地点优先使用服务端 display_name，缺失时显示“未知地点”，保留可用地址/围栏，不调用手机端第三方逆地理编码补全。

### 12. 时区、刷新和缓存

- 采用设备当前 IANA 时区，界面标明统计时区；设备无法提供有效 IANA 时区时使用 UTC 并可见提示，不用固定偏移量假装支持夏令时。首版不增加手动选时区。
- 恢复前台时检测日期/时区变化，重算相对日期筛选及统计窗口，重新查询；历史自定义筛选保留所选日历日期并按新显示时区转换。旧时区的结果不冒充当前结果。
- 内存业务缓存按连接、会话代次、资源路径与完整查询参数隔离；只在本次登录会话保留，不增加离线业务数据库。普通设置仅保存地址、选车、币种和站点 HTTP 授权等非业务偏好。
- 默认不进行后台轮询。手动刷新发出条件请求；回到前台仅对当前可见资源按缓存有效期校验，不同时刷新所有 tab，也不唤醒车辆。
- 尊重响应 max-age、ETag 等缓存信息；304 仅在存在相同键的已授权响应体时复用。缓存体意外缺失时移除条件头进行一次普通 GET，不把 304 当空成功响应。
- 请求/校验成功时间与采样时间分别记录。304 可以更新“已校验时间”，不能改写采样时间，也不能保证绕过服务端自身缓存拿到新采样。

### 13. 新鲜度、兼容性和错误恢复

- freshness 只在实际提供的 meta、车辆和概览使用；last_position_at 是位置采样时间，last_state_at 是最近状态区间起始时间。历史列表、详情、序列、统计没有逐项 freshness，不编造来源时间。
- 旧位置数据、正常休眠和请求失败分别呈现；不设置未经依据的过期红色故障阈值，不从状态起始很早推断采集停摆。
- meta.tested=false 表示版本未在服务端已测范围内，不等于 schema 一定不兼容；显示提示但允许已支持的业务响应展示。站点结构不兼容可能导致服务无法启动，不能依赖一定收到 schema_ok=false。
- 按 HTTP 状态与稳定 error.code 分类，message 仅作补充；包含 unauthorized、already_initialized、rate_limited、not_found、invalid_request、db_unavailable、upstream_timeout、internal_error。兼容 400/422 参数错误、非 JSON 反代错误、连接超时与证书错误。
- 首次加载显示骨架/加载态，空响应显示空态，已有结果刷新失败保留快照并显示失败提示，局部失败局部重试。401 的处理仅对当前有效会话生效；429 不自动循环重试，有 Retry-After 时尊重，没有时不编造精确解限时间。
- 日志不含口令、Authorization、token、完整响应体或轨迹坐标；诊断可展示 X-Request-ID。首版不集成遥测、崩溃上报或第三方行为分析；地图必要请求在其边界单独说明。

## Testing Decisions

### 已与用户确认的主要测试边界

通过可控 HTTP 响应驱动完整 App 的操作与可见输出，覆盖从接入到统计的用户路径。优先采用最高的 App/页面集成边界；不为每个状态类、DTO 或 UI 私有方法分别建测试缝。只有平台安全存储、网络策略和地图坐标等无法由该边界证明的行为，补必要的双端真机验证。

### 性能预算和测量协议

以下是研发验收目标，不是已有实测结论；不把后端单接口耗时直接当 App 端到端耗时。

| 指标 | 起止与条件 | 目标 |
| --- | --- | --- |
| 已登录冷启动 | 进程不存在、已有有效凭据、无内存业务缓存；从启动到概览关键结果及本月主趋势实际可读可交互 | p95 ≤ 2s |
| 同会话热恢复 | 进程存活、当前车存在内存结果；从回到前台到首个可读可交互概览帧，刷新异步进行 | p95 ≤ 800ms |
| 行程详情 | 从点击记录到主要指标和默认曲线可读；不以旧车缓存充数，底图独立测量 | p95 ≤ 1.5s |

- 使用 profile/release 构建，两端各固定一台普通手机；Android 参考 6GB RAM、60Hz 设备，iOS 参考 iPhone 12 或同级。第一次基线测量记录确切型号、OS、SDK、服务端版本、数据集、缓存策略和采样次数，后续不通过换高配设备掩盖回归。
- 可重复网络基线为 80ms RTT、下行 10Mbps、上行 2Mbps、无丢包，作为受控移动网络模型，不声称代表所有 4G。每指标每平台至少 30 次独立测量，报告 p50/p95、失败数与样本总数，不能剔除失败后称通过；另做真实弱网恢复的功能验收。
- 数据规模沿用后端目标：至少 5 万行程、50 万位置点，另含足以翻页的充电记录；数据准备和性能运行安排在项目隔离环境，不改真实用户库。详情固定资源和 200 点采样，不把不同查询混为一组。
- 冷启动包括凭据读取、必要的车辆列表、summary 和概览本月 stats 主图；热恢复计入已缓存主图实际可读，不含用户输入、首次系统权限对话框。详情计入指标与默认曲线，不计第三方底图。既有仅 summary 就绪的标记不足以满足新终点，需调整后复测，不直接沿用旧数据宣称通过。底图单独记录首图耗时、成功率与失败降级，不能因其被单独计时而不验收地图。
- 达不到预算时先报告客户端、网络、后端各段证据再修正瓶颈；服务端耗时本身超预算时明确为外部依赖问题，不伪称 App 已达标。

## 2026-10-28 已确认的统计扩展 A「用车洞察」

本增量已获用户确认，沿用湖畔视觉；优先于历史章节中把长期续航、停放观察或统计分析笼统列为候选的描述，仅扩大下述明确范围。此前已交付范围及外部待验保持有效。本次 to-spec 只更新规格，不实现页面、不建重复 Spec、不分拆或关闭工单、不改变原生阻塞边。

### Problem Statement

当前统计虽有驾驶/充电总计和趋势，但信息割裂、缺少主次，车主需要自行拼出「用了多少、效率如何、钱花在哪里、长期有什么变化」。原有数据闭环不能代替移动端产品表达。接口提案和合成原型也不能作为已实现契约或真实分析结果。

### Solution

采用 A「用车洞察」：结果与同进度参照 → 用车节奏 → 电耗条件 → 补能账目 → 长期观察。统计内设总览、能耗、补能、长期专题，保留四个主导航。默认本月，延续本周、本年和自定义；长期续航独立选择6/12个本地月。主图、单位、比较分母与证据下钻共同表达结果，不搬迁桌面Grafana布局。

### User Stories

以下为本增量独立编号，不改历史故事编号。

1. 作为车主，我希望首屏突出期间里程及主趋势，以便迅速知道这段时间用了多少车。
2. 作为车主，我希望净电耗与已知充电支出作为副读数，以便同时了解效率和账目而不失去视觉重点。
3. 作为车主，我希望比较自己的相同日历进度，以便不把未完月份与完整月份误比。
4. 作为车主，我希望同时查看本期和参照期原值、日期及质量，以便核查差异。
5. 作为车主，我希望基期零、缺历史或质量不足时仍能看原值，以便不被无依据百分比误导。
6. 作为车主，我希望日历热图标出每日里程，以便认出自己的用车节奏。
7. 作为车主，我希望点某天看到该日开始的行程及该日结束的充电，以便查找对应记录而不混淆归期。
8. 作为车主，我希望看到活跃日、驾驶记录时长及每活跃日里程，以便理解使用频率与时间投入。
9. 作为车主，我希望看到单程距离/时长的中位数与P90，以便理解典型行程和较长行程的尺度。
10. 作为车主，我希望比较短、中、长途的次数、里程和加权电耗，以便了解不同使用条件的记录。
11. 作为车主，我希望看到星期分布，以便观察生活节奏而不被自动判断为通勤。
12. 作为车主，我希望按室外均温查看电耗及样本量，以便了解关联而不误认为因果。
13. 作为车主，我希望从距离或温度组进入完整匹配行程，以便核对图形依据，不只看到第一页。
14. 作为车主，我希望分清旧净/毛电耗与新增配对净电耗，以便理解不同分母及估算边界。
15. 作为车主，我希望同时查看费用覆盖、有效入电/网侧均价和分类时长，以便知道账目是否完整。
16. 作为车主，我希望比较AC/DC/未知入电，并进入同分类或地点的补能记录，以便知道电与钱花在哪里。
17. 作为车主，我希望在长期专题切换6/12个月续航记录，以便观察趋势、波动带与有效日数。
18. 作为车主，我希望缺月和稀疏样本明确可见，以便不把有限记录当成健康检测或新车基线。
19. 作为车主，我希望看到闭合停放窗口的SOC变化、观测小时及状态分布，以便理解记录覆盖的停车期间。
20. 作为车主，我希望查阅停放端点、排除原因和开放窗口，以便知道哪些记录参与了统计。
21. 作为车主，我希望区分睡眠、在线、离线和未知，以便不把在线推断成哨兵或空调耗电。
22. 作为车主，我希望一个专题失败时其他结果继续可读且可独立重试，以便不会丢失已有阅读上下文。
23. 作为旧版本站点用户，我希望保留已有统计及明确的升级/不支持提示，以便不因新增能力而失去基础阅读。
24. 作为车主，我希望在深色、大字和辅助读数下仍能读取每条系列，以便舒适、准确地使用统计。

**比较约束及与原型的差异。** 不新增comparison端点。默认本月，周/月/年分别对上周/上月/去年相同当地进度，自定义按触及的本地日期数前移并保持起止本地时刻；IANA/DST计算，不能按UTC毫秒平移。目标日期不存在时按服务端接入约定裁到目标月末并标unaligned_calendar，DST不存在/重复时刻也不比较；可查询非对齐原值，但不显示差值。两期同车、同bucket、同range_kind、方法/版本一致、进度一致且均sample_status=adequate才展示算术差；基期0或缺失不显示相对差。adequate门槛为每期≥5趟配对且有效距离覆盖≥80%，读取服务端状态与thresholds，validation=provisional不是统计显著性。UI可表达有依据的「较参照高/低多少」，不照搬原型默认「开得更多，电耗更低」固定结论，不生成自然语言诊断、评分、原因或建议。两期query/as_of分别保留，不宣称原子快照；as_of是表示生成时间，不是车辆采样时间。

**驾驶口径与证据约束。** 新配对净电耗为同批distance>0且估算能量有效的分子/分母，旧净电耗仍按旧能量/全里程，旧毛电耗为按结束日入电/驾驶里程；三者命名、方法与覆盖分开，不静默替换，不以净毛差推损耗，不声称等同所有Grafana gross算法。有效距离/时长排除负值，但证据原值保留并说明排除；0里程可计次数/距离分位，不进配对电耗。短中长途固定[0,10)/[10,50)/[50,+∞)km。温度来自行程室外均温，不是沿途序列；adequate需配对≥5趟且≥50km，sparse仅点读，不连成确定趋势。星期组本期只展示，没有星期evidence_filter，不能做伪全量下钻。分析筛选和证据列表共享规范化query与方法版本；游标保持原始请求边界，不能翻页时重新取now导致绑定变化。

**补能约束。** 0费用与null区分，已知支出不叫全部用车成本；两种有效均价采用各自同批分母，分类未知不归AC，DC占比沿已知分类分母。完成充电按结束日、行程按开始日，点日两组记录明确归期；记录时长不叫等待时间，AC不自动叫家充。缺失资源的展开指标也必须保留失败/快照标识，不能出现首页失败但明细无说明展示成功聚合。

**长期观察约束及差异。** range请求不接受from，按to前一微秒确定末月、向前包含6/12个本地月，缺省to由服务端截止；独立于首页本月窗口，partial标出未结束月。固定rated与battery_level，SOC20–90闭区间、额定续航>0且有限；同点值先会话中位、再本地结束日日值、再月P50/P10/P90。总体不平均月分位数。status在totals/各bucket读取，不假设顶层status；available仍可能sample_status=sparse（1–2有效日），不得画成可信连续趋势；≥3日才adequate。first_observed_scope=query，首次有效采样仅指当前查询窗口，不称全历史首次记录或新车基线。方法/阈值provisional；不输出SOH、容量、衰减%、等效循环或实际可开距离。

**停放约束及差异。** 只用服务端精确事件边界SOC、可靠里程构造的闭合窗口：≥1h且绝对里程差<1km，SOC与usable不混，负SOC变化表示下降，合法正/零变化保留。按window_start归期，闭合end可以晚于请求to但须已发生且≤as_of；不能裁切窗口后自行分摊百分点。总速率读取sum变化/sum有效小时×24，不平均窗口速率，不推算未来24h。端点缺失/事件或状态重叠等排除原因原样可核查；开放尾段不输出最终变化。online/asleep/offline/unknown分别展示，开放状态时长归unknown，不把离线算睡眠。部分状态覆盖窗口可有效且quality=partial_state_coverage；状态小时合计为observed_hours。汇总不随证据页改变，matched_windows包含排除及开放项，不当作有效窗口数。没有有效窗口为null，不显示0损耗；只观察这些窗口，不称全月停放耗能，不换算kWh或诊断哨兵/空调。

**加载与兼容。** 各资源及参照请求独立加载、失败、快照和重试，只有当前可见专题及必要摘要请求，不后台预取全历史。切车/站点/会话/时区/日期/筛选或恢复前台换日时隔离旧结果；换周期后选中日期必须在新查询范围内，不用查询外默认0。保持ETag/304、TTL及429既有边界；新弱ETag排除as_of，304复用已授权同查询快照；规范化范围/方法变化重置游标与相关图形。无记录、全缺失、稀疏、不支持和旧快照各有可见状态。

## 2026-10-29 车主体验整体复核增量

本增量依据本轮用户提出的整体产品复核、已完成的现有接口范围内客户端优化，以及随后要求更新正式 Spec 的指令整理。继续使用已确认的湖畔视觉和四个主 Tab；既有 V01–V08、A01–A06、T17–T18 与 SI01–SI10 验收保持有效。涉及页面职责、概览配对电耗及覆盖、专题入口与阅读层级时，本增量优先于历史章节中将它们列为候选或未接入的描述；不改写其他历史验收结果。

### Problem Statement

车主在手机上需要快速理解自己的车辆和使用记录。即使已有较多接口和图表，如果概览、行程与统计重复展示总量，主结果和背景字段同等显眼，或者有价值的内容藏在深层入口，用户仍须自行拼接结论，难以判断哪些变化值得继续查看。

用户要求从特斯拉车主和专业产品经理视角复核：每个 Tab 应回答什么问题、突出哪些指标、图形如何符合直觉、哪些 TeslaMate 数据尚未被利用。参考 Grafana 的分析深度，同时保留适合手机的阅读与操作方式。可能的付费价值来自清楚、可信、可核查的体验；不能把“增加卡片数量”或技术验证成功当作付费意愿、产品成熟度和用户审美认可的证据。

### Solution

将全局阅读主线固定为“现在怎样 → 最近怎样使用 → 能量与钱去了哪里 → 长期发生什么变化 → 查看依据记录”。每个主要内容区围绕一个用户问题组织主结果、证据图、背景指标和下钻入口；不要求每个区块都重复四种元素，不增加仅供装饰的图形。

| 主入口 | 首要任务与焦点 | 后续内容和下钻 |
| --- | --- | --- |
| 概览 | 最近车况与近期变化；紧凑状态/SOC/带口径续航和采样时间，期间主数与可切换日趋势 | 配对电耗/样本覆盖、已知费用/有效均价、用车节奏/条件/长期专题直达、最近记录、车辆资料 |
| 行程 | 回顾出行、找记录；期间里程为主结果，紧凑日节奏后进入日期分组记录 | 路线地图、距离/时长/估算能量、SOC区间、历史参照、速度/电量/海拔过程及环境明细 |
| 充电 | 补能账本；已知费用及其覆盖为主结果，入电/有效均价/记录时长提供背景，日趋势提供证据 | AC/DC/未知、地点账目、筛选与全部记录；详情展示功率/SOC过程和其他已支持采样 |
| 统计 | 解释使用结构和长期变化；期间里程为主结果，配对电耗/已知支出为副读数，趋势和参照紧邻 | 总览/节奏/能耗/补能/长期；活跃日与分布、条件关联、费用结构、额定续航与停放窗口及证据 |

车辆仍从顶部切换，设置保持表单与必要状态反馈，不新增主 Tab。概览承担近况摘要和发现入口，统计承担任意期间的结构分析，行程/充电承担记录查找和单次回顾；同一指标共享定义，不在不同页面创建不同分母。

本期范围为现有已冻结 0.1/0.2/0.3 能力内的体验基线及其验收。OE01–OE06 保持独立后端交接，不以本次 Spec 更新将其自动转为已批准的全量实现或当前 Mobile 必须交付的接口。

### Implementation Decisions

**范围及兼容优先级。** 保留原有四 Tab、湖畔视觉、单站点多车辆和只读业务边界。本增量不修改已发布的能耗、费用或归期公式；通过现有能力声明选择准确的展示口径。初版 V01–V08、既有充电 CH01–CH05、统计洞察及本轮车主体验验收共同构成当前范围，重复指标复用定义，不重复建设后端聚合。

**能力门控。** 概览的元数据、summary、驾驶统计、充电统计和参照请求分别加载/缓存/恢复。配对电耗核对独立 statistics-insights-v1 能力族、最低0.3.0与driving_coverage；费用覆盖与配对有效入电均价核对 charging-experience-v1 能力声明，不凭服务版本字符串假定全部支持。旧站点使用已发布基础口径并明确标签；元数据失败可独立重试。声明支持但严格扩展响应缺必需字段时显示缺失/不兼容，不把旧净电耗或旧单价套上新名称。

**概览指标与比较。** 支持站点的主电耗和对应日桶趋势都取net_consumption_paired；总值不平均日桶比率。配对值、eligible_drives、denominator_distance_km、全里程、duration_known_min及有效趟数直接读取服务端。旧净/毛电耗以各自名称保留明细。比较沿用已有同车、IANA日历、期间进度、bucket、range_kind、方法/版本及两期sample_status=adequate检查，不能用覆盖不足、方法不同、查询错位或旧比较快照输出有效差异。合法零基期可读原值和允许的绝对差，不输出相对百分比；月长/DST无法对齐时不强行比较。比较数值与短质量提示可见，具体query/as_of进入展开层；as_of不称车辆采样时间，两端点不宣称原子快照。

**费用与有效均价。** 费用有记录的会话数、匹配会话总数、对应入电与unit_cost_added直接取服务端；次数覆盖仅表达记录次数比例，不叫金额覆盖率或费用完整度估计。均价用其配对有效集，不能用已知费用总数除以全部入电。已知支出不叫总养车成本；未记录用中性提示，0金额保留。电网侧能量与入电能量分别命名，不相加，不直接推导损耗；AC/DC/未知保持分类，AC不叫家充。

**直达与期间。** 概览直达节奏/条件分析时保留所选车辆、本月/近7天对应的本地日历起止和IANA时区；独立长期续航仍使用其冻结6/12月窗口，不伪称与首页区间相同。进入专题才读取所需分析，不预取所有专题。默认统计入口恢复总览及默认期间；用户在统计内显式切专题保留当前选择。旧站点从概览进入基础充电统计仍须有可见日期控件，不能只显示失去期间选择的专题内容。

**信息层级。** 概览保留车况、期间主数与实际趋势的首屏关系。行程以期间里程为主、记录路线/地点和距离/时长为一级，估算能量/电耗为次级；详情路线地图与过程在环境/极值长明细之前。充电以已知支出/覆盖为期间焦点，以补入电池能量、SOC、费用为单次焦点。统计以期间里程与主图为主，记录驾驶时长、已完成/进行中趟数、估算能量和能量有效里程补足背景；本期/参照的精确选点读数必须紧邻主图，背景卡片置后。最高速度、峰值功率保留查询入口，不作为首页成绩或鼓励极值的重点。

**视觉及图形正确性。** 每区块一个焦点，数字/单位/口径有层级，使用等宽数字特性；金额或长单位允许重排。两列指标按实际容器宽度布局，200%字号可单列；不能靠缩小文字或横向裁切塞入。360×800/100%时概览与统计可见实际绘图区，行程可见日节奏与首条可点击记录，详情短摘要后进入地图或曲线。趋势、分类和过程采用适合问题的真实图形；零基线、单位、图例、负值/缺失/单点等沿A03。参照采用琥珀配线型/描边，不只靠颜色。色彩不暗示里程多或费用少一定更好。长技术说明进入帮助/展开层，但估算、已知费用、非实时、缺失和样本不足紧邻受影响结果。

**科学解释边界。** 温度与电耗仅为条件关联，显示样本量、有效里程和单程距离等背景，不输出因果、最佳温度或驾驶评分。长期额定续航为固定方法的记录观察，不叫SOH、真实可达距离或新车衰减；停放SOC只代表有效观测窗口，保留正/负/零变化、四类状态和排除证据，不推断哨兵/空调耗能。历史均值不当采样过程，分页或降采样点不当完整聚合输入。

**状态与性能。** 切车、站点、会话、时区、日期或换日前台校验时隔离旧响应；分页固定原查询边界。真实0、null、无记录、稀疏、不支持、旧快照和失败各自表达。基础区域不因扩展能力或某专题失败失去阅读，旧快照保留原查询和校验信息；独立重试维持既有TTL、ETag/304和429边界，不新增后台轮询。summary/标题出现不能代替主要趋势实际可读的性能终点；既有设备性能预算不因本轮本地构建通过而宣告达标。

## 2026-10-30 C「数据拼贴」视觉重构增量

2026-10-30 已确认并发布；本增量追加于 Spec #1 与本地镜像，保留 `ready-for-agent`。未修改代码、未创建或关闭 tickets。

### Problem Statement

在本次增量之前，Spec #1 的正式视觉仍是 A「湖畔」：紧凑车况、期间主数、主图和记录以接近同权的卡片纵向排列。实际渲染暴露出的问题不是数据不足，而是页面缺少唯一主角：车况、月度里程、净电耗、费用、AC/DC、最近记录和口径说明都在用相近的音量说话；技术元数据进入首屏；统计页先出现五个等权 tab；结论常常藏在一行小字里。用户因此觉得页面“太素、平铺、没有重心”。

用户在评审 A/B/C 三套方向后明确选择 **C「数据拼贴」**：沿用湖畔绿白/深绿与琥珀比较色，但用大小不同的 tile、深色主 tile、纸面图 tile 和满幅图重建阅读节奏。C 要解决的是**层级与阅读顺序**，不是增加指标、改变口径或重做产品范围。

### Solution

C 把每个页面固定为“**一个主导 tile + 一组证据 + 一个下钻**”：

- **概览**：深色车况主 tile（SOC、额定续航、状态、今日摘要）→ 本月里程最大 tile + 同期变化 → 净电耗/费用辅助 tile → 满幅每日趋势 → 一条洞察 → 最近行程/充电 → 四个章节入口。
- **行程**：期间里程主 tile → 紧凑节奏图 → 最近一条路线 tile + 日期分组记录；详情以满幅地图开场。
- **充电**：已知费用与覆盖主 tile → 入电/时长辅助 tile → 满幅每日补能 → AC/DC/未知构成 → 地点账目 → 最近一次充电；详情以 SOC 电池弧 + 功率曲线开场。
- **统计**：结论 tile + 本期/参照主图 → 2×2 章节卡（节奏/能耗/补能/长期）→ 独立专题页；不再让五个等权 tab 占据首屏。
- **技术口径**：归期时区、完整采样定义、车辆资料进入“数据说明/更多”；主路径只保留“非实时、估算、已知费用、覆盖不足、进行中”等会影响判断的短提示。

C 仍使用四个主 Tab、单站点多车辆、现有只读 API、现有地图/曲线和现有空/缺失/失败语义。它取代 A 的版面与视觉验收，但不取代湖畔配色语义，也不改变 V01–V08 的能力范围。

### User Stories

1. 作为车主，我希望打开概览时第一眼先看到车况，而不是一屏等权卡片，以便快速确认车现在怎样。
2. 作为车主，我希望本月的里程成为页面上最大的数据 tile，以便知道这段时间用了多少车。
3. 作为车主，我希望 tile 的大小和颜色表达主次，而不是所有内容都长成同一张卡，以便视线有明确落点。
4. 作为车主，我希望在首屏看到实际绘图区，而不只是标题或占位，以便确认趋势真的存在。
5. 作为车主，我希望主图上的当前值、参照线和读数清楚，以便把图形当作证据而不是装饰。
6. 作为车主，我希望本月主数旁有同口径的同期变化，以便知道“多开了还是少开了”。
7. 作为车主，我希望最近行程/充电以带路线缩略图或 SOC 条的 tile 出现，以便从概览直接进入一次回顾。
8. 作为车主，我希望行程页先给期间里程，再用紧凑节奏图帮助找日期，以便不被大段摘要推到记录之后。
9. 作为车主，我希望行程记录以起终点为主标题、距离为主数，以便快速辨认一段路。
10. 作为车主，我希望最新或最长的一条记录有明确强调，其余记录保持安静，以便页面有重点但不丢记录入口。
11. 作为车主，我希望行程详情用地图开场，再给结果和过程曲线，以便先回忆路线再看数据。
12. 作为车主，我希望充电页以已知费用和费用覆盖为主结果，以便知道花了多少、账目缺不缺。
13. 作为车主，我希望 AC/DC/未知和地点账目作为第二层结构，而不是和费用主数争夺首屏。
14. 作为车主，我希望充电详情用 SOC 电池弧和功率曲线开场，以便先看补能结果和过程。
15. 作为车主，我希望统计页先给一句结论和一个主图，而不是五个等权 tab，以便先读懂这段时间的变化。
16. 作为车主，我希望统计的节奏、能耗、补能、长期以 2×2 章节卡出现，以便知道还能往哪里看。
17. 作为车主，我希望点章节卡进入独立专题页，并在详情里保留期间和车辆，以便不丢失上下文。
18. 作为车主，我希望专题页只回答一个问题，而不是继续堆同权卡片，以便阅读有终点。
19. 作为车主，我希望归期时区、完整采样口径和车辆资料放在“数据说明/更多”，以便主路径先读结果。
20. 作为车主，我希望“非实时、估算、已知费用、覆盖不足、进行中”这些影响判断的短提示仍紧邻结果，以便不因收起说明而误读。
21. 作为车主，我希望 200% 字号时 bento 改为单列、主数和单位仍可见，以便大字用户不需要横向滚动。
22. 作为车主，我希望浅色和深色都保留同一个主 tile 和同一套图表语义，以便主题切换不改变阅读顺序。
23. 作为车主，我希望空数据、部分缺失、局部失败和真实 0 分别呈现，以便不把未知当作零、不把空态画成全零趋势。
24. 作为车主，我希望 C 不重算服务端总计或比率，以便视觉重构不改变数据可信度。
25. 作为车主，我希望旧 A 的截图不再被当作 C 的视觉通过证据，以便验收对应当前设计。
26. 作为车主，我希望现有四 Tab、车辆切换、详情下钻和外部待验边界保持不变，以便视觉重构不扩大范围。
27. 作为车主，我希望 C 的每个页面都只有一个主导 tile，避免拼贴再次退化成“更多卡片”。
28. 作为车主，我希望统计章节卡仍覆盖原有的节奏、能耗、补能、长期能力，以便改版不丢失任何指标入口。

### Implementation Decisions

**方向与范围。** C 是湖畔配色下的版面/层级重基线。保留浅色暖雾底、纸白、深墨绿、湖绿、薄荷、琥珀比较色及深色对应 token；保留四 Tab、车辆切换、概览/行程/充电/统计、两类详情、地图/曲线、分页、条件缓存、空/缺失/失败和只读边界。C 只改变页面编排、tile 体系、字体层级和统计导航，不新增或删除 V01–V08 的数据能力。

**页面蓝图与唯一主角。**

| 页面 | 主导 tile / 主结果 | 第二层 | 下移或折叠 | 下钻 |
| --- | --- | --- | --- | --- |
| 概览 | 深色车况：SOC、额定续航、状态、今日摘要 | 本月里程最大 tile、同期变化、净电耗/费用辅助 tile、满幅日趋势 | 独立驾驶消耗/补能账本大卡、时区/采样/车辆资料 | 最近行程/充电、四章节 |
| 行程 | 期间里程 tile | 紧凑出行节奏、日起点、最新路线 tile | 长摘要、最高速度等次级指标 | 日期记录、单次详情 |
| 充电 | 已知费用 + 费用覆盖 tile | 入电/时长、每日补能、AC/DC/未知、地点账目 | 记录时长、均价等口径长说明 | 最近充电、单次详情 |
| 统计 | 结论 + 同期变化 | 本期/参照主图 | 五个等权 tab、长指标清单 | 2×2 章节卡 → 专题页 |
| 行程详情 | 满幅地图 | 距离/时长/电耗、SOC 区间、参照 | 环境、更多指标、原始采样 | 速度/电量/海拔曲线 |
| 充电详情 | SOC 电池弧 + 功率曲线 | 充入能量、费用、时长 | 电网侧/能量、温度、相数 | 功率/电量切换 |
| 统计专题 | 一个主数 + 一张主图 | 一组证据数字 | 其他专题 | 返回统计 |

**Bento 栅格与层级。**

- 360 逻辑宽度下使用 12px 页面边距、7–8px tile 间距、18–22px 圆角；主 tile 和主图可满幅，其余最多 2 列。
- 每屏只有一个**主导 tile**；其他深色 tile 必须明显更小或更安静，不能与主 tile 同权。禁止“所有 tile 一样大”的拼贴。
- 默认不嵌套卡片；tile 内部用分隔线、留白和字号分层，不再套一层白卡。
- 200% 字号时 bento 强制单列；主数、单位、图表和说明不得横向裁切；允许纵向滚动。
- 360×800、100% 字号的概览首屏必须露出车况主 tile、本月主数和实际趋势绘图区；统计首屏必须露出结论、主图和第一个章节入口；行程首屏必须露出期间主数、节奏和第一条可点击记录；详情摘要后进入地图或曲线。
- 不用装饰性图形替代数据；颜色只用于聚焦和系列区分，不用红绿暗示“开得多/花得少就是好”。

**颜色与字体 token（语义）。**

| 语义 | 浅色 | 深色 |
| --- | --- | --- |
| 页面底 | 暖雾 `#E9EFE6` | 深林 `#09140F` |
| 纸面 tile | `#FBFDF9` | `#12231A` |
| 主墨 | `#142019` | `#EEF7EF` |
| 深色主 tile | `#0B2A20` | `#06140F` 加湖绿径向光 |
| 主湖绿 | `#2F7D58` | `#8AD6AF` |
| 薄荷辅助 | `#D4F0DC` | `#1E3B2C` |
| 沙色辅助 | `#F2E2C6` | `#3B3120` |
| 琥珀比较 | `#B9813D` | `#E1B779` |

- 数字使用等宽数字特性（tabular numerals）；每屏最多 4 个字号层级：44–56 主数、28–36 次主数、13–16 标题、8–10 标签。
- 中文正文使用系统黑体；不引入新字体依赖。单位、口径、时间比数字小两级。
- 金额、长单位允许换行；200% 字号允许 tile 内部纵向重排。

**图表规则。**

- 主图必须有时间范围、单位、当前点、可点读；柱图从 0 起，当前柱实色，其他柱降为低透明度；参照用琥珀虚线/描边，不能只靠颜色。
- 净电耗/均价等比率图允许局部轴，但必须显示刻度和单位；缺失断开，不补点、不补零。
- 概览当前值、统计本期/参照、详情个人参照必须紧邻图形，不能隔着背景卡。
- 对比图同单位同尺度；不默认双轴；不把 AC+DC 归一成全部能量饼图。
- 空态不画全零趋势；真实 0 保留；单点、全缺失、稀疏点分别呈现。

**地图规则。**

- 行程详情使用满幅地图作为第一视觉；充电详情使用地点图 + SOC 电池弧/功率曲线。地图可缩放、可显示起终点与采样路线；不是导航。
- 底图失败仍保留结果、SOC、曲线和文字；无坐标/单点按现有语义处理。
- 真实底图、供应商、坐标参考系和网络验收沿用现有待验边界；原型合成路线不能作为正式底图证据。
- 不新增地图供应商或切换 UI；不向底图发送站点 token。

**统计导航。**

- 当前五个等权 tab（总览/节奏/能耗/补能/长期）不再作为统计首屏的等权导航。
- 统计默认首页 = 总览：期间选择 → 结论 + 同期变化 → 本期/参照主图 → 2×2 章节卡（节奏/能耗/补能/长期）。
- 点击章节卡进入独立专题页；专题页保留当前车辆、期间和 IANA 时区，返回时恢复统计首页的期间选择。
- “总览”仍是默认入口；已有直达链接/测试若指向旧 tab，必须映射到对应专题页或默认首页，不能保留第二套等权导航。
- 章节卡必须覆盖原有节奏、能耗、补能、长期能力；原有 V06–V08 的图表和 totals 入口不能因改版丢失。
- 具体路由/组件拆分不在本 Spec 固定；实施时以现有导航和缓存边界为准，不新增后端请求。

**详情与口径。**

- 行程详情：地图 → 起终点/时间标题 → 距离/时长/净电耗结果 → 速度/电量/海拔曲线 → SOC 区间与温度/环境指标 → 底部的个人历史参照口径行。（2026-10-31 用户裁定：本节原写「SOC 区间与个人参照 → 曲线」，与已确认的 `C-drive-detail-light.png` 渲染相反，按渲染更正；口径行沿用 C 原型的单行脚注。）
- 充电详情：地点 → SOC 电池弧 → 充入能量/费用/时长 → 功率/电量曲线 → 电网侧/入电并列 → 环境与原始明细。
- 归期时区、完整采样定义、车辆资料进入“数据说明/更多”层；主路径保留非实时、估算、已知费用、覆盖不足、进行中短提示。
- 不把时区、逐点采样数、完整车辆资料重新放回首屏；不隐藏会影响判断的短提示。

**状态与数据边界。**

- 空数据、部分缺失、真实 0、null、局部失败、旧快照分别呈现；不从有限摘要补全。
- 切换车辆/站点/会话/时区/日期时隔离旧响应；分页和缓存沿现有条件请求、ETag/304、TTL、429 边界。
- 不新增后台轮询、秒级刷新或前端全量聚合；不改变净/毛电耗、费用、均价、AC/DC 占比、续航口径。
- 数据/API 能力仍以冻结 0.3.0 实际契约为准；声明支持但字段缺失时显示缺失/不兼容，不套用旧值。

### Testing Decisions

**测试缝（已确认）。** 行为继续使用现有最高层 **App + 可控 HTTP** 集成缝；视觉继续使用现有 **360×800 实际 Flutter 渲染**入口，不新增逐 DTO、私有 widget 或 SQL 测试缝。C 的 tile/章节卡不是新的业务层；不为它们建独立服务或状态机。若实施中确需新的视觉 seam，优先扩展现有 opt-in 渲染入口，而不是新增一套组件测试框架。

**好测试的标准。** 只断言用户可观察的行为：固定时钟/时区下的请求范围、选车/期间/指标/选点、可见主数、图形、空/缺失/失败状态；视觉断言检查 tile 主次、首屏绘图区、单位/读数、无重叠裁切、浅深色/200% 重排。不按实现复写公式，不以内部调用次数或单纯截图快照作为正确性依据。数据正确性和视觉评审分开记录。

**新增验收（C01–C10）。**

- [ ] C01 页面唯一主角：概览、行程、充电、统计、两类详情和专题页各只有一个主导 tile/主结果；没有同权 tile 网格。
- [ ] C02 首屏层级：360×800/100% 下，概览露出车况主 tile、本月主数和实际绘图区；统计露出结论、主图和首个章节入口；行程露出期间主数、节奏和第一条可点击记录；详情摘要后进入地图/曲线。
- [ ] C03 统计章节导航：五个等权 tab 不再占据首屏；2×2 章节卡可进入节奏/能耗/补能/长期专题；期间、车辆、时区保持；旧直达路径映射到专题或默认首页。
- [ ] C04 主图正确性：柱图零基线、当前柱/参照线/选点读数、单位和时间范围与原始值一致；null 断开，不补零。
- [ ] C05 详情主视觉：行程地图、充电 SOC 电池弧/功率曲线在结果之前出现；地图/曲线失败仍保留结果和文字。
- [ ] C06 技术口径：完整时区/采样/车辆资料在说明层；主路径仍有非实时、估算、已知费用、覆盖不足、进行中短提示。
- [ ] C07 状态：正常/空/部分缺失/单点/全缺失/局部失败/旧快照/真实 0；空态不画全零趋势；缺失不补零。
- [ ] C08 可访问性：360×800、200% 字号、浅/深色；200% 单列，主数和单位可见，无横向滚动/遮挡；语义包含图表读数。
- [ ] C09 数据边界：C 不改变 totals/比率/费用/AC-DC/续航口径；不从分页补算，不新增 API，不改变 304/TTL/429/切车隔离。
- [ ] C10 证据：保存 C 的浅/深色、100%/200%、空/缺失实际 Flutter 渲染、来源指纹和用户视觉评审；旧 A 渲染不计入 C 验收。

**A01–A06 映射。**

| 原验收 | C 下的通过条件 |
| --- | --- |
| A01 指标覆盖 | V01–V08 每个指标仍有 C 的 tile/章节/图入口；不因改版丢失；G01–G08 缺口不变 |
| A02 首屏与层级 | 按 C02 的页面顺序；不再用 A 的“紧凑车况→四卡→主图”作为唯一顺序 |
| A03 图形正确性 | 按 C04；选点/切指标/区间对应原值，图形不为拼贴装饰 |
| A04 状态与可访问性 | 按 C07/C08；空/缺失/失败/200%/浅深色保留图和等价读数 |
| A05 好看、好用 | 以 C 的浅深色代表页面和新用户评审为准；旧 A 的 A05 证据保留为历史，不替代 C |
| A06 口径与性能 | 数据口径不变；C 首屏主图和详情默认曲线的实际可读仍计入原性能预算 |

**旧 A 证据。** 已有 A 的 32/40 张渲染、旧 A05 评审和旧首屏截图继续作为历史证据保留，但不再作为 C 的视觉通过证据。C 需要新的代表页面渲染、来源指纹和用户评审；双端真机、真实站点、Grafana 对账、地图外部条件和性能仍按原边界待验。

### Out of Scope

- 不修改数据口径、API、后端、Mileaf Server、TeslaMate、数据库、认证或只读外部仓库。
- 不新增 OE01–OE06 后端能力，不以假数据或前端推算填充缺失能力。
- 不重做登录/连接/设置页；只处理四个业务 Tab、两类详情和统计专题。
- 不新增车辆控制、Tesla 凭据接入、多车对比、秒级刷新、自动诊断、驾驶评分、SOH/衰减、停车耗能归因、税务或运维页面。
- 不新增地图供应商/切换 UI/坐标转换规则；真实底图与坐标验收沿用既有待验边界。
- 不新增设计系统依赖、字体依赖、图表库或插件架构；C 使用现有 Flutter 组件与自绘图表。
- 不新增手动主题切换；继续跟随系统浅/深色。
- 不在本增量重开 A/B/C 方向选择；C 已由 ADR 0001 确认。
- 不在本 Spec 创建平行 ticket 树；不重复 V01–V08 能力票。

## 2026-10-31 地图双端接入增量

### Problem Statement

C 的行程/充电详情已经把地图放到首屏或次级视觉，但正式底图一直空缺：`CandidateMap` 只接受未配置的 XYZ 模板，没有 provider 时显示“地图暂不可用”。Android 高德 key 不能直接作为瓦片 URL，iOS 又需要单独的 key；只做 Android 会违背双端应用。

### Solution

采用共享 Dart 地图外壳 + 平台适配器：

- Android：`AndroidView` + Kotlin `TextureMapView` + 高德 Android SDK 11.3.100；
- iOS：`UiKitView` + MapKit（Apple 地图）作为没有 iOS key 时的过渡；拿到 iOS key 后新增 `AmapIosPlatform`，页面/测试不变；
- 行程详情首屏静态 hero + 点按全屏交互；充电详情地图放在功率曲线之后，作为次级视觉；
- 地图失败/未同意/无坐标时使用路线速写，不遮挡结果；
- WGS84→GCJ-02 只在地图边界转换；不申请定位权限、不向地图传站点 token。
- 本增量取代 C 增量中“不新增地图供应商/坐标转换规则”的范围限制；C 版面、配色、层级不变，仍不做供应商切换 UI。

### Testing Decisions

- 行为继续使用 App + 可控 HTTP；新增 `MapPlatform` 平台边界缝，测试用 `FakeMapPlatform`，不建原生视图。
- `Gcj02`、`MapScene` 分段、同意、15 秒失败、重试、空场景由纯 Dart/Widget 测试覆盖。
- 真实高德/MapKit 渲染只由真机/模拟器或 iOS 构建证明；透明测试瓦片和路线速写不能冒充真实底图。
- 运行证据见 `docs/implementation/amap-map.md`。

### Out of Scope

- 不实现 iOS 高德 key 申请、AMap iOS 适配器、App Store IDFA/隐私清单。
- 不新增供应商切换 UI、导航、GPS、离线地图、概览/统计/列表地图。
- 不修改数据口径、API、后端、外部仓库。
- 不因为本地实现/构建通过而关闭 #4/#11 或宣称双端高德完成。
