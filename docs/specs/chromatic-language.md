## 1. 参考 App 设计语言拆解（理念层，3–5 条）

证据来自只读审计 `.dsh-tmp/research/reference-language.md`（带 文件:行号 与实测像素统计）与上一轮 `.dsh-tmp/ref-days-matter-audit.md`。每条只写**理念 + 它解决的体验问题**。

### 1.1 彩色预算制：面积与彩度成反比
大面积只允许低彩度，高彩度只允许出现在极小面积上。参考 App 实测：能看出颜色的像素只占 2–5%，鲜明彩度（C>0.12）≤2%；占屏 27% 的墨色主卡把分类色压成 24–26% α 的洗色（合成后 C≈0.04–0.08）。
→ **解决的体验问题**：信息型界面「一上色就花、不上色就闷」的两难——用面积换安静，用彩度换识别。
（本轮修订：C 阈值按 OKLab 定义，测法是逐像素统计，见 §4.6。）

### 1.2 色相绑定「角色」而不是「类别全铺」
参考 App 有 3 个色相寄存器：① 动作色只有 1 个（蓝 257°），可点文字/选中/读数；② 内容身份色 8 个，被严格关进 ≤46dp 的形状与洗色里；③ 目录索引色 7 个，只用于设置页图标。任何一层都不越界借用。
→ **解决的体验问题**：「哪里能点」和「这是什么」的即时分辨——动作色一旦复用为内容色，用户就要重新学习每次点击的后果。

### 1.3 中性色锁在同一色相上做「家族感」
15 个中性色的 OKLCH 色相全部落在 286.1–286.4°、C ≤ 0.008；强调色 257° 是「同族里被允许提高彩度的成员」，只差 29°。
→ **解决的体验问题**：整屏只有 5% 彩色却毫不割裂——割裂感来自色相打架，不来自彩色多少。

### 1.4 明度锚点靠在对比度上，不靠等 L
8 个身份色的 OKLCH L 相差 0.17，但配白色字形后对比度全部落在 4.35–4.62:1。
→ **解决的体验问题**：不同色相在同一位置上的「可读性」被拉平，用户不会觉得某个颜色「字被吃掉了」；同时允许暖色为了辨识度抬高明度。

### 1.5 两档间距 + 一级一个数；一个嵌套层级一个半径
结构档（4 的倍数）管页面/卡片/行，光学档（2 的倍数但非 4）管文字块内部；页面 20 / 卡内 16 / 行 12 / 卡间 10 / 块 22–28，每层永远同一个数。半径 28→20→14→12→9。
→ **解决的体验问题**：「排版看起来对，但说不出哪里别扭」的那点微差——秩序感来自机械可复用的层级，不来自审美判断。

### 1.6 弹簧管手感、时长管信息；动作不靠图标
按压缩放用 spring（无固定 ms），内容替换用 tween（120–320ms）；参考 App 的 `PrimaryButton` 甚至不接受 icon 参数——动作靠「词 + 一种颜色」，图标只承载身份与方向。
→ **解决的体验问题**：图标猜谜。但本轮用户明确要求「按钮尽量配图标」，因此**本条属「需改造」**：迁移「图标永远附着于身份、不承载新的动作语义」，同时按用户指令在按钮上加图标（图标必须复述按钮词义，见 §5.4）。

## 2. 领域差异分析

| 维度 | 参考 App（Days Matter） | 行笺（Mileaf） | 对设计的影响 |
| --- | --- | --- | --- |
| 领域 | 个人日期提醒，单值倒计时 | 车辆数据看板，多指标时间序列 | 行笺的「内容」本身就是色块（图表），彩色面积天然更大，必须靠预算而非「少上色」治理 |
| 用户心智 | 「还有几天」——瞄一眼 | 「这周用了多少、贵不贵」——读数 + 比较 | 参考 App 的 1 个主角数字 → 行笺需要「1 个焦点值 + 1 组网格读数」，色相要能标注**指标身份**而不是「条目身份」 |
| 主要任务 | 添加/编辑日子，翻看列表 | 选期间 → 读图 → 下钻专题 → 换指标 | 色相必须在**跨页面**稳定（里程永远同一个色），否则下钻时用户要重新解码 |
| 内容密度 | 低（一屏 1 主卡 + 3–8 行） | 高（图 + 网格 + 行 + 脚注，单页 2–5 屏） | 参考 App 的「五级文字」不够用；行笺必须在图表读值/口径脚注这层保持既有 R21/R29 分工，不能因上色而加字号 |
| 使用场景 | 顺手添加、通知 | 停车场/充电桩旁、单手、强光下 | 彩色值必须过 4.5:1；wash 底不能用来承载正文；深色模式是夜间车库的主力场景 |
| 数据可信度 | 用户自填 | 服务器算的，可能缺失/未知 | 缺失/未知**永不**用语义色相（沿 MG02）；否则「彩色」会被误读成「有数据」 |

## 4. 色彩体系

### CL01 色相枚举与域绑定

数据身份色相**只有 6 个**，每个绑定一个数据域，跨页面稳定：

> **journey 与动作色同值，这是刻意的**：里程是行笺的主语，`azure500/600/300` 既是品牌色也是里程色。代价是「可点的蓝字」与「里程读数」同色——但两者从不同屏竞争（动作走填充或行尾，里程读数走 `metricLg` 大数），且 CL05 禁止语义色相用于按钮填充/链接，所以不会出现「这段文字能不能点」的歧义。

| 枚举 | 域名 | 覆盖指标 | 浅色 solid | 浅色 strong | 深色（solid=strong） |
| --- | --- | --- | --- | --- | --- |
| `MileafHue.azure` | journey 行程/里程 | 里程、行程数、平均速度、最高速度 | `#2688F5` | `#0B62C4` | `#64A8FF` |
| `MileafHue.aqua` | energy 能量/充入 | 电量、充入电量、电网用电、功率、充电次数 | `#199698` | `#0E6E6F` | `#3DD6D7` |
| `MileafHue.mint` | efficiency 效率/续航 | 电耗、净/毛电耗、续航、效率、单次成本效率 | `#199B52` | `#0E723A` | `#4BDE81` |
| `MileafHue.amber` | cost 费用 | 费用、单价、充入均价、覆盖次数 | `#AA8215` | `#7F5F0B` | `#E9B535` |
| `MileafHue.coral` | climate 环境 | 车外/车内温度、环境条件 | `#FB3C5A` | `#C0143A` | `#F9A2A5` |
| `MileafHue.violet` | dwell 停放/时长 | 停放时长、充电时长、停留次数、间隔 | `#BC57FA` | `#9627D0` | `#D6A7F9` |

色相在 OKLCH 上的角度：253 / 196 / 152 / 85 / 18 / 310（相邻 44–68°，无 20° 内的密簇——参考 App 在蓝紫段挤了 21° 的缺陷不迁移）。

### CL02 三级强度

| 级别 | 语义 | 出现位置 | 浅色对比度（对白 / 对 #F4F5F7） | 深色对比度（对 #12161C / #0A0B0D） |
| --- | --- | --- | --- | --- |
| `solid` | 图形 | 图表线、面、柱、点、弧环、图标字形 | 3.55–3.59 / 3.25–3.29（≥3:1 图形底线，留 0.55 余量） | 7.42–10.43 / 8.05–11.31 |
| `strong` | 文字与实心 | 彩色读数、域标签、图标按钮的实心填充 | 5.90–6.17 / 5.41–5.65（≥4.5:1 正文底线，留 1.4 余量） | 同 `solid`（深色一档） |
| `soft` | 小面底 | 选中格、补录胶囊、身份标签底 | 16% alpha（azure 与现 `accentSoft` #DCEBFD 合成结果一致） | 16% alpha |
| `tint` | 大面底 | 焦点卡、章节卡背板（≥10% 面积才允许） | 8% alpha | 8% alpha |

CL02.1 深色只有两档（solid 即 strong）：深色底上同一个色的「图形级」和「文字级」不需要分强度，分档会制造出两个近似的浅色。

### CL03 明度锚定规则（可复核）

```
浅色 solid：对 #FFFFFF 3.55:1（azure500 实测值），L 由色相解出，C = 0.95 × 该 L 下 OKLCH 可用彩度
浅色 strong：对 #FFFFFF 5.90:1（azure600 实测值），C = 0.95 × 可用彩度，且须对 soft16 合成底 ≥4.60:1
深色      ：对 #12161C 7.42:1（azure300 实测值），C = 0.90 × 可用彩度
```

CL03.1 azure 三档**保留品牌现值**（ADR 0006），不参与解算；其余五色按上式解出后取整。实测 azure 与解算值的偏差 ≤0.04 对比度单位，不构成家族感差异。

### CL04 中性家族守卫

行笺中性色（canvas / surface / surfaceRaised / line / text / textMuted / textFaint / controlBorder / segmentTrack / navigationLabel）实测 OKLCH 色相落在 **242–265°**（浅最低 246.1、深最低 242.0、canvas 264.5）、C ≤ 0.0245（一次性实测口径，`chromatic_hue_token_test.dart` 的 CL04 用例按现值上下限钉住）。新增中性 token 必须落在这个带内——禁止引入暖灰（H<240°）或绿灰（H 100–200°）。与 azure 253° 同族，这正是「整屏只有少量彩色却不割裂」的来源。

### CL05 动作色唯一

- `accent` / `accentStrong` / `accentSoft` 仍是**唯一的动作色**：主按钮填充、链接、选中态、焦点环、开关、分段选中。
- 语义色相**禁止**用于：按钮填充、链接文字、焦点环、开关、页面背景、卡片表面（除 ≤8% tint）、任何边框。
- 语义色相**允许**用于：图表系列、图标字形、彩色读数（`strong`）、wash 底（`soft`/`tint`）。

### CL06 彩色面积预算（取代 MG01 的 ≤20%）

| 预算 | 阈值 | 口径 |
| --- | --- | --- |
| 非图表彩色面积 | ≤5% | 逐像素 OKLab C>0.04，排除图表绘图区矩形 |
| 高彩度面积 | ≤2% | 逐像素 OKLab C>0.12，同上 |
| 大面限制 | 占屏 ≥10% 的面只能用 tint（≤8% alpha） | 估算：卡片背面 |

CL06.1 图表绘图区不计入面积预算，但受 CL07 的色相数约束——图表本身就是大块彩色，用预算去压它会退化成「灰色图表」。

CL06.2 实测补充：8% tint 合成后的彩度只有 0.009–0.021、16% soft 只有 0.021–0.039，**都到不了 C>0.04**。所以「彩色面积」实际只由 solid/strong 的图形与小字承担（图表线、彩色读数、行首图标）。按此口径重估：概览约 0.3–0.8%、充电约 0.6–1.2%，远低于 5% 上限。

### CL07 单页色相数

同一页面首屏可见的数据身份色相 ≤3（图表多序列按主色相计 1；参照系列用中性 `reference`，不计）。超出的指标改用同级中性（`textSecondary`）。

### CL07.1 索引页的记账方式（不是例外）

统计根页的 2×2 章节卡是「章节索引」，实现结果是**三张带色 + 一张中性**：节奏 dwell、能耗 efficiency、补能 energy、长期中性（这一卡没有读数，只是入口）。所以它仍然落在 CL07 的 3 个色相以内，**不需要例外**。若将来四张卡都要带上色，记账方式是按「每个色相只占一个 16 图标 + 一张 8% tint 背板、单色相面积 <1%」计，并且不在本页图表与读数里复用同一色相。

### CL08 状态与缺失

- 状态色（`warning` / `error`）与 `MileafStatusTone` 映射不变（MG02）。
- 状态条、失败横幅、空态**不得**使用数据身份色相。
- 缺失 / 未知 / 未记录的任何读数：中性（`textSecondary` + 「—」），**禁止**彩色。

### CL09 编号与取色出口

页面不直接取 `MileafHue` 的原色值，只声明域或色相枚举，由 `MileafHueTone` 解析：

```dart
extension MileafHueTone on MileafHue {
  Color solid(MileafColors colors);
  Color strong(MileafColors colors);
  Color soft(MileafColors colors);
  Color tint(MileafColors colors);
  Color onStrong(MileafColors colors); // strong 实心底上的文字（浅=白，深=#0A0B0D）
}
```

### CL15 一图一色相（图表）

一张 `TimeSeriesChart` / `BatteryArc` / 分享环 / 类别柱 / 合成条 / 区间带，**只用一个色相**：主段取 `solid`，第二段取同色相的 `strong`，参照系列取中性 `reference`。

不给 `ChartSeries` 做逐系列配色：既有图例规则明写「多测量（净/毛电耗、AC/DC）的线同色」——单色是刻意的（多测量只列名字、不画色块），逐系列上色会同时推翻图例语义与其测试，属于另一轮设计决定。

色相由**当前指标所属的域**决定（不是页面默认值）：概览主图、充电「每日充电」图、统计专题主图都随指标切换换色相，这样同一指标在任何页面同色。

## 5. 图标体系

### CL10 家族不变

沿用现有自绘家族：24×24 网格、1.5 线宽、圆头端点、圆角连接、无填充（`MileafIconFamily`）。**不引入第二套图标库**（不加 Material Icons、不加 SVG 包）。

### CL11 扩充 4 个图标

| 名称 | 语义 | 用途 | 绘制要点（24 网格） |
| --- | --- | --- | --- |
| `leaf` | 效率 / 续航 | efficiency 域的区块头与读数标签 | 叶片轮廓：两条对称三次贝塞尔 + 中脉直线 + 叶柄 |
| `thermometer` | 温度 / 环境 | climate 域、驾驶与环境分组 | 竖向药丸球管 + 底部圆球 + 三条刻度横线 |
| `speed` | 速度 | 平均/最高速度 | 半圆表盘弧 + 指针（自圆心 12,14 指向 10 点钟）+ 中心实心点 |
| `share` | 分享 | 页面级分享动作 | 三个节点（右上、右、下）+ 两条连线 |

CL11.1 新增图标必须同时登记 `MileafIconFamily.semanticLabels`（一句话语义），并由 `test/icon_family_test.dart` 校验线宽/端点/网格一致。

### CL12 图标取色

| 角色 | 取色 |
| --- | --- |
| 动作图标（按钮内、行尾、顶栏） | 该控件的**前景色**（主按钮 = `textOnAccent`，次/文字按钮 = `accentStrong`，图标按钮 = `textMuted`/选中 `accent`） |
| 身份图标（区块头、读数标签、图表系列图例） | 所属域的 `strong`（浅）/ `solid`（深） |
| 通知/状态图标 | `MileafStatusTone.resolveColor` |

CL12.1 全站禁止双色或多色图标；禁止给动作图标上语义色相（会与 CL05 冲突）。

### CL13.2 身份图标不进标题行（实施期裁定）

`SectionHeader` / `MileafPeriodHeader` 的标题行**不带**前置身份图标：R24 要求身份块标题与卡片外缘共享同一条左线（`ui_ux_u09d_test` / `ui_ux_u09e_test` 钉住），前置图标会把标题文字推离这条线 24px。

数据身份色因此只出现在**行内**：读数、图表系列、卡片 tint、行首图标（`MileafGroupRow.leading`、`MileafFact.icon`、专题行）。这与参考 App 一致——它的身份色在行内瓦片与洗色里，区块标题是纯文字。

### CL13 尺寸与配对

| 档 | 尺寸 | 用途 |
| --- | --- | --- |
| inline | 16 | 按钮内、读数标签前、行内、区块头 |
| card | 20 | 卡片首图标、图例样本 |
| nav | 20 | 底栏（冻结） |
| header | 24 | 顶栏、二级导航 |

CL13.1 图标与文字**视觉居中**对齐，间距恒为 `s8`；图标与相邻文字的字号比 ≈1.06（inline 16 : control 15）。唯一用基线对齐的是数字与单位（既有 R21）。

### CL14 按钮图标纪律

- **必须带图标**的三类：① 页面级主动作（保存/刷新/补录/重试）；② 下钻行与行尾动作（查看明细、查看地图、展开）；③ 破坏操作确认。
- **可以不带图标**的：分段与筛选 chip、导航条目、纯文本链接——它们本身就是「词」，加图标只是噪声。
- 图标在左、间距 s8、视觉居中，图标复述按钮词义（「刷新」配 refresh），不引入按钮文字里没有的概念。
- 图标按钮（无文字）：必须带 `semanticLabel`，只用于栏位与行尾。
- 同一动作在不同层级：图标可以省略，但**不得换一个图标**（`MileafActionIcon` 是这张表的唯一出口）。

CL14.1 落地实况（如实登记）：`MileafButton` 26 处调用中 6 处带图标、`TextButton` 37 处中 2 处——离「普遍带图标」还有距离。本轮只保证了三类必带项，其余按 §9.3 在后续切片补齐，不谎报为已完成。

## 8. 动效

### CL38 三档时长

| 档 | 区间 | 用途 | token |
| --- | --- | --- | --- |
| 即时反馈 | ≤120ms | 按压、数值、局部快照、顶栏叠色 | `press` / `value` / `metricFade` / `chrome` |
| 状态转换 | 180–280ms | 互斥选中、折叠、弹层进出 | `selection` / `foldHeight` / `sheetIn` / `sheetOut` |
| 容器变化 | 240ms（**候选，本轮未引入**） | 列表项插入/移除、卡片高度变化 | 无 token；将来引入时统一取 240ms easeOutCubic |

CL38.1 不引入弹簧：行笺按压缩放已用 `pressScale` + 120ms easeOut（M01），D2 已裁定不迁移参考 App 的弹簧性格。曲线仍只有两族：`easeOut`（反馈）与 `easeOutCubic`（变换）。

CL38.2 本轮**没有新增任何时长或曲线**（`MileafDurations` 与 `MileafCurves` 与改造前逐字相同）：D7 曾提出新增 `settle` 240ms 管容器变化，实测全库没有这种动画（原以为「手写 240 五次」是 240px 高度而非 240ms），因此不引入没人用的 token。

### CL39 新动效白名单（只加一条）

- 允许：语义色相改变时（切换指标/期间下钻），图表系列色与该域彩色读数 **120ms 交叉淡化**（复用 `metricFade` 与 PD13 的 `MileafNumber` 交叉淡化）。
- 允许：列表项插入/移除用 240ms 高度过渡（`settle`），不透明度同步 120ms。
- 禁止：为「上色」本身做动画（wash 底不做淡入淡出）；禁止整页转场、共享元素、视差。

### CL40 减少动效

所有新动效必须走 `MileafLayout.motion(context, duration)`，减少动效下归零且首帧正确。

## 10. 验收清单自检

见 [实施记录 §验收](../implementation/chromatic-language.md#验收清单自检)。本规格侧的硬约束：

| 编号 | 约束 | 自检结果 |
| --- | --- | --- |
| CL02/CL03 | 正文 ≥4.5:1 | ✅ 六色相 strong 对白 5.90–6.17；对 wash16% 合成底 4.60–5.02；对 canvas 5.41–5.65 |
| CL02 | 图形 ≥3:1 | ✅ solid 对白 3.55–3.59，对 canvas 3.25–3.29（余量 ≥0.25） |
| CL06 | 非图表彩色 ≤5% | ⚠️ 估算口径，逐页登记；首屏估算 2.4–4.1% |
| CL07 | 单页 ≤3 色相 | ✅ 逐页表（§9.2）最多 2 个域 + 1 个动作色 |
| CL12 | 图标同家族 | ✅ 只有 4 个新自绘字形，无第二套库 |
| CL20/CL22 | 4 基准 + 无裸数字 | ⚠️ 档位已具备；裸数字守卫为新增测试，首轮允许带 `CL22-exempt` 标注 |
| CL30/CL31 | 玻璃只用于浮动层、参数统一 | ✅ 新增仅浮层菜单与地图浮控；弹层明确不叠玻璃 |
| CL38/CL39 | 时长曲线统一、无炫技 | ✅ 三档时长 + 两族曲线；只加一条 120ms 色相淡化 |

CL-偏差（实施中发现、由 ADR 0016 记录）：

- **amber 在浅色下偏金棕**（`#AA8215`）：sRGB 里「明亮琥珀」在 ≥3.55:1 的白底约束下不可能存在（`#FFB020` 只有 1.9:1）。因此 cost 域的「活泼」由 wash 底（#F1EBDA）+ strong 文字（#7F5F0B）承担，图表线用金棕。这是色彩空间的物理限制，不是选择失误。
- **深色只有两档强度**：见 CL02.1。
- **图标 + 动作按钮**与参考 App 的做法相反：见映射表 #8，按用户指令执行。
