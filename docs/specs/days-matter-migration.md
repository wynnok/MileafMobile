# 参考设计语言理念迁移规格（Days Matter → 行笺）

> 2026-11-19，状态 **accepted**（D1–D4 已确认，见 ADR0015 确认记录）。本规格只迁移理念层，不迁移元素层；全部取值改造基于行笺现行 token 体系（appearance v2 / R21–R32 / L01–L12），不从参考 App 抄任何数值。证据引用格式 `文件:行号`，参考 App 路径相对 `days-matter-android/app/src/main`，行笺路径相对仓库根。配套：[ADR0015](../adr/0015-days-matter-language-migration.md)、[实施 Tickets](days-matter-migration-tickets.md)。

## 1. 参考 App 设计语言拆解

参考 App 为 Kotlin + Jetpack Compose（Material 3 + Haze 磨砂），设计令牌唯一来源 `ui/Theme.kt`（注释明言「Every colour, type size, radius and motion curve in the app comes from this file. Screens read AppTheme.colors — never literal values.」，Theme.kt:25-28），组件库 `ui/DesignSystem.kt`（998 行），意图自述 `docs/design/2026-11-14-android-apple-refresh.md`。

### 理念一：一屏一个数字主角（数字即界面）

- **表现**：全 App 围绕「最近的那个日子」组织，72sp 等宽数字（`tnum`、字距 −3.2sp）占据视觉中心，次级数字各有专属档位（20/40sp）且全部等宽（Theme.kt:174-186）；数字变化用交叉淡化（入 220ms 淡入 + 上滑 1/4 高、出 120ms 淡出），注释写明「so digits do not shift while they animate」（DesignSystem.kt:916-934；design 文档:64）。
- **解决什么**：倒数日被高频「瞄一眼」，痛点是「我最在意的那天还有多久」必须 0 秒可得，且数字变化不闪不抖、扫视成本趋零。
- **层面**：理念层（层级与阅读节奏）。72sp 等取值属元素层不迁移。

### 理念二：单强调色纪律——彩色只出现在「动作」和「倒数」上

- **表现**：全 App 一个 accent，只给可点动作、选中与倒数数字；倒数徽标三态取色（未来 = accent / 已过 = 次要 / 待同步 = 更弱），色彩携带时间方向语义（Screens.kt:419-423）；辅助七色带只用于设置图标瓦片，从不进正文区（Theme.kt:100-107）；danger 只给破坏性操作与必填星号。设计文档自述「one accent colour, used for actions and 'days until' only」（design 文档:12）。
- **解决什么**：让「哪里能点、哪里在倒计时」一眼分辨，界面安静可预期；彩色预算花在功能上而非装饰上。
- **层面**：理念层（色彩分工纪律）。色值与色带属元素层。

### 理念三：分组内嵌列表 + 发丝线，而不是逐项卡片

- **表现**：同类信息收进一张分组卡（iOS 设置式 inset grouped），行间用对齐文本起始线的发丝线分隔（列表行分隔线内缩 64dp = 行内边距 + 分类块宽 + 间距，Screens.kt:287）；浅色卡无描边无阴影、深色才补发丝描边（「hairline only where needed」，DesignSystem.kt:107-133）；行最小高 56dp、卡间 10dp、组间 28dp（Theme.kt:193-199）。
- **解决什么**：条目多的列表若逐项卡片会「碎」，扫视噪音大；分组卡 + 对齐发丝线给出强秩序感与明确组边界，深色靠描边而非阴影保持分区。
- **层面**：理念层（列表结构与密度控制）。0.6dp、20dp gutter 等属元素层。

### 理念四：材质三分——墨色 Hero、平面内容卡、玻璃 Chrome

- **表现**：全 App 只有三种材质且互不混用：Hero 深墨色面板（两模式都保持墨黑，径向柔光晕染右上角，Screens.kt:306-316）；内容区无阴影平面卡，层级只靠 canvas 与卡面明度差（Theme.kt:73-75）；导航 Chrome 是真实磨砂玻璃（12dp 模糊 + 垂直高光渐变 + 四段式渐变描边，NavigationChrome.kt:150-190），顶栏静止完全透明、内容滚入才浮现（DesignSystem.kt:567-582）。页头材质用 canvas 色调而非卡面色，避免页面上方出现凸起横带（design 文档:70-73）。
- **解决什么**：材质混乱是「廉价感」主因；三种材质各司其职——Hero 制造仪式感、Chrome 暗示悬浮、内容保持安静可读。
- **层面**：理念层（材质分工哲学）。Hero 色值、玻璃各 alpha、12dp 模糊属元素层。

### 理念五：动效解释状态，从不装饰

- **表现**：动效只做两件事——表达层级与位置（页面转场按深度方向滑入，320ms FastOutSlowInEasing，MainActivity.kt:282-289）、表达状态变化（数字交叉淡化、大标题收缩、选中滑移）；三个时间尺度分工清楚：转场一档 320ms、状态反馈 140–240ms、按压用弹簧而非固定时长（Theme.kt:216-229）；「Only transform and alpha animate」（design 文档:74-77）；无障碍「减少动效」随系统零代码全生效。
- **解决什么**：用户转场后知道自己在第几层、数字变了能注意到但不被惊扰；动效敏感用户一键关闭。
- **层面**：理念层（动效性格与节奏）。ms 值与弹簧参数属元素层。

### 理念六：状态诚实——离线、失败、待同步都是「内容」，不是 toast

- **表现**：一切不理想的数据状态排版成显式内容层：离线条带具体到分钟的缓存时间（Widgets.kt:80-97）；同步失败卡内说明 + 可点「重试同步」、重试中变「正在重试…」（NavigationChrome.kt:273-282）；统计带常驻「待同步」计数并附原因说明（Screens.kt:241-253）；空态按原因分五档各一句话（Screens.kt:189-197）；全局忙碌 = 顶部 2dp 线性进度条（MainActivity.kt:383-389）、按钮级忙碌 = 内嵌圆环 + 降活。
- **解决什么**：网络类 App 的核心不信任感来自「我看到的数是新是旧？」；把缓存时间、待同步数直接排版出来，用户不必猜，且总有明确下一步。
- **层面**：理念层（反馈模式与信息诚实性）。横条造型与文案措辞属元素层。

**贯穿性习惯（触感与可达性）**：触控统一无涟漪、按压缩放分档（0.92–0.985）+ 4% 洗色（DesignSystem.kt:243-290）；触达尺寸有刻度（行 56 / 图标 44 / 主按钮 52）；图标按钮一律带语义标签、行内合并语义、选中态显式上报、字体缩放 ≥1.3 时头部行高增长防裁切（design 文档:130-140）。

## 2. 领域差异分析

| 维度 | Days Matter（倒数日） | 行笺 Mileaf（TeslaMate 数据看板） | 对迁移的含义 |
| --- | --- | --- | --- |
| 领域与对象 | 单一情感对象（一个日子），生命周期长 | 多对象多指标（车辆 × 期间 × 指标），图表/地图/关键数字为主体 | 「唯一主角」的版式不能照搬；迁移的是「主角唯一 + 数字不跳变」纪律，不是单卡结构 |
| 用户心智 | 扫视型：还有多久，0 秒可得 | 判读型：车况/花销是否正常，要可比对、可下钻 | 焦点值周围必须有参照与口径（R21/R29 已定），迁移重点是变更时不打断判读 |
| 主要任务 | 创建/查看/同步 | 只读展示（唯一业务写入 = 费用补录，ADR0007） | 反馈模式迁移空间大：状态诚实、失败可补救是高频痛点 |
| 内容密度 | 低：一屏一个主角 + 短列表 | 高：模块卡 + 读值网格 + 记录行 + 说明层 | 不能迁它的疏朗节奏；密度纪律沿 R21.5/R24 档位 |
| 使用场景 | 高频瞄一眼，无沉浸 | 中频查阅 + 详情沉浸（过程图/地图） | 转场编码深度的理念已在 R15/平台路由，无需改 |
| 数据新鲜度 | 同步状态敏感（离线/待同步显式排版） | 服务端快照新鲜度敏感（更新时间、口径） | **最大净增益点**：状态诚实三要素 + 失败补救动作 |
| 材质语境 | 玻璃只用于 Chrome；Hero 独立墨色制造仪式感 | 玻璃只用于 Chrome（ADR0013/R28）；Hero 已裁定落普通卡面（PD06） | 材质分工同构；Hero 第三材质判「不迁移」 |
| 设计成熟度 | 令牌单文件、纪律自述成文档 | 三代规格 + 守卫测试体系，纪律已成条款 | 大量理念已同构收敛；增量应做成「守卫化收尾」而非重写 |

**结论**：两 App 都是 Apple 校准的克制体系，理念层重合度高。迁移方式为**增量收尾 + 守卫固化**，共九条条款（§4），不做推翻式重构。

## 4. 改造方案条款（MG01–MG09）

冲突时优先级链更新为（插入位置加粗）：用户明确决定 > S01–S08 > **本规格确认增量（MG01–MG09）** > ADR0014 R21–R32 > ADR0013 L01–L12 > ADR0012 R11–R20 > ADR0011 R01–R10。

### 色彩体系

**MG01 彩色面积预算**
- 现状（前）：appearance v2 有「颜色只做信号」三规则，但无量化审计；彩色面积无登记。
- 改造（后）：每页（根页四 Tab、五专题、两详情、设置、连接）登记非图表彩色面积占比，目标 ≤20%；图表绘图区的主数据系列（accent/seriesSecondary/reference）不计入预算，但图例、轴文字、选中标记计入。审计产物为「彩色面积登记表」+ 每页浅/深两张渲染图册；超标页在所属页面包内整改（手段：把彩色从装饰位挪到功能位或降为中性），**不得靠压饱和度凑数**。
- 验收：登记表逐页 ≤20% 或列明豁免理由；图册入库 `docs/implementation/days-matter-migration-renders/`。

**MG02 状态取色映射表**
- 现状（前）：进行中胶囊（segmentTrack 中性）、刷新 120ms 交接、错误红行、口径旁注等散在各页，取色无统一登记；个别位置彩色语义依赖惯例。
- 改造（后）：全站唯一映射表——进行中/加载 = accent；警示（数据异常、Key 失效）= warning；失败/破坏 = error；**缺失/未知/未记录 = 中性（textSecondary/textFaint + 「—」或口径旁注），禁止任何彩色**；参照/基线 = reference；进行中胶囊维持中性底。StateView 与 InlineBanner 的色彩参数收为受限枚举（neutral/warning/error/accent 四值），页面不得直接传任意颜色。
- 验收：映射表入规格；StateView/InlineBanner 参数枚举守卫测试；新增白盒测试「缺失数据渲染输出不含 accent/warning/error 色」。

**MG03 对比度自动化守卫（裁决 textFaint 矛盾）**
- 现状（前）：overview-reading.md:78 与 overview-chart-header.md:79 对 textFaint 对比度结论互相矛盾（<4.5:1 vs 全组合 4.65–5.59 ≥4.5），无自动化校验，靠人工复测。
- 改造（后）：以 WCAG 公式复测口径为裁决（textFaint 现值 #63707C/#7E8A96 保留不变）；新增 tokens 级白盒守卫测试，遍历全部「语义前景 × 其声明背景」组合断言 ≥4.5:1（正文类）或 ≥3:1（图形与边框类，按各 token 声明用途），浅深两模式各跑一遍；未来调色板改动触碰下限即测试失败。
- 验收：守卫测试入库并常绿；overview-reading.md 的旧结论以追加批注方式订正（不改写原文）。

### 图标体系

**MG04 图标家族参数登记与统一出口**
- 现状（前）：R32 要求自绘图标，但图标散在页面自绘（如 hero 状态图形在 overview/charging 页内），线宽、端点、视觉盒无登记，家族一致性靠人工。
- 改造（后）：实测现有全部自绘图标，登记家族参数表（线宽、端点/拐角、网格 24、视觉盒、命中区），收进 `lib/src/design/components/icons.dart` 统一出口；新图标必须走出口并满足参数表；图标语义选择走 apple-polish-copy CP04 术语表。**不迁移参考 App 的图标瓦片造型与 83 图标库**；图标配色沿用现行语义色（accent 四类用途），不另起高饱和色。
- 验收：参数表 + 统一出口入库；逐图标 golden（浅/深）钉住家族一致；页面直绘图标清零（迁移到出口）。

### 布局与间距

**MG05 行程记录行句法统一**
- 现状（前）：行程记录行用 `MileafDataRow` meta 串句法（charging-rows.md:69 遗留 11），与充电记录行（标题行 + 三格 metricSm 读值网格）并存两套。
- 改造（后）：行程记录行改为与充电记录行同构的固定读值网格：标题行（日期/起讫时刻）+ 三格 metricSm（里程/时长/能耗），标签在上、数值同基线成列；共享组件沿用 `_cardRow` 卡内 16 两条起始线模式。文案变更走 copy guard 登记（行数只降不升基线随结构登记）。
- 验收：两页记录行同构；结构映射测试规则更新；360 宽与 200% 渲染无折行孤字。

**MG06 卡头→焦点值间距裁决（D1）**
- 现状（前）：焦点卡头（`MileafPeriodHeader`）→ 焦点值间距 `s4`，按 R21.6/R24 字面应为 `s12`，裁定悬置（period-header.md:60）。
- 改造（后）：`s12`（D1 已确认，登记为 PD12）；360×800 概览首屏预算由页面包实测：若超预算，按六步退让阶梯第 1–4 步在页面包内回收（候选：图下读值区与本期读数表间距 s12→s8），第五步起须视觉评审。
- 验收：spacing 实测截图（before/after 各一）；首屏预算结论入实施记录。

**MG05b 分组标题 inset 迁移（挂靠 MG05 执行）**：`MileafGroupHeader` 的 `inset` 参数（settings-order.md:49 遗留 9）逐页迁移到 overview、connection、currency 等页，全库「分组标题与卡内边距对齐」零例外。

### 材质

**MG07 材质三分登记表 + 内容层玻璃守卫**
- 现状（前）：三种材质事实上存在（底栏玻璃、顶栏磨砂、内容平面卡、浮层 surfaceRaised），但无登记表；「玻璃不进内容层」靠约定，无守卫。
- 改造（后）：登记表钉住四区（Chrome 玻璃 = 仅底栏，参数 L01–L12 全套冻结；顶栏磨砂 = 18σ/0.88–0.90 沿 R14；内容 = 平面卡无阴影浅色、深色靠 surfaceRaised 明度差 + line 描边；浮层 = surfaceRaised + 阴影，不用玻璃沿 R28）；新增 import 守卫测试：内容层组件文件（components/ 除 glass_surface/navigation_material/nav_bar/top_bar 外）禁止 import 玻璃材质。镜片受光带维持默认关（D2）；玻璃 painter 参数债（GlassPaint 值类型收敛，遗留 7）列为独立工程候选，不阻塞本增量。
- 验收：登记表入规格；守卫测试常绿；AP02 镜片用例不变。

### 动效

**MG08 数值变更统一交叉淡化（M08 扩展）**
- 现状（前）：120ms 交叉淡化只覆盖「换指标」（M08）与概览图表读值（overview-reading），期间切换、数据刷新完成后的焦点值变更无统一处理。
- 改造（后）：M08 语义扩展为「任何焦点值内容变更统一 120ms 交叉淡化，减动效归零」：覆盖期间切换、数据刷新完成、图表读值切换；**拖动取点维持原地即时更新不淡入**（延续 overview-reading 现状）；时长集合维持 {120,150,160,180,200,220,280} 七档、曲线维持 easeOut/easeOutCubic 两族（D3）；按压弹簧不迁移（PD11 冻结）；R07 白名单相应登记扩展项（数据刷新淡入）。
- 验收：焦点值变更动画时长 ∈ {0,120} 的守卫测试；减动效下 0ms 回归；M08 条款修订在 apple-polish 登记为 PD13。

### 状态反馈

**MG09 状态诚实三要素**
- 现状（前）：StateView 整页态有主按钮但 compact 态无动作槽；InlineBanner 无统一「现状 + 时间 + 动作」结构；刷新失败/离线场景的表达各页不一。
- 改造（后）：StateView 与 InlineBanner 增加「三要素」结构支持：现状句（title/正文）、时间或原因行（数据截至 HH:mm、失败原因、待同步计数）、下一步动作槽（compact 态新增文字动作槽，整页态沿用主按钮）；空态按原因分档（离线 / 加载失败 / 无数据 / 筛选无结果）各一句话，措辞走 CP 系列；页面级接线范围：四根页 + 两详情 + 连接页。
- 验收：三要素组件测试；「显示至 HH:mm 的缓存数据」场景在连接页与根页各有渲染用例；文案守卫基线登记。

## 8. 决策点（2026-11-19 用户确认：全部按推荐执行，见 ADR0015 确认记录）

- **D1（推荐采纳）**：卡头→焦点值 `s4`→`s12`。理由：消除与 R21.6/R24 的字面冲突；预算风险有六步退让阶梯兜底。不采纳的代价：R24 需登记豁免，秩序感规则出现首例例外。
- **D2（推荐维持默认关）**：镜片受光带是参考 App 高光渐变性格的近亲，属元素层性格；AP02 用例已钉住现状，开启无验收收益。
- **D3（推荐维持现行集合）**：{120…280} 七档同类一致、状态档 ≤200ms、白名单冻结；改档将触发全库 M 系列修订，收益不明确。
- **D4（推荐不迁移 Hero 墨色材质）**：与 PD06「hero 落普通卡面」直接冲突；数据看板的仪式感由「唯一 display + 电池弧」承担，墨色面板在浅色模式会引入大面积深色，违反中性底规则。
