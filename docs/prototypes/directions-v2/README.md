# 行笺方向评审 v2 · 设计室

2026-11-01。一次性 UI 原型，用来回答一个问题：**同一组车主数据，下一版用哪种视觉语言承载，才既有消费级质感，又不回到 Grafana？**

三套方向不是换色稿：A「夜航」用深色车况主屏建立锚点；B「仪表」用等宽数字、刻度和面板建立精度；C「夜读」用衬线、纸感和账簿建立品牌。所有数据为固定合成样例，不连接真实站点、数据库或 Tesla API；不修改 Flutter 页面、Spec、工单或外部只读仓库。

> 方向评审文档：[产品方向评审](../../product/direction-review-v2.md)。本文只说明如何打开和检查原型。

## 打开

在项目根目录运行已有 Node，无需安装依赖：

```sh
node docs/prototypes/directions-v2/serve.mjs
```

- 交互评审：<http://127.0.0.1:8771/>
- 默认方向 A、深色、概览。
- 换方向 / 页面 / 主题：左侧栏，或 URL 参数。
- 单屏截图入口：`?variant=A&page=overview&theme=dark&capture=1`
- 并排图：`renders/compare-dark.png`
- 图册：`renders/index.html`

服务只监听 `127.0.0.1`；`MILEAF_DIRECTION_PORT` 可改端口。页面没有外部字体、图片、地图瓦片或网络请求；CSP 禁止连接其他数据源。

## 参数

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `variant` | `A` / `B` / `C` | 方向 |
| `page` | `overview` / `statistics` / `drives` / `drive` / `charging` | 页面 |
| `theme` | `dark` / `light` | 主题；深色为主基线，浅色对照 |
| `capture` | `1` | 只留 360×800 手机，用于截图 |

## 固定样例

时钟固定在 **2026-10-26 18:40 Asia/Shanghai**，车辆「白露 · Model 3」。

- 车况：68% 电量、320 km 额定续航、充电中 11.0 kW；今日 60.0 km、3 次行程、11.25 kWh。
- 本月：1,198.6 km、46 趟、净电耗 158 Wh/km、充入 234.7 kWh、9 次充电、已知费用 ¥186.4（8/9 次有记录）、22 个活跃日。
- 参照：上月同期 1,107.3 km、166 Wh/km；差异 +91.3 km、−8 Wh/km。
- 最近行程：32.9 km / 46 分钟 / 154 Wh/km，松岚小区 → 云栖中心。
- 最近充电：46.8 kWh / 18→82% / 34 分钟 / ¥71.28，湖畔超级充电站。
- 地图与路线均为自绘合成示意，不是供应商底图；正式 App 仍以真实地图/坐标验收为准。

## 评审时看什么

1. **5 秒**：第一眼落在哪里；能否立刻说出车现在怎样。
2. **30 秒**：本月开了多少、和之前比怎样、钱花在哪；是否被口径说明打断。
3. **5 分钟**：能否从主图走到最近记录、再走到详情；未知/缺失是否只变成“—”，而不是补零。
4. **结构差异**：A 的竖向叙事、B 的仪表读数、C 的编辑流，是否真的改变了阅读顺序。
5. **明暗**：深色是否仍有层级；浅色是否只是反色，还是重新设计过纸面。
6. **放大**：数字是否对齐、单位是否分级、细线是否稳定、卡片圆角是否统一。
