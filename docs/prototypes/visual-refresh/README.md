# 行笺视觉重构 · 设计室

2026-10-30。一次性 UI 原型，用来回答一个问题：**同一组车主数据，怎样排才有重心、有节奏、也仍然可信？**

> 2026-10-30 决策更新：用户已选择 **C「数据拼贴」**。本文中的 A 推荐保留为评审历史；当前决定见 [ADR 0001](../../adr/0001-visual-direction-c.md)。

三套结构不是换色：A 用深色车况主屏建立锚点；B 用纸面与衬线把一个月写成小志；C 用大小色块制造拼贴节奏。所有数据为固定合成样例，不连接真实站点、数据库或 Tesla API；不修改 Flutter 页面、Spec、工单或外部只读仓库。

## 打开

在项目根目录运行已有 Node，无需安装依赖：

```sh
node docs/prototypes/visual-refresh/serve.mjs
```

- 交互评审：<http://127.0.0.1:8770/>
- 三套方向并排：<http://127.0.0.1:8770/?compare=1>
- 推荐 A 完整首屏：<http://127.0.0.1:8770/?variant=A&page=overview>
- 推荐 A 详情：<http://127.0.0.1:8770/?variant=A&page=driveDetail>
- 360×800 截图入口：在任意 URL 后加 `capture=1`
- 完整长页：在任意 URL 后加 `full=1`

服务只监听 `127.0.0.1`，`MILEAF_VISUAL_PORT` 可改端口。页面没有外部字体、图片、地图瓦片或网络请求；CSP 禁止连接其他数据源。`renders/` 内是实际 Chrome 截图和并排图，可直接作为评审图册。

## 三套方向

| 方向 | 一句话 | 第一视觉锚点 | 主要风险 |
| --- | --- | --- | --- |
| **A 仪表舱 · 推荐** | 先看车，再看这个月 | 深色车况主屏 + 320 km + 本月 1,198.6 km | 深色块过多会重新变重 |
| **B 行笺志** | 把一个月写成一本小志 | 衬线大标题 + 一张纸面图版 | 信息密度较低，字体/实现更定制 |
| **C 数据拼贴** | 用大小和颜色制造节奏 | 最大的里程 tile + 车况 tile | 容易变成“更多卡片”，需控制主角 |

产品判断、页面蓝图、数据取舍与实施顺序见[视觉重构方案](../../product/visual-refresh-proposal.md)。

## 可操作

- `← / →` 或底部胶囊左右按钮切换 A/B/C。
- 手机内底部四个 Tab：概览、行程、充电、统计。
- 概览点四个指标 chip（里程/净电耗/补能/费用）切换主图；点图上任意柱子读值；`‹ ›` 前后读数。
- 「最近行程」「最近充电」进入详情；详情内可切速度/电量/海拔或功率/电量。
- 统计点「节奏/能耗/补能/长期」进入专题页。
- 点「数据说明」「比较依据」「全部记录」打开底部说明层；`Esc` 或右上关闭。
- 侧栏可切浅/深色、100%/200% 字号、A 概览的正常/部分缺失/空数据。
- 并排模式 `?compare=1` 同屏看三套方向；`capture=1` 隐藏评审框架，只留 360×800 手机。

## 固定样例

时钟固定在 **2026-10-26 18:40 Asia/Shanghai**。主要数字：

- 车况：68% 电量、320 km 额定续航、充电中 11.0 kW；今日 60.0 km、3 次行程、11.25 kWh。
- 本月：1,198.6 km、46 趟、净电耗 158 Wh/km、估算驾驶能量 189.3 kWh、充入 234.7 kWh、9 次充电、已知费用 ¥186.4（8/9 次有记录）。
- 参照：上月同期 1,107.3 km、166 Wh/km；差异 +91.3 km、−8 Wh/km。
- 补能结构：AC 118.0 / DC 96.0 / 未知 20.7 kWh；DC 占已知分类 44.9%；有效入电均价约 ¥0.87/kWh。
- 记录：最近行程 32.9 km / 46 分钟 / 145 Wh/km；最近充电 46.8 kWh / 18→82% / 34 分钟 / ¥71.28。
- 详情过程：速度/电量/海拔、充电功率/电量均为服务端采样示意；地图为自行绘制的合成路线，不是供应商底图。
- 正式 App 的总计和比率必须直接取服务端结果；不从列表分页加总、不平均桶比率。原型内聚合只为固定样例自洽。

## 评审时看什么

1. **5 秒**：能否说出车现在怎样，视线第一落点在哪里。
2. **30 秒**：能否说出本月开了多少、和之前比怎样、钱花在哪；是否被时间戳、时区和口径说明打断。
3. **5 分钟**：能否从主图走到最近记录、再走到详情，并区分“估算、已知费用、覆盖不足、样本不足”。
4. **结构差异**：A 的竖向叙事、B 的编辑流、C 的拼贴网格，是否真的改变了阅读顺序，而不是只换了颜色。
5. **状态**：A 概览空数据时是否仍能看懂页面职责；部分缺失时是否只把不确定项变成“—”。

## 验证

- 21 个组合（A/B/C × 概览/行程/充电/统计/两类详情/专题）实际 Chrome 渲染：均只有 1 台手机、正文非空、`.screen` 无横向溢出、控制台无异常。
- 并排模式 3 台手机；A/B/C 底部 Tab、指标切换、周期切换、图上点读、详情往返、专题入口均通过脚本点击验证。
- 说明层打开/关闭通过；`Esc` 关闭通过。
- A 概览 200% 与 C 概览 200% 重新检查：C 的 tile 在 200% 时改为单列，A 的主数与单位仍可读。
- 浅/深色、A 空数据截图见 `renders/`；`renders/A-sheet.png` 为说明层截图。
- 这些是浏览器级设计验证，不是正式 Flutter 渲染、真机、真实站点、地图许可/坐标或性能验收。
